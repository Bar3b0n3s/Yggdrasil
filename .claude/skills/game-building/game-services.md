# Game services: an options menu and saving

A reference page of the `game-building` skill (`skills/game-building`). The script side (the `Application` display calls, `SaveData`, the audio mix) is `skills/luau-gameplay/game-services`; this page is what an agent building the game does with the editor.

**An options menu.** Build it as UI (`skills/game-building/ui`) driven by a behaviour that lists `Application.GetDisplayModes()` and calls `Application.SetDisplaySettings`. The display calls do nothing in the editor, in test runs, replays, recordings and lockstep sessions: the list is empty and the request returns `false` and the reason, so the menu still opens there, and its effect is checked in an export (`skills/game-building/exports`), where the Runtime keeps the choice in `user://Display.json` and restores it at the next start. A test checks the menu's logic, not the switch. Volumes go through `Audio.SetGroupVolume`, which holds across scene loads; save them to keep them across runs.

**Saving.** Editor play has a store of its own, the project's `Library/SaveData/Store.json` (a read-only editor's is private, in memory): a live `play_start` session starts with it and `SaveData.Commit` writes it. `savedata_get` reads it (`{target: "Play"}` reads the running session's store instead), `savedata_set {values, merge?}` seeds it and `savedata_clear` empties it, as a first run finds it; the Save Data panel (Window menu) shows and edits the same store. Lockstep sessions (`play_start {lockstep: true}`), test runs and replays never touch it: they keep their store in memory.

- **A branch that saved progress opens:** in a suite, seed the store with `Test.SetSaveData({...})` and `Scene.Reload()` so the scene's scripts read it at their creation; each case of an `Isolation: "Case"` suite starts empty again.
- **A replay of a game that reads its store:** `savedata_set` the store the run should start with, then `input_record`; the replay's header records that store exactly (its numbers as doubles), so the replay verifies at its hash whatever the machine's store holds when it plays. `savedata_clear` afterwards if the next play should start without it.
- **A corrupt store:** a store file that cannot be read is moved aside as `Store.corrupt-<n>.json`; `savedata_get` reports why in `loadError`, and the next session starts empty with `SaveData.GetLoadError()` saying so.
