# Navigation

A reference page of the `game-building` skill (`skills/game-building`), for its steps "3. Scenes, assets and prefabs" and "4. Scripts": the navigation mesh enemies path on, how a scene declares it, how `navigation_bake` builds it, and what a builder checks.

- **Declare it.** One `Navigation` component per scene (`component_schema {name: "Navigation"}`), on any entity: up to four `AgentTypes`, each `{Name, Radius, Height, MaxSlope, MaxStep}` (a small one for most enemies, about 0.4 m radius; a large one, about 1 m, for a brute that needs wider lanes), the physics `Layers` whose static colliders count as ground and walls (empty: every layer), and the voxels `CellSize` (smaller follows walls more closely and bakes more slowly) and `CellHeight` (the precision of steps and slopes); walkable islands under `MinRegionArea` square metres are left out. Neither it nor `NavModifier` is visible to scripts: they are the bake's input, and scripts read the baked mesh.
- **What the bake reads.** The static, solid colliders of the scene, exactly the bodies a play session creates as Static: implicit static colliders and Static RigidBodies, never Kinematic or Dynamic ones (a moving platform or a crate is no ground; enemies go around them locally), never triggers or characters. A box, sphere, capsule, mesh collider (its mesh's triangles, even when Convex) and terrain collider all count. Mark a lava channel or a trap with a `NavModifier` box (`Kind: "NotWalkable"`: a hole agents keep their radius from), or a hazard with `Kind: "Cost"` and a `Cost` (a path inside costs that many times its length, so it is taken only when no cheaper way exists). The box is centred on its entity, scaled by its scale, turned by its yaw only (its sides stay vertical), and must reach down to the floor it marks (its `HalfExtents.y` around the floor's height).
- **Bake it** with `navigation_bake {}` (the editor's Tools > Bake navigation runs the same method) after saving the scene: it needs no GPU, so a `--renderer none` editor bakes too. It writes `Assets/Navigation/<the scene's path below Assets/ without .scene>.navmesh`, imports it and sets the `Navigation` component's `NavMesh` in one undo step, then save the scene again. The result lists each agent type's polygons (0 means the agent type walks nowhere: check its `MaxSlope`, `MaxStep`, `Height` and the layers) and any static body whose shape could not be described (`skippedBodies`, `PHYSICS_INVALID_SHAPE`). A rebake of an unchanged scene writes nothing and records no undo step, so bake as often as you like; two bakes are byte-identical.
- **See it.** `viewport_set_options {navMesh: true}` draws the baked mesh's polygon edges in the scene view (one colour per agent type; borders bright, edges between polygons dim), and `viewport_screenshot {annotate: {navMesh: true}}` draws them into a capture of the edit or play scene, so you can check that each agent type walks where you meant.
- **Use it from scripts** with the `Navigation` module (`skills/luau-gameplay/navigation`): `FindPath`, `ClosestPoint`, `Raycast` and `RandomPoint`, deterministic in the fixed step.
- **Bake again after every edit of the level.** `project_validate` warns `NAV_MESH_NOT_BAKED` (a Navigation without a mesh: every query finds nothing) and `NAV_MESH_STALE` (a static collider, a modifier or a setting changed since the bake, naming the scene; `skills/game-debugging/validation-codes`). Bake before recording replays: a replay whose agents path on an old mesh changes when the mesh does.
- **Limits.** One mesh per agent type covers the whole scene, at most 4,096 cells along X and Z (819 m at the default 0.2 m cells) and 8,191 from its lowest static collider to its highest (819 m at the default 0.1 m `CellHeight`): raise `CellSize` or `CellHeight` for a larger level. There are no run-time rebakes, crowds, local avoidance or jump links: scripts steer agents and keep them apart. A convex mesh collider over a non-convex mesh is baked as its mesh's surface, so a hollow the physics hull fills stays open on the mesh.
