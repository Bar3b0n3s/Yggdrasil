# Game debugging

Use this skill when a game built through automation does something unexpected: a script error, a test that fails, a ball that falls through the track, a sound that is silent, a replay that no longer verifies. `docs.get {topic: "reference/Automation"}` has every method's params and results, and `reference/Validation` every validation code (the topics `game-building` lists under "Documentation"; Architecture §13.7 of the repository describes the observability design). Methods are written `domain.verb` as `engine_client` calls them; the MCP bridge proxies the tool-flagged ones as `domain_verb` (`log.read` is the tool `log_read`) and reaches every other method through `engine_call {method, params}`. Work in a loop: **observe, form one hypothesis, check it with the narrowest query, fix through automation, re-run the deterministic check.** Never edit project files by hand to try something (see `game-building`).

## The observability loop

1. **Read what the engine already told you.** Every response carries `_meta.diagnostics` (`newErrors`, `newWarnings`, `newScriptErrors`, `firstNew`) and `_meta.playState`. Start there. `_meta.revision` counts changes to the addressed open scene (the active one, or the request's `scene` target) and the project settings only: creating or writing assets and scripts leaves it unchanged, so `ifRevision` guards the scene and the settings, not asset files. A revision names one state of one scene, so a revision read in one open scene never matches another.
2. **Logs and events, by cursor.** `log.read {cursor, minLevel: "Warn", contains?, limit?}` returns structured entries with source locations and entity context, oldest first, at most `limit` per call, and `nextCursor`. Page by passing exactly the returned `nextCursor` as the next `cursor` until a read returns no entries; never compute or guess a cursor (from `seq` numbers or entry counts), which skips entries without an error. `cursor: ""` starts at the oldest entry held, `cursor: "end"` returns only the cursor of the next entry (to watch from now on), and `dropped` counts entries overwritten before the read could see them. `events.read {cursor, types?: ["ScriptErrorRaised", "AssetImportFailed", "PlayStateChanged", "AssetReloaded", "SceneChangedOnDisk", "SceneOpened", "SceneActivated", "SceneClosed", "DiagnosticsChanged", "GpuDeviceLost"]}` pages the same way and tells what happened in order.
3. **Script errors.** `script.errors {since}` lists deduplicated errors with kind, script, line, column, callback, entity, slot (the faulting behaviour's place in its entity's Script list), tick, count and traceback; `nextCursor` continues, `evicted` says older ones were dropped. A failing instance is disabled, and only it: an entity's other script slots keep running; with `Scripting.PauseOnError` the editor also pauses ordinary play at the first error. A `script.eval` that raises is answered with `ScriptError` (-32006, the located error in error data `scriptError`) and also enters this list with callback `Evaluate`: read `script.errors` before evaluating, or tell those entries from the game's by their callback.
4. **Ask the running game.** `script.eval {context: "Play", entity: "/Game", code: "return self.Board:ToAscii()"}` evaluates in the play VM with `self` bound to the instance of the entity's first script slot (`script: "<Name>"` binds it to the slot whose behaviour has that `Script.Define` name; NotFound at `/script` when none has) and returns the value plus captured prints. The value must be JSON (nil, booleans, numbers, strings and tables of them): a vector or `Quat` fails with an error naming its type and place, so unpack it (`return {v.x, v.y, v.z}`). `context: "Edit"` is read-only. During a recording, evaluate only reads: a write through an engine API (a component, an entity, `SetActive`, a session `Random` draw) invalidates the recording, and a write to a Luau table (`self.Score = 0`, `self.Board:FillRows(...)`) is neither detected nor recorded, so once that write shows in a checkpoint, the final hash or an expectation the recording no longer reproduces itself and `input.record`'s `stop` refuses it, event-free or not.
5. **Where things are.** `scene.tree {format: "Text", root?, depth?}` gives the compact outline (ids, components, positions); `scene.query {where: {name?, tag?, component?, path?}}` finds entities; `entity.get {entity, components: "all"}` shows values; `entity.bounds {entities}` gives world AABBs, the quickest check for gaps and overlaps.
6. **What changed.** `scene.diff {against: "Saved"}` lists RFC 6902 changes per entity since the last save (or `against: "Revision", revision`); `edit.history` lists the undo steps. Each open scene has its own command history: `scene.open` and `scene.new` without `keepOpen` replace the active scene and clear its history (earlier undo steps are gone), but undo indices keep increasing for the editor's lifetime, so an index never names a later command; an `undoIndex` of 0 means the call recorded no command (a `project.validate` that fixed nothing, a dry run, a batch op).
7. **Look.** `viewport.screenshot {view: "Game" | "Scene", width, height, target?, annotate: {labels: "all", colliders: true, bounds: true, axes: true}}` draws names, short ids, colliders and bounds over the frame so you can tie pixels to entities. For the game view pass the project window's size (`width: 720, height: 900` for a 720 × 900 game): the default is 640 × 360 whatever the window, which misframes a portrait game and scales screen text by the wrong height; `target: "Play"` renders the play scene, where runtime entities such as a pool exist; `debugView` shows a data view instead of the lit image: `Albedo`, `Normals`, `Roughness`, `Metallic`, `Emissive`, `AO`, `ShadowCascades` or `Overdraw` (`Lit` is the default). `ShadowCascades` colours each surface by its cascade: 1 red, 2 green, 3 blue, 4 yellow, blended across the blend bands; black is no surface, no shadow-casting `DirectionalLight`, or beyond the shadow distance (`ShadowDistance` or the camera's far clip), into which the last cascade fades. Needs an editor with `renderer: "vulkan"`.
8. **Physics.** `physics.bodyInfo {entity}` reports the body (type, layer, sensor, colliders, velocities, sleeping, bounds, contacts since which tick, grounded and ground normal) of the play session. A missing body means a physics validation error kept it from being created.
9. **Timing and load.** `stats.get` reports frame and per-pass timings, dropped simulation time, entity, body and voice counts, the Luau heap and its limits, and the GPU device losses the editor recovered from (`deviceLosses`). Its `views` are the editor's displayed viewport panels, and only displayed panels render: a headless editor displays the Scene view only, so `game` is unavailable there, and `play.step {render}` renders the play scene through the Scene view. `play.state` reports mode, tick, `stateHash`, lockstep owner, whether the session was modified, recording, and `stopped`/`stopError` after a fatal stop.
10. **Audio.** `audio.stats` lists the device, group volumes and every voice (clip, entity, volume, pitch, spatial position, cursor). No voice means nothing played; a voice at volume 0 points at the mixer or attenuation.
11. **Reproduce deterministically.** `play.start {lockstep: true, seed}` and `play.step {ticks, input}` reproduce a bug tick by tick; equal seeds and inputs must give equal `stateHash` values. A test that fails only sometimes is a determinism bug (unordered iteration, wall time, unseeded randomness, `^` with a non-trivial exponent: see `luau-gameplay`).

### Common situations

- **A replay no longer verifies.** `input.replay {path, verify: true, strictHash: true}` reports each `Expect` outcome, `finalTick`, `stateHash`, `stopReason`, `checkpointsChecked` and `checkpointFailed`; a failed verification (also the expected failure of `withoutInput: true`) is error -32003 `Validation`, whose data `replay` holds that outcome with `passed: false` and, at a differing checkpoint, `checkpointFailed: true`, `finalTick` at that checkpoint and `checkpointsChecked` counting it. The usual failure is "replay verification failed at checkpoint tick N: expected state hash X, observed Y" (`checkpointFailed: true`, playback stopped at N): checkpoint N is the first whose state hash differed and every earlier one matched, so the divergence lies in the 60 ticks before N; bisect only there (a final-hash mismatch with every checkpoint matched lies after the last checkpoint). In `test.run` the replay's `Checkpoint@<tick>` or `FinalStateHash` row fails with both hashes. Either failure carries a hint: the world differs from the recording, because a serialized component of the scene (the look's included: `PostProcess`, `Environment`, lights, `Camera`, `Text`), a script, the game's native module, an asset or the engine changed since it was recorded, or the play is not deterministic. A replay recorded with a start fingerprint (format 3) also names what changed: `changes` lists each entity, component and directly referenced asset (a script, a material) that differs from the recording, the first ending the message; a replay upgraded from format 2 names nothing until it is recorded again, and a change of the native module's code (`Native/`) is never named. `continuePastCheckpoint: true` (with `strictHash`) plays on past a differing checkpoint and reports `checkpointsFailed` and `firstFailedCheckpointTick`; without it both stay 0, and the failed checkpoint is `finalTick`, where playback stopped. An edit of the scene's look changes every checkpoint, so its replays fail at their first. The session then stays paused at the replay's last tick (or where playback stopped): read its state with `script.eval {context: "Play"}`, `scene.query` or `entity.get`, and end it with `play.stop`. A hash mismatch after an intended change (an engine fix, gameplay, the look) means re-recording with `test.run {record}` (`game-building`, "Re-recording replays"); otherwise compare `play.step` hashes tick by tick against a fresh recording within that window to find the first divergent tick.
- **A recording is refused: "does not depend on its input".** `input.record {action: "Stop"}` or `test.run {record}` fails with `Validation` when the recording, replayed without its input events, still passes its verification (every checkpoint, the final hash and every expectation, whatever script errors that run raised); `input.record` puts that run's outcome in error data `inputCheck`, and nothing is written. That happens only when the input never shows in the world at a checkpoint (one every 60 ticks), at the end or in an expectation: a recording shorter than 60 ticks that ends idle, input that changes only script state, or play after the last checkpoint that a restart undoes (a longer recording that ends with a restart is accepted, its checkpoints having seen the play, but its final hash then proves only the restored state). End the recording while the played state is still in the scene, record again, and confirm with `input.replay {path, verify: true, strictHash: true, withoutInput: true}` that the new replay fails without its input. An accepted `test.run {record}` reports its replay in the `recording` block, whose `inputCheck.divergedAtTick` is where the run without input first differed (`input.record`'s `inputCheckTick`). A recording written with a `warnings` entry ("its final state hash does not depend on its input") passed the check only at its checkpoints: its run without input reached the recorded final hash, so end it while the played state is still in the scene.
- **A recording is refused: "while taking the recording's start fingerprint".** A recording fingerprints every asset its scene references (format 3), so `input.record {action: "start"}` fails with the asset's own error, or `test.run {record}` with `Validation` ("recording invalidated: ..."), naming the asset, when one cannot be hashed: its source no longer imports. Nothing is recorded or written. Fix the source (`asset.info` shows its diagnostics; while the editor knows the asset errors, play itself is refused with `InvalidState`), or remove the reference, then record again. A playback is never refused for this: a replay whose hash differs names the error as its change ("not known, because the playback's start fingerprint could not be taken").
- **A recording is refused: "does not reproduce itself".** Before its input check, `input.record {action: "Stop"}` replays a recording with input events with its input (`verify`, `strictHash`, its `expect`) and refuses with `Validation` at `/path` naming the first failure in tick order: a checkpoint (`the state hash at checkpoint tick <t> is <observed>, recorded <expected>`), an expectation (`expectation <i> at tick <t> (/expect/<i>/luau) is false`, or `failed: <message>`), the final hash, where playback stopped, or the playback's first script error. Error data `verification` holds the playback's outcome; nothing is written, the recording has ended and the session is the verification's, paused where it stopped. The usual causes: a `script.eval` or `play.waitFor` that wrote script state during the recording, an expectation that does not hold with the recording's own input (check it first with `script.eval {context: "Play"}` at its tick), and a script that reads the host or iterates entity keys with `pairs` (`luau-gameplay`). Record again without them.
- **`test.run` refuses: "is open with unsaved changes".** A selected suite is bound to an open scene with unsaved changes, active or not, or a selected replay plays it, and runs play saved scene files: `scene.save` it (`scene.save {scene: <its path>}` for another tab), then run again.
- **A request changed the wrong scene.** Without `scene`, a request addresses the active scene. `scene.list` shows which open scene is active and each one's `id`; name the scene (`scene: "<project path>"` or its `id`) or `scene.activate` it first, and `edit.undo {scene}` takes the change back in the scene that recorded it. A target naming no open scene is NotFound at `/scene`, its hint listing the open scenes; an `id` names nothing once its scene was closed or replaced. During play, a target naming another open scene than the played one addresses that edit scene, and `target: "play"` with it is InvalidArgument at `/scene`.
- **One of an entity's scripts misbehaves.** `GetScript()` returns the first slot's instance only: ask for a behaviour by its `Script.Define` name, `GetScript("<Name>")`, or list them with `GetScripts()`. Callbacks run in (`ExecutionOrder`, canonical entity order, slot) order, so a slot that must run before another needs the lower `ExecutionOrder`. A `script.errors` row's `slot` names the faulting slot; the entity's other slots keep running. A native fault (`script` `native:<System>`, `callback` `NativeStep`) has no behaviour: its `slot` 0 names none. `entity.get {entity, components: ["Script"]}` shows the `Scripts` list.
- **A `test.run {record}` is refused because a row did not pass.** The message lists the selected rows that did not pass, `<suite>/<case> (<status>)`. A `replay:<path>/...` row is a committed replay the filter also selected: give the recording suite a name that no replay path contains (`Record.<Name>`) and record with exactly that filter.
- **A soak fails a scene.** The milestone gate plays every scene of a game in `Projects/<Game>` for 10,000 lockstep ticks without input and fails it on growing entity, body, voice or allocation counts, a growing memory or script heap, or a new script error (`OnStart` included). Reproduce it: `play.start {lockstep: true}` without a seed, `play.step` to tick 10,000, `script.errors` (before any `script.eval`, item 3), and `stats.get` past ticks 5,000 and 9,500; a per-lock `Scene.Instantiate`, pooled entities with bodies, a looping or late game-over sound and unbounded histories are the usual causes.
- **A test case fails.** `test.run {filter: "<suite>/<case>"}` reruns one case; its row has the failure messages with file and line, and `Test.ExpectScriptError` claims expected errors. A failed `Test.ExpectEqual` or `Test.ExpectNear` shows its message followed by `(got <actual>, expected <expected>)` (and `, epsilon <e>`), so pass the actual value first. Add `print` calls or `Test.GetStateHash()` checkpoints, then remove them.
- **A result too large to answer inline.** A response over 48 KB is `{path, truncated: true, summary}`: read the file with the bridge's `result_read {path, pointer?, offset?, length?}` (one page with `nextOffset`, or the JSON value at a pointer such as `/cases/0`; `engine_client.load_offloaded` outside the bridge), never with another file tool; it also reads a test run's `jsonPath` and `junitPath` reports. A `test.run` result names its failing rows in `failedCases` and counts every status in `counts`, inline. A `docs.get` topic too long for one response comes back as its first page with `nextOffset` and its sections; ask for a `section` or page on with `offset`.
- **A ball falls through or bumps.** `entity.bounds` on the neighbouring pieces shows gaps; `project.validate` reports `PHYSICS_ADJACENT_STATIC_BODIES` and layer problems; `physics.bodyInfo` shows the layer and contacts; check `Physics.Collisions` pairs the layers.
- **A collision callback does not arrive.** A collider merged into an ancestor's compound body gets its own `OnCollisionEnter` (and its own `OnTriggerEnter` when its body passes through a sensor) only when its entity has a Script naming a script; the other side's callback names the body's owner (`contact.OtherCollider` is the collider). Pieces of one body whose contacts share a normal (coplanar pieces, the seam between two edge-to-edge bricks) report the event to one piece only, an accepted limit of Jolt's manifold reduction: a piece that must get its own event at a seam keeps its own `Static` body. An enter needs touching shapes, or the step the solver bounces one off the other: a pass within Jolt's 2 cm speculative distance reports nothing. A callback that reads an entity another callback destroyed this tick works, but a write to it raises `entity <id> was destroyed`.
- **A script or asset change does nothing.** Lockstep, recording, replay and test sessions defer script and asset reloads (materials, sound effects, textures) until the session ends, so an `asset.setProperties` shows only after `play.stop` and a new `play.start`, while `asset.getProperties` (the tool `asset_get_properties`) reads a material's or sound effect's values from its file at once; ordinary play reloads scripts at the next safe point and assets at the next frame. To try component values in a running session, `entity.update {target: "Play"}` changes the play scene alone. A reload refused for type errors (with `BlockPlayOnTypeErrors`) or compile errors keeps the old code and reports a `type` or `compile` error with callback `Reload`.
- **An export is refused.** `project.export` refuses script type errors, asset errors (also of content `Export.Exclude` leaves out, `Assets/Tests/**` included), missing build scenes, an `Export.Version` that is not `major.minor.patch` (each part at most 65535), an `Export.Icon` that is not a square PNG of at least 256 × 256, and an existing output directory that holds anything but an earlier export. Fix what the error names (`script.check`, `asset.info`, `project.validate`), or export into another directory.
- **`project.upgrade` refuses.** A material, sound effect, replay or sprite sheet with a member its reader does not know fails the upgrade at its file and pointer instead of losing the member; any open scene with unsaved changes is refused, the error naming every one (save them first), while no open scene is needed.
- **The editor died.** The bridge reports `EditorCrashed {exitCode, lastLogLines, crashReportPath, autosaveAvailable}`; read the crash report, then `editor_launch {recover: true}` if an autosave exists: it reopens every autosaved scene as an unsaved open scene.

## Native module

A game's C++ module (Windows only) is the `.cpp` and `.h` files below `Native/`, built and loaded only while the user's "Allow native code" preference is on: the user sets it in the editor's Native panel, and no method can. The preference is the user's, stored in `user://Editor.json`, so every editor that user starts has it, not only the one whose panel set it. The one engine header its sources include, `NativeApi.h`, is the `docs.get` topic `native/NativeApi.h`; a source includes the module's own headers by their project-relative path, `#include "Native/<File>.h"`, never `"<File>.h"`.
- **Why it does not run.** `native.status` says: `allowed` false (ask the user), `supported` false (not Windows), `sources` empty (write one with `native.write`), `latestBuildCurrent` false (a source or the engine's `NativeApi.h` changed since the newest build: `native.build`), `lastBuildSucceeded` false (read `lastBuildDiagnostics`), `loaded` or `loadedCurrent` false (`native.load`). While a Play session runs the module, `playResources` holds each resource's value.
- **Build diagnostics** (`native.build`'s `diagnostics`, located by `file`, `line` and `column`; a failed build resolves with `succeeded: false`, and `log` names its whole output): `NATIVE_LINT_ERROR` (a banned or nondeterministic API, an include other than the engine's `NativeApi.h`, the module's own headers (`"Native/<File>.h"`), glm and the standard library, a file below `Native/` that is not a `.cpp` or `.h` (the editor's own `.bak` backups aside), a mutable static or `thread_local`, `throw`), `NATIVE_FORMAT_WARNING` (a warning, so the build still succeeds: a source that is not clang-format clean, at its first differing line, whose message quotes that line as clang-format writes it or names its CRLF ending (write LF line endings); or a format check that could not run), `NATIVE_COMPILE_ERROR`, `NATIVE_COMPILE_WARNING` (warnings are errors), `NATIVE_LINK_ERROR`, `NATIVE_BUILD_ERROR` (the toolchain, the build lock, missing build outputs).
- **Refusals.** `PermissionDenied`: `native.build`, `native.load` and the export of a game with `Native/` while the preference is off. `Unsupported`: off Windows. `InvalidState`: `native.load` while a play session runs or without a current successful build; `native.write` while a build runs, an export's included; `native.setComponents` without a loaded module, or on a member of a prefab instance in the edit scene (no prefab override records native components: set them before `prefab.create`, or `prefab.unpack` the instance). `NotFound`: a component name the module does not register, or an Entity value (an id, a unique id prefix or a path) that names no entity. `Validation`: a value its type rejects, at `/components/Native.<Name>/<Field>`. `project.export` fails with `CompileFailed` when the game's Runtime with its module does not build.
- **Native components** are written as `Native.<Name>` and kept as written whatever is loaded. Their findings (`native.load`'s `diagnostics` with `scene` (its path, empty when never saved), `sceneId`, entity and pointer, scene loads, a `--strict` editor): `NATIVE_COMPONENT_UNREGISTERED` (no loaded module registers it; an error under `--strict`, so build and load the module before a strict run), `NATIVE_COMPONENT_INVALID` (its type rejects the value: a Play session of the scene does not start), `NATIVE_FIELD_DROPPED` and `NATIVE_FIELD_RESET` (a reload with a changed layout migrated it by field name; a field renamed with `RenamedFrom` keeps its value). A load whose layout changed (a first load included) migrates every open scene, marking each modified where it migrated a component, and clears every open scene's undo history (`sceneChanged`, `undoCleared`); a value one open scene's types reject fails the load and changes no scene, and the error names that scene by path, or by id when never saved: pass it as `scene` to `native.setComponents`; a reload with an unchanged layout changes nothing. `native.getComponents` and `native.setComponents` take `scene` like the entity tools.
- **A Play session stops fatally** (`play.state`'s `stopped` and `stopError`) when a system throws, naming the system, or reads or leaves a value its type rejects, naming the entity and the component (or the resource); a rejected value a system wrote is put back as the system found it. A crash in native code ends the editor.
- **What a module reaches.** A system reaches built-in state only through its step context (`INativeStepContext`): Transforms, the active flag, name, parent, `FindEntity`, `CreateEntity` and `DestroyEntity`, besides its own components and resources; never a `Text`, `MeshRenderer`, material, light or sound. Scripts and test suites cannot read `Native.*` components or resources (no script proxy: `Entity:HasComponent("Native.<Name>")` raises `NotFound`, its hint naming `native.getComponents`). So test a module through the built-in state its systems write (a suite checks the Transforms), and read its own state from automation: `native.getComponents {entity, target: "Play"}` and `native.status`'s `playResources`. The scene reads see native components as the scene holds them: `scene.tree` lists their names, and `entity.get` and `scene.query` (`where.component`, `select`) carry their JSON. Only `native.setComponents` writes them: a `Native.<Name>` in `entity.create`'s, `entity.update`'s or `prefab.instantiate`'s `components`, or in `removeComponents`, is InvalidParams whose hint names it.
- **Provenance and format.** Every file below `Native/` is engine-consumed: write the sources only with `native.write` (the audit rejects any other origin), keep nothing else there, and write them clang-format clean (tabs, braces on their own lines): the repository's format check reads them, `native.build` reports each source it would refuse as a `NATIVE_FORMAT_WARNING` (rewrite it as the message quotes, then build again until none is left), and `Format.py` never rewrites them (it fails, naming each), since provenance hashed their bytes.

## Error codes and fixes

### JSON-RPC errors (§13.3)

Every error response carries `error.data.errorCode` (the engine `ErrorCode` below) and `issues[]` of `{pointer, message, hint?, suggestions?}`; fix the value at each pointer.

| Code | Name | Fix |
|---|---|---|
| -32700 / -32600 | Parse error / Invalid request | Send one well-formed JSON-RPC 2.0 object per message. |
| -32601 | Method not found | Use a method `rpc.discover` lists; the hint suggests close names. |
| -32602 | Invalid params | Correct each `issues[]` pointer (unknown field, wrong type, out of range, missing required param). A `scene` member on a method that takes no scene target is refused at `/scene`, and on an op of `edit.batch` at `/ops/<i>/params/scene` (give `scene` on the batch instead). The one-script shape `{Script: {Script: ...}}` is an unknown field: give `{Script: {Scripts: [{Script: ..., Fields: {...}}]}}`. |
| -32000 | Internal | An engine bug: read `log.read` and the crash report, then report it with the request. When `error.data.errorCode` is `Io`, `Gpu` or `OutOfMemory`, the environment failed instead: see the engine `ErrorCode` table. |
| -32001 | NotFound | The entity, asset, component, file or topic does not exist: check the path or id; follow the suggestions. |
| -32002 | InvalidState | Not allowed now (no project or scene open, a test run owns the editor, another client owns lockstep, not playing): reach the needed state first. |
| -32003 | ValidationFailed | The input breaks a rule: fix each issue, then retry. |
| -32004 | Conflict | `ifRevision` no longer matches: re-read the state and retry with the current revision. |
| -32005 | Timeout | The call exceeded its deadline: bound the work (fewer ticks per `play.step`) or retry. |
| -32006 | ScriptError | A script raised during the call: read the located error and fix the script. |
| -32007 | Busy | The editor is in a long operation: retry after it ends. |
| -32008 | Unauthorized | Mutations are denied (read-only project or the deny switch): open a writable project or allow automation. |
| -32009 | Unsupported | Not available here (`dryRun` on a method without it, screenshots with `renderer: "none"`). |
| -32010 | Cancelled | The request was cancelled (client disconnect, project closed): repeat it if still needed. |

### Engine `ErrorCode` (`error.data.errorCode`, script and log messages)

| ErrorCode | Meaning | Fix |
|---|---|---|
| `InvalidArgument` | A parameter is malformed or out of range. | Correct the parameter the location names. `input.replay`'s `strictHash` and `withoutInput` each require `verify: true`, and its `continuePastCheckpoint` requires `strictHash: true`. `test.run`'s `expect` requires `record` (at `/expect`), and its expectations' ticks must be in order (at `/expect/<i>/tick`). An `Entity` value inside component data (a script's `Field.Entity()`) takes an id, a unique id prefix or a path, resolved in the scene the call targets; an ambiguous one is refused at its pointer with the candidates as suggestions. An `edit.batch` op's `name` must be an identifier of at most 64 characters, unique in the batch, and `{"$ref": "<name>.<path>"}` must name an earlier op (the hint lists them). A `$ref` path that names no member says which object it inspected (`'0.prefab' (in the result of op 0)`) and lists up to 32 of the members that object has. `prefab.apply`'s `level` must be one of the instance's levels, which the hint lists, outermost first. `scene.close` and `scene.open` take at most one of `save` and `discardChanges`, and `scene.open` and `scene.new` neither with `keepOpen` (nor `scene.open` its `reload`). During play, `target: "play"` with a scene target that names another open scene than the played one. |
| `NotFound` | A file, entity, asset, component or method does not exist. | Fix the reference; check spelling and case (paths are case-sensitive everywhere). A scene target (`/scene`) that names no open scene: `scene.list` lists them (an `id` dies with its scene). `script.eval`'s `script` (`/script`) that names no behaviour of the entity's script slots. |
| `AlreadyExists` | The name, path or id is taken. | Choose another path or open the existing item. |
| `InvalidState` | Not allowed in the current state. | Reach the state the message names (open a project, stop play, wait for a test run). "no scene open" after a launch or attach: `scene_open {path}` (the project's `StartScene`); `editor_status` shows the active scene as `session.scene`. `test.run`'s "is open with unsaved changes": `scene.save` first. `asset.delete` of a folder holding a file whose name no project path can spell (such as `nul.txt` or one ending in a dot) removes nothing: remove that file outside the editor. `prefab.unpack` of a nested instance root: unpack its outermost instance first, as the hint says (one level per call). A second `Scene.Load` or `Scene.Reload` in one frame: the first transition of a frame wins. With several open scenes: a seventeenth open scene (close one); `scene.open` or `scene.new` of a path that is already open (`scene.activate` it, or `scene.open {reload: true}`); `scene.close {save}` of a scene never saved (`scene.save {path}` first); `scene.save` to another open scene's path; `scene.activate` or `scene.close` while a test run owns the editor. |
| `Io` | The operating system refused a file operation. | Check the path, disk space and that no other process locks the file. |
| `Parse` | Malformed JSON or truncated data. | Fix the syntax at the reported line and column. |
| `Validation` | Well-formed input breaks a rule. | Fix the value at the JSON pointer; the hint says how. A recording refused because it "does not depend on its input": end it while the played state is still in the scene, record again, and confirm with `input.replay {verify: true, strictHash: true, withoutInput: true}` ("Common situations"). `PREFAB_CYCLE` from `prefab.apply`: the prefabs named nest each other; nothing was written. |
| `UnsupportedVersion` | A file is newer than this build. | Use a newer engine, or restore the file from the version this engine wrote. |
| `ImportFailed` | An asset failed to import. | Fix the source file; `asset.info` shows its diagnostics. |
| `CompileFailed` | Luau source did not compile. | Fix the syntax at the reported location (`script.check`). |
| `Script` | A script raised, or a reload was refused for its errors. | Fix the script at the reported location. |
| `Gpu` | The GPU device failed or is missing, or was lost during the call (a GPU hang that the driver reset is a loss too). | Use `renderer: "none"` for logic-only work, or check the Vulkan driver. A lost device is recovered at the next frame boundary, play going on as if nothing happened: wait for the `GpuDeviceLost` event (`events.read {types: ["GpuDeviceLost"]}`), then repeat the request. |
| `Timeout` | An operation exceeded its budget. | Bound the work or raise the budget the message names. |
| `PermissionDenied` | A write to a read-only project or mount, or, with mutations denied, a request that would discard an open scene's unsaved changes (`scene.close {discardChanges}`, `scene.open {discardChanges}`, `session.shutdown {force}`). | Open the project writable; never write under `engine://`; save the scene, or allow mutations, before discarding. |
| `Unsupported` | Not available in this host or configuration. | Use a host that supports it (an editor with a renderer, a non-Dist build). |
| `Conflict` | An optimistic-concurrency mismatch. | Re-read and retry with the current revision. |
| `Cancelled` | The operation was cancelled. | Repeat it if it is still wanted. |
| `OutOfMemory` | The request (a screenshot, a resize, a debug view) ran out of GPU memory again after the engine freed what it could rebuild and retried once; only it failed, and the editor goes on (JSON-RPC Internal). | Ask for less (a smaller `width` and `height`, no `debugView`), or repeat it later; a debug view that ran out of memory stays on its previous mode (`viewport.setOptions {}` reads it). |

### Script error kinds (`script.errors` rows, §11.7)

| Kind | When | Fix |
|---|---|---|
| `compile` | The source or a required module does not compile, a require does not resolve, or the module top fails at load time (an engine call at the module top, an error, the 250 ms load budget). Also a reload refused for these. | Fix the reported location; keep module tops free of engine calls (do that work in callbacks). |
| `type` | A reload refused because the new source has type errors while `Scripting.BlockPlayOnTypeErrors` is set, or in a test run (callback `Reload`). The running code is kept. | Fix the type error at the reported location (`script.check`), then save again to reload. |
| `runtime` | A callback, task or test case raised. The instance is disabled. | Fix the line in the traceback; guard optional values (`if self.Goal then`). |
| `timeout` | A callback ran past `Scripting.CallbackBudgetMs`. | Remove the unbounded loop, or spread the work over ticks with a task. |
| `memory` | The VM passed `Scripting.MemoryLimitMB`; a second breach stops the session. | Stop allocating per tick (pool tables and entities), or raise the limit deliberately. |

### Validation codes (`project.validate`, `reference/Validation`)

`project.validate {fix: true}` applies every safe fix; `fix: ["<id or CODE>"]` only the selected ones, as one undoable command. Each diagnostic's `autoFixable` says whether that one can be fixed automatically.

| Code | Severity | What it means | Fix |
|---|---|---|---|
| `SCENE_NO_PRIMARY_CAMERA` | Warning | A scene with entities has no Primary camera. | Set Primary on the camera, or add one with `entity.create {components: {Camera: {Primary: true}}}`; the fix makes a scene's only camera Primary. |
| `SCENE_MULTIPLE_PRIMARY_CAMERAS` | Error | Several cameras are Primary. | Clear Primary on all but one; the fix keeps the first in scene order. |
| `SCENE_DUPLICATE_UNIQUE_COMPONENT` | Error | A scene file holds two Environment or PostProcess components. | `scene.open {repair: true}`, then `scene.save`. |
| `SCENE_NONCANONICAL_ORDER` | Warning | A child is listed before its parent in a scene file. | `scene.open {repair: true}`, then `scene.save`. |
| `SCENE_INVALID_HIERARCHY` | Error | A Parent names no entity, or parents form a cycle. | `scene.open {repair: true}`, then `scene.save`. |
| `SCENE_INCONSISTENT_PREFAB_LINK` | Error | A prefab member's PrefabLink does not match its instance root, an OuterPrefabEntityID names no enclosing instance, or a nested instance root records overrides. | `scene.open {repair: true}` (unpacks the member, clears the OuterPrefabEntityID or drops the nested root's overrides), then `scene.save`, or re-instantiate the prefab. |
| `ENTITY_DUPLICATE_ID` | Error | Two entities of a file share an ID. | `scene.open {repair: true}`, then `scene.save`. |
| `ENTITY_DANGLING_REFERENCE` | Warning | An entity reference names no entity of its scene. | Point it at an existing entity; the fix clears it in the open scene. |

| `ASSET_MISSING` | Error | A reference names a handle no asset has. | Restore the asset (`edit.undo` of its deletion) or assign another. |
| `ASSET_TYPE_MISMATCH` | Error | A reference names an asset of another type, or a .meta disagrees with its source. | Assign an asset of the accepted type; the fix rewrites a mismatching .meta for the importer that takes the source, keeping its handle. |

| `ASSET_VERTEX_COLORS_IGNORED` | Warning | A glTF primitive has vertex colours, which are ignored. | Bake them into a texture or material. |
| `ASSET_CONTENT_SKIPPED` | Warning | A glTF holds skins, animations, cameras, lights, points or lines. | Remove them, or rebuild cameras and lights as components. |
