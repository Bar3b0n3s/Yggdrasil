# Built-in assets

Generated by `Editor --dump-reference` and written by `python Scripts/GenerateDocs.py`; do not edit by hand.

The assets the engine ships, which every project references by engine path, such as `engine://Meshes/Cube` in a MeshRenderer's `Mesh` or `engine://Environments/Studio` in an Environment's `Environment` (Architecture §7.1). The engine's catalogue `Resources/EngineAssets.json` names them; this page lists every entry, sorted by path. `asset.list {dir: "engine://"}` lists them too (a folder such as `engine://Environments` narrows the list), `asset.info` describes one, and an engine path that names nothing is refused with the closest built-in paths as suggestions. Built-ins have no `.meta` and cannot be changed: create a project asset instead (`asset.create`). The id is the asset's handle, which scenes and prefabs store.

## Placeholders

A load that fails gets its type's placeholder (Architecture §7.2) and records a diagnostic: AudioClip `engine://Audio/Silence`, Font `engine://Fonts/Default`, Material `engine://Materials/Error`, Mesh `engine://Meshes/Cube`, Texture `engine://Textures/Missing`. Scenes, prefabs, scripts and replays report their failure instead, and an environment that fails lights the scene with the Environment's `FallbackColor`.
