# Automation methods

Generated by `Editor --dump-reference` and written by `python Scripts/GenerateDocs.py`; do not edit by hand.

The 89 JSON-RPC methods of the editor's automation server in 21 domains (Architecture §13), from the method registry. This is the compact reference: `Methods.json` holds every method's full params and result schemas, as `rpc.discover` returns them. Params keys are camelCase; component and asset data inside them keep their registry PascalCase. Every member is optional unless marked required, and defaults to the value shown.

Flags: **tool** (proxied by the MCP bridge as the named tool), **mutates** (changes project files or the open scene), **dry run** (accepts `dryRun: true`), **runtime** (also served by the Runtime), **launcher** (callable before a project is open), **batch** (allowed as an op of `edit.batch`), **scene target** (accepts `scene`, the path or the `scene.list` id of the open scene the request addresses; absent, the active scene; **scene target (required)** requires it), **pending** (resolves later).

## asset

### asset.create

Creates a material or a sound effect (with values over the defaults), an empty scene, a one-entity prefab or a folder below Assets/, with its .meta and any missing parent folders, as one undoable command. A folder that already exists succeeds without a command (created: false), so a Folder op is needed only for an empty folder.

- Flags: tool `asset_create`, mutates, dry run, batch
- Timeout: 60 s
- Required params: `type`, `path`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `type` | `AssetCreateType` | yes | `"Material"` | What to create. |
| `path` | `String` | yes | `""` | The project-relative path below Assets/, with the type's extension (.material, .scene, .prefab, .sfx; none for a folder); missing parent folders are created with it. |
| `values` | `Variant` |  | `null` | A Material's or a SoundEffect's fields over the defaults (registry names, such as Roughness, or Layers, which a sound effect needs); absent for other types. |

| Result | Type | Description |
|---|---|---|
| `asset` | `AssetSummary` | The created asset; an empty id and type None for a folder. |
| `path` | `String` | The project-relative path created. |
| `undoIndex` | `UInt32` | The command's undo index; 0 in a dry run or a batch, and when nothing was created. |
| `created` | `Bool` | Whether anything was created: false only for a Folder whose path is already a folder, which succeeds without a command. |

Example: Create a red material.

```json
{"type":"Material","path":"Assets/Materials/Red.material","values":{"BaseColor":[0.9,0.15,0.15,1],"Roughness":0.45}}
```

Example: Create a two-note coin pickup sound.

```json
{"type":"SoundEffect","path":"Assets/Audio/Coin.sfx","values":{"Layers":[{"Wave":"Square","Notes":["B5:0.05","E6:0.2"]}]}}
```

### asset.delete

Moves an asset with its .meta (and a glTF's dependency files) to Library/Trash as one undoable command; never a permanent delete. A folder below Assets/ that holds no files (only empty folders) is removed, also undoably; a folder that holds files is refused (Validation, naming them): delete its assets first.

- Flags: tool `asset_delete`, mutates, batch
- Timeout: 60 s
- Required params: `asset`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `asset` | `String` | yes | `""` | The asset to move to the trash (a source, not a sub-asset), or a folder below Assets/ that holds no files, to remove. |

| Result | Type | Description |
|---|---|---|
| `asset` | `AssetSummary` | The asset as it was; for a folder its path, with an empty id and type None. |
| `trashDirectory` | `String` | Where its files went: "Library/Trash/\<entry>"; empty for a folder, which holds none. |
| `trashedFiles` | `Array<String>` | The old paths of every file trashed, .meta files and dependency files included. |
| `removedFolders` | `Array<String>` | A folder delete: the folder and every empty folder below it, project-relative and sorted; empty for an asset. |
| `undoIndex` | `UInt32` | The command's undo index; 0 in a batch. |

Example: Delete an unused material.

```json
{"asset":"Assets/Materials/Old.material"}
```

### asset.setImportSettings

Applies an RFC 7386 merge patch to an asset's import settings as one undoable command; the asset reimports. For a glTF that an open scene instantiates or a prefab nests, the prefabs nesting it and the instances follow in the same undo step, and the instances of the other open scenes in their own undo histories.

- Flags: mutates, batch
- Timeout: 60 s
- Required params: `asset`, `settings`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `asset` | `String` | yes | `""` | The asset (a source, not a sub-asset). |
| `settings` | `Variant` | yes | `null` | An RFC 7386 merge patch of the import settings. |

| Result | Type | Description |
|---|---|---|
| `asset` | `AssetSummary` | The asset. |
| `importer` | `String` | The importer's id. |
| `settings` | `Variant` | Every field after the patch. |
| `undoIndex` | `UInt32` | The undo index; 0 when nothing changed or in a batch. |

Example: Import a texture as a normal map.

```json
{"asset":"Assets/Textures/WoodNormal.png","settings":{"Usage":"NormalMap"}}
```

### asset.setProperties

- Required params: `asset`, `values`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `asset` | `String` | yes | `""` | The native asset (a material or a sound effect). |

| Result | Type | Description |
|---|---|---|
| `asset` | `AssetSummary` | The asset. |
| `values` | `Variant` | Every property after the patch. |
| `undoIndex` | `UInt32` | The command's undo index; 0 when nothing changed, in a dry run or a batch. |

## docs

### docs.get

Serves the agent documentation: without a topic the list of topics (skills, the generated reference and JSON schemas, the script declarations, the script templates and the native module's interface); with one its text, one section of it (section, or "\<topic>#\<section>", by heading text or anchor), one page (offset, length) or with toc only its section list with sizes. A text too large to return inline comes back as its first page with nextOffset and its list of sections.

- Flags: tool `docs_get`, launcher, batch
- Timeout: 60 s

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `topic` | `String` |  | `""` | The topic, such as "skills/game-building", "reference/ScriptAPI", "reference/Schemas/Scene", "scripting/Engine.d.luau", "templates/Scripts/Behaviour" or "native/NativeApi.h"; a "#\<section>" suffix selects a section like section; empty for the list of topics. |
| `section` | `String` |  | `""` | A section of the topic: a Markdown heading, or a top-level declaration of a .d.luau topic ("Entity"). Named by the heading's exact text ("Test.Suite"), by that text without a trailing parenthesized qualifier ("TestSuite" for "TestSuite (type)"), or by its anchor (the text lowercased, spaces as '-', other ASCII punctuation removed, "-1" added to a repeat: "testsuite-type"), tried in that order; a text several headings share is refused with their anchors. The result is the section with its subsections. |
| `offset` | `UInt32` |  | `0` | Where the page starts, in bytes of the topic's (or the section's) text: 0, or the previous page's nextOffset. |
| `length` | `UInt32` |  | `32768` | The most bytes of text to return (the default is the most). A page ends after a line break when one falls inside it. |
| `toc` | `Bool` |  | `false` | Return no text, only the topic's section list (or the subsections of section) with each section's title, anchor, level, offset and size, down to the deepest heading level whose list fits in 40960 bytes, and totalBytes. Not with offset or length. |

| Result | Type | Description |
|---|---|---|
| `topics` | `Array<DocsTopic>` | Every topic, when no topic was asked for. |
| `topic` | `String` | The topic asked for, without its "#\<section>". |
| `section` | `String` | The anchor of the section returned; empty for the whole topic. |
| `content` | `String` | The text (Markdown for skills and reference documents), or one page of it. |
| `path` | `String` | The topic's file, relative to the repository root. |
| `offset` | `UInt32` | Where content starts in the topic's (or the section's) text, in bytes. |
| `totalBytes` | `UInt32` | The size of the topic's (or the section's) text. |
| `nextOffset` | `UInt32` | The offset of the next page; 0 when content reaches the end of the text. |
| `sections` | `Array<DocsSection>` | The sections of the text: with the first page of a text that needs several pages, every heading level whose list fits in 12288 bytes; with toc, every level whose list fits in 40960 bytes. |

Example: Read the add-automation-method skill.

```json
{"topic":"skills/add-automation-method"}
```

Example: Read the Input section of the script API reference.

```json
{"topic":"reference/ScriptAPI","section":"Input"}
```

Example: Read the first 8 KB of the script declarations.

```json
{"topic":"scripting/Engine.d.luau","offset":0,"length":8192}
```

Example: List the sections of the script API reference with their sizes.

```json
{"topic":"reference/ScriptAPI","toc":true}
```

| `undoIndex` | `UInt32` | The batch's undo index; 0 in a dry run or when nothing changed. |

### input.record

Starts a tick-zero recording or saves its validated applied inputs, expectations and state-hash checkpoints (one every 60 ticks). Stop checks output write permission. Every recording is first replayed with its input events, if any (the verification, which replaces the play session as input.replay does): unless that run reproduces every checkpoint, the final hash and every expectation and raises no script error, Stop refuses to write it (Validation naming the first divergence, the run's outcome in error data verification), which catches a script.eval that wrote script state during the recording. Once the run passed, its scripts are stopped, and an error their OnDestroy raises refuses the recording too (named at teardown). A recording without input events is then written, and the play session is the verification's, paused at its final tick with its scripts stopped (script.eval in the play context is refused there; scene.query and entity.get read its final state). One with input events is then replayed without them (the input check); when that run also reproduces every checkpoint, the final hash and every expectation, whatever script errors it raises, the recording's outcome does not depend on its input and Stop refuses to write it (Validation, the check's outcome in error data inputCheck). The play session is then the last run's, paused where it ended. End such a recording while the played state is still in the scene.

- Flags: tool `input_record`, runtime, pending
- Timeout: 600 s
- Required params: `action`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|

| `path` | `String` |  | `""` | Stop only, required: confined replay destination (Runtime relative paths are below user://Replays). |
| `expect` | `Array<InputRecordExpectation>` |  | `[]` | Stop only: ordered expectations, compiled before consuming the recording. |

| Result | Type | Description |

### input.replay

Replays recorded inputs in a fresh session; verification failures retain every expectation and hash outcome in error data. strictHash compares the state hash at each checkpoint and at the final tick and, unless continuePastCheckpoint, stops at the first checkpoint that differs. The state hash covers the simulated world (entities and their serialized components, the tick, Random, id draws, physics), never script tables, so expectations observe script state. withoutInput replays without the input events, the check that the replay depends on its input. Afterwards the session stays paused at the replay's last tick (or where playback stopped), so script.eval, scene.query and entity.get read its final state; play.stop ends it.

- Flags: tool `input_replay`, runtime, pending
- Timeout: 600 s
- Required params: `path`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | `String` | yes | `""` | Replay asset path, or a Runtime recording's returned user://Replays identity. |
| `verify` | `Bool` |  | `false` | Evaluate cooked expectations. |
| `strictHash` | `Bool` |  | `false` | Compare the recorded state hash at every checkpoint and at the final tick; requires verify. The first checkpoint that differs ends the playback there, unless continuePastCheckpoint. |
| `withoutInput` | `Bool` |  | `false` | Apply none of the replay's input events: the check that its outcome depends on its input; requires verify. A replay whose verification still passes this way proves nothing about its input. |
| `continuePastCheckpoint` | `Bool` |  | `false` | Play on past every checkpoint whose hash differs, to the final tick, and compare the final hash too; requires strictHash. The replay still fails when any checkpoint differed (checkpointsFailed, firstFailedCheckpointTick). With withoutInput it tells a replay whose final hash alone does not depend on its input. |

| Result | Type | Description |
|---|---|---|
| `passed` | `Bool` | Playback and all requested verification passed. |
| `verified` | `Bool` | Expectation verification was requested. |
| `hashChecked` | `Bool` | The state hashes (every checkpoint and the final one) were compared. |
| `hashMatched` | `Bool` | Compared hashes matched. |
| `finalTick` | `UInt32` | Completed simulation ticks: the replay's final tick, or where playback stopped. |
| `stateHash` | `String` | Observed state hash at finalTick. It covers the simulated world only (every entity with its serialized components, the tick, the session's Random state, the id draws and every body's physics state), never script tables, audio or input. |
| `expectedStateHash` | `String` | Recorded state hash at finalTick: the final hash, or the failed checkpoint's. |
| `stopReason` | `String` | Why playback ended before the replay's final tick (a quit, a fatal script error or a checkpoint whose hash differed); empty when it reached it. |
| `checkpointsChecked` | `UInt32` | State-hash checkpoints compared (strictHash), the failed one included. |
| `checkpointFailed` | `Bool` | A checkpoint's hash differed. Without continuePastCheckpoint playback stopped at its tick (finalTick), and stateHash and expectedStateHash are the observed and recorded hashes there; with it, playback went on to the final tick and firstFailedCheckpointTick names the first. |
| `withoutInput` | `Bool` | None of the replay's input events were applied. |
| `checkpointsFailed` | `UInt32` | continuePastCheckpoint: the checkpoints whose hash differed; 0 otherwise. |
| `firstFailedCheckpointTick` | `UInt32` | continuePastCheckpoint: the tick of the first checkpoint whose hash differed; 0 when none differed or without continuePastCheckpoint. |
| `changes` | `Array<String>` | When a hash differed in a playback with the replay's input: what changed since the recording, by the replay's start fingerprint (an entity, a component of an entity, a script, a material or another referenced asset), one line each; empty for a replay recorded without a fingerprint. |
| `expect` | `Array<InputReplayExpectationResult>` | Every expectation outcome in authored order. |

Example: Verify a replay.

```json
{"path":"Assets/Tests/Recorded.replay","verify":true,"strictHash":true}
```

- Timeout: 7800 s
- Required params: `config`

| Param | Type | Required | Default | Description |
|---|---|---|---|---|
| `config` | `ExportConfiguration` | yes | `"Release"` | The build configuration whose Runtime and shaders the export packages. |
| `outDir` | `String` |  | `""` | The project-relative output directory below Build/; empty or absent: Build/\<Platform>-\<Config>/\<Name>. An earlier export there is replaced once the new one is complete. |
| `smokeTest` | `Bool` |  | `false` | Run the exported game headless for 300 frames with --expect-no-errors before it replaces the output directory, and require exit code 0. |
| `testing` | `Bool` |  | `false` | A testing export: Game.json says Testing true, so the exported game runs --feature-test; Assets/Tests/** and every Testing.Suites script and scene and Testing.Replays match are packaged whatever Export.Exclude says; invalid suites (TEST_SUITE_INVALID) and replays that do not import fail validation. Its default output directory is Build/\<Platform>-\<Config>-Testing/\<Name>. |
| `featureTest` | `Bool` |  | `false` | With testing: run the staged game's --feature-test before it replaces the output directory and report its replays' state hashes in featureTest, the hashes the games suite's Dist half compares with the editors'. A failing run does not fail the export; the report says so. |

| Result | Type | Description |
|---|---|---|
| `outputDirectory` | `String` | The absolute path of the exported game's folder. |
| `executable` | `String` | The absolute path of its executable, named after the project. |
| `config` | `ExportConfiguration` | The configuration exported. |
| `files` | `Array<ExportedFileSummary>` | Every file of the package, sorted by path. |
| `gameAssetCount` | `UInt32` | The cooked assets in Data/Game.pak. |
| `engineEntryCount` | `UInt32` | The entries of Data/Engine.pak: shader files and built-ins. |
| `warnings` | `Array<String>` | What the export left out or could not check. |
| `smokeTestRan` | `Bool` | Whether the smoke test ran: false without smokeTest, and for a Dist export from an editor without a graphics device. |
| `smokeTestExitCode` | `Variant` | The smoke test's exit code, an integer; null when it did not run (smokeTestRan false). |
| `seconds` | `Float` | How long the export took (wall-clock time, for information). |
