### 2. The six components (R-UI-CORE, R-UI-RENDER, R-UI-TEXT, R-UI-LAYOUT)

A category of their own, **Ui**, after Scripting (ADR 0028's phase-2 ledger: phase 2's categories go after Scripting in landing order; M21's go before or after by landing), registered by `RegisterUiComponents` in `Scene/Registration/UiRegistration.cpp`, each at version 1 with the default flags (serializable, script-visible, editor-visible, removable), in this order:

| Component (registry name) | Fields (defaults, ranges) | Relations |
|---|---|---|
| `UiCanvasComponent` (`UiCanvas`) | `int32 SortOrder{0}`; `UiScaleMode ScaleMode{ConstantPixelSize}` (ConstantPixelSize, MatchHeight); `float ScaleFactor{1}` (0.01 to 100); `float ReferenceHeight{1080}` (1 to 100,000); `bool PixelSnap{true}` | excludes UiRect (declared by both, as RigidBody and CharacterController are) |
| `UiRectComponent` (`UiRect`) | `vec2 AnchorMin{0.5}`, `vec2 AnchorMax{0.5}` (0 to 1; AnchorMin at most AnchorMax per axis, a Validate hook with its Generate hook); `vec2 Pivot{0.5}` (0 to 1); `vec2 Position{0}`, `vec2 Size{100}` (±1,000,000 canvas units); `bool ClipChildren{false}` | excludes UiCanvas |
| `UiImageComponent` (`UiImage`) | `AssetRef<SpriteSheet> Sheet` (null: a plain rectangle of Color); `uint32 Frame{0}` (0 to 65,535); `color4 Color{1}`; `UiImageType Type{Simple}` (Simple, Sliced); `float BorderScale{1}` (0.01 to 1000); `UiImageFilter Filter{Point}` (Point, Linear) | requires UiRect |
| `UiTextComponent` (`UiText`) | `std::string Text`; `AssetRef<Font> Font` (null: the default font); `float Size{32}` (1 to 100,000 canvas units per em); `color4 Color{1}`; `TextAlignment Alignment{Left}` (the Text component's registry enum); `UiTextVerticalAlignment VerticalAlignment{Top}` (Top, Middle, Bottom); `bool Wrap{true}`; `float LineSpacing{1}` (0.1 to 10) | requires UiRect |
| `UiLayoutComponent` (`UiLayout`) | `UiLayoutKind Kind{Stack}` (Stack, Grid, Flex); `UiLayoutDirection Direction{Vertical}` (Horizontal, Vertical); `UiPadding Padding` (registry struct `UiPadding {Left, Top, Right, Bottom}`, each 0 to 1,000,000); `vec2 Spacing{0}` (0 to 1,000,000); `UiMainAlignment MainAlignment{Start}` (Start, Center, End); `UiCrossAlignment CrossAlignment{Start}` (Start, Center, End, Stretch); `uint32 Columns{0}` (0 to 1024); `vec2 CellSize{100}` (0 to 1,000,000); `bool Wrap{false}` | requires UiRect |
| `UiLayoutElementComponent` (`UiLayoutElement`) | `bool IgnoreLayout{false}`; `float Grow{0}`, `float Shrink{1}` (0 to 1000); `vec2 MinSize{0}` (0 to 1,000,000) | requires UiRect |

- **Why these six.** The plan's W22.1 names a canvas and rectangles (R-UI-CORE), images with 9-slice and clipping (R-UI-RENDER), text (R-UI-TEXT) and stack, grid and flex containers (R-UI-LAYOUT): a container component holds the three kinds (one component, so a container switches kind without losing its padding and alignment), and its children's flex weights and opt-out need a per-child component (UiLayoutElement). Clipping is a rectangle's flag (`ClipChildren`), so W22.2's ScrollView clips with it and needs no component of its own.
- **Elements.** A UI element is an entity with a UiRect below a canvas; its parent element is its nearest ancestor with a UiRect below that canvas, or the canvas (an entity without a UiRect in between is transparent to the layout). A UiLayout container places the elements whose parent element it is, in canonical order, so a grouping entity's elements are placed as the container's own (`UiLayoutComponent.h`, `UiRectComponent.h`, `UiLayout.h` and `UiContainerLayout.h` state the same rule). A UiCanvas below another canvas's element starts a canvas of its own, laid out over the whole scene image. A canvas has no rectangle of its own (it excludes UiRect), so a full-screen background is a child with stretched anchors. An entity may hold a UiImage and a UiText together (a button's background and label): the image draws first.
- **Left for later waves, with a stated reason:** a canvas's render mode (C22.3 adds `RenderMode` with World and Screen; a one-value enum now could not be covered by FeatureTest's gate 1, which needs a non-default value of every field); interaction (`RaycastTarget`, widgets, focus) and the canvas's theme font (C22.2). Fields are added while the components are unlanded, so no version changes within M22.
- **The demos' hashes.** No audited project holds a UI component (fact 8), so the components change no hash and need no canonical upgrade.

### 3. The UiLayout and FrameUiLayout phases, and the session's UI (R-UI-CORE; stream A)

- **Positions** (ADR 0028's phase-2 execution order; `PlaySessionPhase` in `Session/PlaySession.h`): **UiLayout** ends the fixed step, after PostStepTransformUpdate, so the layout matches the state the step left; **FrameUiLayout** follows FrameTransformUpdate and precedes AudioUpdate and RenderExtraction, so UI written in `OnUpdate` or `OnLateUpdate` is laid out as the frame draws it. The contract adds both enumerators and their names; stream A runs them (`EnterPhase`), in Play and Simulate, with or without a canvas, and adds them to "PlaySession: step order matches the documented sequence" and "PlaySession: Simulate mode skips the script and audio phases", which change with it (extended, not weakened). C22.2 and C22.3 insert TextLatch and UiInput after ApplyInput and UiEvents after StartFlush, and M21 and M23 their own phases, at the ledger's positions.
- **`UiSystem`** (`Scene/UiSystem.h`), owned by the session (`PlaySession::GetUi`): `LayoutStep` and `LayoutFrame` compute `ComputeUiLayout(scene, sceneSize)` into the step's and the frame's table; `GetLayout` is the later of the two (the frame's when a FrameUiLayout ran after the last UiLayout, the step's when none did), which W22.2's UiInput hit-tests and `ui.tree` reads, so a hit test depends only on the state, never on how many frames ran between two ticks (the ledger).
- **The scene resolution.** Both phases lay out at the session's scene resolution: in W22.1 the session's view size (`GetViewSize`: the game view in live play, the project's window size, `GetDeterministicViewSize`, in every deterministic session), the scene resolution of the default `RenderOutputSettings`. The later lander of M21 and M22 makes it the scene resolution M21's PixelPerfectCamera sets (the combined test, plan §3.5), in the session and in extraction alike.
- **Not simulated state.** Layouts are derived from the scene and the scene resolution; they never reach the state hash. W22.2's ui hash block (after physics2d, empty without a canvas) holds interaction state only.
- **The current scene's layout, always.** Outside the phase list (no observer reports it), `PlaySession::Activate` ends, after the scene's startup callbacks, with `LayoutStep` of the session's scene, and so does a `Scene.Load` or `Scene.Reload`'s replacement of the scene at the end of a frame (`ConsumeRequests`, after the new scene's startup): `GetLayout` is empty only before `Activate` and never describes a replaced scene, so `ui.tree {target: play}` right after `play.start` lists the UI, and the first UiInput after a load hit-tests the loaded scene (`UiSystem.h`, `PlaySession.h`; "PlaySession: the current UI layout is the scene's from the start and the loaded scene's right after a Scene.Load").

### 4. Layout (`Scene/UiLayout.h`; R-UI-CORE; stream A)

- **Space.** Scene pixels: x right, y down, origin at the scene image's top-left corner (ADR 0029 decision 8). A canvas covers the scene image; its scale is `ScaleFactor` (ConstantPixelSize) or `sceneHeight / ReferenceHeight` (MatchHeight); its size in canvas units is the scene resolution over its scale.
- **A rectangle in its parent's** (`UiRectComponent.h`): anchor rectangle `A = [P.Min + AnchorMin * P.Size, P.Min + AnchorMax * P.Size]`; size `(A.Max - A.Min) + Size`, each component at least 0; pivot point `A.Min + Pivot * (A.Max - A.Min) + Position`; rectangle `[pivot point - Pivot * size, + size]`; in canvas units, then times the scale from the canvas's origin. A UiLayout parent places its children instead (decision 5), unless a child's UiLayoutElement ignores the layout.
- **PixelSnap** rounds each corner to `floor(v + 0.5)` scene pixels after the scale and before the children are placed in it, so images and clips land on pixel corners.
- **Clip:** the intersection of `ComputeUiClipRect` of every ancestor element with ClipChildren; the element's own flag clips only its descendants. A rectangle covers the pixels whose centres it holds (`min <= x + 0.5 < max`), so `ComputeUiClipRect` is `ceil(v - 0.5)` at both ends (`UiClipRect`, `Renderer/UiDrawList.h`), each clamped to ±2^30 (`UiClipCoordinateLimit`; a NaN to -2^30) before it converts to int32. The registry's ranges do not keep rectangles inside int32 (a MatchHeight canvas scales a unit to up to the scene's height in pixels, and lengths add down a hierarchy), nor inside float's exact integers (2^24): such values are inexact but deterministic, and the clamp keeps the conversion defined.
- **Visible:** the rectangle, intersected with its clip and with the scene image, covers a pixel.
- **The table** (`UiLayoutTable`): the scene resolution; every effectively enabled canvas in draw order (ascending SortOrder, ties in canonical order) with its scale, size and node range; every effectively enabled element of each canvas in canonical order (a parent before its children, siblings in order: painter's order), with its canvas, parent, depth, rectangle, clip and visibility. An effectively disabled element and its subtree are left out and take no space in a container; a UiRect without a canvas ancestor is not laid out (project.validate's `UI_ELEMENT_WITHOUT_CANVAS`, decision 13).
- **Deterministic:** only IEEE-exact float operations (+, -, *, /, comparisons, floor and ceil) on the components' values, in canonical order; no asset access (decision 6). The acceptance "UI layout tables are byte-identical across configurations" is checked by the layout cases' exact expected values in the Debug and Release unit runs, and by the UI replays of W22.2 in the four runs.

### 5. Containers (`Scene/UiContainerLayout.h`; R-UI-LAYOUT; stream D)

`LayoutUiContainer(layout, containerSize, children)` places a container's children (the elements whose parent element it is, decision 2) in canvas units; the header states every rule. In short: the inner rectangle is the container's less Padding; a child's preferred size is its UiRect Size (its UiLayoutElement adds MinSize, Grow and Shrink); **Stack** puts the children one after another along Direction with Spacing, the run placed by MainAlignment (an overflowing run starts at the inner start); **Flex** shares the line's free space by Grow or takes the overflow back by Shrink times size (never below MinSize, without redistribution; a line whose total of Shrink times size is 0 does not shrink and overflows), with Wrap starting new lines, each line as tall as its tallest child; **Grid** gives each child a cell of CellSize, Columns per row (Horizontal) or column (Vertical), or with Columns 0 as many as fit, clamped to 1 to 1024 (1024 when the main axis's cell plus spacing is 0); CrossAlignment places each child across its line (Stretch fills it, a Stack's or Flex's child never below its MinSize; such a child larger than its line follows the same formula, so Center overflows both sides equally and End overflows the start, accepted at W22.1's integration). No rule divides by 0, and every placed size is at least 0. A container's own size never follows its children (decision 6). A pure function, called by stream A's `ComputeUiLayout`; the header is public so the unit tests reach it (a Scene `Private/` header is Scene's alone, Lint's `include-private`).

### 6. Text measurement and character ranges (R-UI-TEXT, R-UI-L10N's ranges; stream B)

- **Beside the frozen `TextLayout.h`** (ADR 0013 decision 11), which keeps laying out TextComponent unchanged: `Renderer/TextMeasurement.h`, `MeasureText(fonts, text, options)` and `MeasureTextSize`, from a font chain's metrics to positioned glyphs in pixels, lines (their byte ranges, left, width, top and baseline) and a block size, with word wrapping (`TextWrap::Word` breaks at spaces, a word wider than `MaxWidth` between glyphs), line feeds, `LineSpacing` and alignment within `MaxWidth` (or the widest line). The header states the contract's rules, and `TextMeasurement.cpp`'s file comment and Architecture §8.10 the finer wrapping rules stream B implemented beside them (W22.1's integration: which space of a run a line breaks at, that a line never wraps empty, where skipped bytes and carriage returns belong, one skipped codepoint per ill-formed byte, the 2^32 - 1 byte bound); the output is identical for equal inputs in every configuration.
- **Shaping and bidi are reserved for W22.3** behind these signatures: `TextDirection` (Auto, LeftToRight, RightToLeft; every value lays out left to right in W22.1), `TextMeasuredGlyph::ByteOffset` (a cluster's first byte once HarfBuzz shapes clusters) and the **font chain** (a codepoint takes the first font of the chain with a glyph for it; W22.1's callers pass one font, W22.3's fallback chain more). C22.3 pins HarfBuzz and SheenBidi and puts them inside `MeasureText`.
- **Scene does not include it.** ADR 0028's ledger adds the measurement header to SnapshotHeaders "if Scene's layout includes it"; it does not: render extraction reads no asset (fact 3), so Scene's layout needs no font, and a rectangle never follows its content (a label is not sized to its text, an image not to its frame, a container not to its children). Text wraps and aligns inside the rectangle it is given, which the renderer lays out with its fonts, as it lays out TextItems (decision 7). The header includes nothing beyond Core, Asset, glm and the standard library, so a later contract may list it if content sizing is ever wanted. Recorded as an accepted limit (Backlog §6).
- **Character ranges:** Latin-1 is already baked (fact 4). Per-font ranges are a new import setting, frozen here and landed by stream B with the registry change: `FontImportSettings.Ranges`, an array of the registry struct `FontCharacterRange {First, Last}` (UInt32 codepoints, `0x20 <= First <= Last <= 0x10FFFF`, at most 64 ranges and 65,536 codepoints in all, located Validation errors otherwise), baked with ASCII and Latin-1 (codepoints the font lacks left out, as today); **FontImporter version 4** (the ledger's "4 and up": every cached atlas is rebuilt once, byte-identical for a font without ranges). `FontData` stays at format 1 in W22.1 (the glyph list grows; C22.3 takes FontData 2 if shaping needs glyph indices). The default font takes no ranges, so its atlas, and the Text golden, do not change.

### 7. The draw list and the Ui pass (R-UI-RENDER; stream C)

- **`Renderer/UiDrawList.h`** (in SnapshotHeaders and Scene's Headers): `UiDrawList {Items, Annotations}` over a memory resource like the snapshot's containers (M18's R-ARENA); a `UiDrawItem` is an image or a text of one element in scene pixels with its entity, rectangle, colour and clip, and for an image its sheet handle, frame, type, border scale (scene pixels per texel) and filter, for a text its string, font handle, size in scene pixels per em, alignments, wrap and line spacing (the draw list's own enums, since the header cannot include Scene); a `UiAnnotation` is a capture's outline or label (decision 9). `RenderSnapshot::Ui` follows `Output` (ADR 0028's ledger).
- **Extraction** (`ExtractRenderSnapshot`, `Scene/UiExtraction.h`'s `AppendUiDrawItems`, stream C's code in `RenderExtraction.cpp` after M23's paths): for the Primary and Entity camera sources (the game view and a camera's view; a view without a primary camera draws its UI, as it draws its screen texts), every canvas laid out at the scene resolution of the snapshot's Output (the view's size by default) and each visible element's image, then its text when not empty, with the canvas's scale applied to the lengths. The editor's scene view (Explicit) draws no game UI; W22.2's authoring overlay decides what the editor shows there. Extraction lays out afresh: the layout is a pure function, so the game view's draw list equals the session's frame layout at the same scene resolution, and a screenshot at another size lays out at its own (fact 3: every host gets UI without a change).

### 8. `ui.tree` (R-UI-AUTO; stream E)

- **`ui.tree {canvas?, depth?, format?, width?, height?, target?}`** (`Engine/Automation/Methods/UiMethods.h`), shared by the editor and the Runtime: the target scene's UI laid out in scene pixels. The play scene reads the session's current layout (`UiSystem::GetLayout`) at its scene resolution unless `width` and `height` ask for another; the edit scene is laid out at `width` x `height`, by default the project's window size (`GetDeterministicViewSize`, the view of every deterministic session). `canvas` (an EntityRef) narrows it to one canvas; `depth` limits the levels below each canvas (0: unlimited); `format` is `SceneTreeFormat`'s Text or Json.
- **The result:** `{scene, width, height, text | elements}`; an element (`UiTreeEntry`) is `{id, name, path, canvas, parent, depth, components, rect, sortOrder, scale, clipped, clip, visible, text}` (`sortOrder` and `scale`, the scene pixels per canvas unit at the resolution laid out at, are a canvas's, 0 for an element, as the text outline prints them) (rectangles as `UiPixelRect {x, y, width, height}`; the text cut to 256 bytes at a UTF-8 boundary) plus the **interaction fields reserved for W22.2**, reported as their defaults until then: `interactable`, `focused`, `hovered`, `pressed` and `widget` (the widget kind W22.2 names; W22.3's `TextInput`). The text outline: a header line `<file name>  rev <n>  <width>x<height> scene pixels  <count> elements`, then per canvas `<name> <8 hex> UiCanvas(sort <n>, scale <s>)` and per element a box-drawn line with its name, 8 hex digits, short component forms (`UiImage(<sheet path>#<frame>)`, `UiText("<text>")`, `UiLayout(<kind> <direction>)`), its rectangle `(x,y wxh)` and `clipped` or `hidden`.
- **Flags:** a tool (`ui_tree`; §13.8: 66 proxied tools), `AvailableInRuntime`, `AllowedInBatch`, `SupportsSceneTarget` (the scene-target inventory's Target: it reads the addressed scene, ADR 0031 decision 16), not mutating, no dry run (a read). Errors: the target's and `canvas`'s (ResolveEntity at `/canvas`); InvalidArgument at `/canvas` for an entity without a UiCanvas, and for one of `width` and `height` alone.
- **Parity:** the UI the editor shows (its game view, decision 7) is read by `ui.tree` and captured by `viewport.screenshot`; the method has its C++ round trip ("UiMethods: ...") and its Python tests (`Tests/Automation/test_ui.py`, the Runtime's included), and gate 5.

### 10. String tables (R-UI-L10N; stream L)

- **The type:** `AssetType::StringTable`, 12 on M22's branch (ADR 0028's phase-2 ledger: the first of M21 and M22 to land takes 12, the other 13, renumbering its own at its merge and rebuilding its checkouts' cooked caches), spelled `StringTable` in `.meta` files, the script API (`Field.Asset("StringTable")`) and automation. No placeholder table.
- **The file:** `.stringtable`, format `StringTable` version 1, canonical JSON written in full (§6), an authored extension (load and save byte-identical; `ModuleRules.json`'s `Json` list). The data (`Asset/StringTableData.h`): the registry structs `StringTable` (`StringTableData`: `Locales`, `Entries`) and `StringTableEntry` (`Key`, `Values` a Map from locale to string); the header's conventions are the rules: locales are 1 to 35-byte tags of ASCII letters, digits and '-' starting with a letter, unique ignoring ASCII case, the first the fallback; keys 1 to 256 bytes of UTF-8 without control characters, unique; values at most 16,384 bytes of UTF-8 (line feeds and tabs allowed); every entry has the fallback's value; at most 64 locales and 65,536 entries; `ValidateStringTable` reports one located issue per violation in document order.
- **Lookups** (`ResolveStringTableLocale`, `FindStringTableEntry`, `FindLocalizedString`): the table's locale equal to the requested one ignoring ASCII case, else the one equal to its language (before the first '-'), else the fallback; the entry's value for it, or the fallback's. Byte-wise, no locale database, deterministic.
- **The cooked format:** a binary payload, FormatVersion 1, little-endian (the header documents it byte for byte): the locales, then the entries **sorted by key** (so a loaded table binary-searches), each with a presence byte and string per locale. The reader checks every count against its limit and the bytes left, refuses a presence byte other than 0 or 1, entries out of order and trailing bytes, then validates. Its fuzz target, `StringTableData` (`Tests/Data/Fuzz/Targets.json`, added by the contract), mutates the document and the cooked form: the plan placed it in W22.3's stream E, but the reader lands in W22.1, and ADR 0028 decision 12 has a wave that adds a reader of external input run its fuzz case in its targeted unit run, so it moves to stream L (accepted by the lead, 2026-10-29).
- **The importer** (`AssetPipeline/Importers/StringTableImporter.h`): id `StringTable`, version 1, `.stringtable`, no settings, strict (an unknown member fails the import), one artifact, `Import.Dependencies` set explicitly to `GetStringTableDependencies` (none: a table references no asset; ADR 0028's ledger). Registered with its source format (`Asset/SourceFormats.cpp`, gate 9) and its loader (`RegisterBuiltinLoaders`); `ReadCookedArtifact` accepts the type. No validation code (a bad table fails its import).
- **Authoring:** `asset.create {type: StringTable, path, values?}` (`AssetCreateType::StringTable`, appended), `asset.getProperties` and `asset.setProperties` as for a sprite sheet (refusals located under `/values`); the content browser's Create popup gains "String table" after "Sprite sheet" (ADR 0028's ledger: the create list in landing order), which submits `asset.create` without values (a table with the locale "en" and no entries); tables show `EditorIcon::StringTable` (implemented by the contract). The reference generator documents the format (`FileFormats.md`, `Schemas/StringTable.schema.json`).
- **Export:** the exporter cooks every registered asset; M19's pruning follows `Import.Dependencies` and the literal `Assets.Load` scan, so a table a script loads by literal path is kept.

### 11. `Loc` and the locale setting (R-UI-L10N; stream L)

### 12. W-CLOCK: the same-frame input preview (stream K)

- **Acceptance** (Roadmap M22): "A frame that runs no step sees new input while the step view is unchanged."
- **`PlayInput`** (`Session/PlayInput.h`): `SetFramePreview(bool)` and `IsFramePreviewEnabled()` (off at creation). With the preview on, `LatchFrame` latches the frame view from the devices' state with the **device events** queued for `GetNextTick()` (`QueueDeviceEvent`'s, in queue order, as `ApplyTick` will apply them) applied on a preview copy; the step view, the applied state, the queue and the next `ApplyTick` are unchanged, and a previewed edge is reported once by the frame view (the frame after the tick that applies it sees no second press). Injected events (`Queue`: automation, replays, `Test.Inject*`) are never previewed: they belong to the tick that applies them.
- **The session's policy** (`PlaySession`'s LatchFrame phase): the preview is on only while the session is neither in lockstep nor recording, so lockstep, recording, replaying and test sessions latch exactly as before and every replay keeps its hash (a recording replays with the frame views its ticks gave). The policy, not the hosts, keeps the preview out of deterministic runs: a lockstep or recording session can still receive device input (the Runtime's window queues it in lockstep, the editor's Game view while recording), and the policy switches the preview off for both; replay and test sessions receive no device input (their hosts queue none while a replay or FeatureTest owns input). So the preview never touches a deterministic run. (Corrected by W22.1's review: this bullet first said that deterministic sessions receive no device input at all.)
- **The ledger:** LatchFrame changes in place (no PlaySessionPhase). Stream K amends Architecture §4.3 and §5.7's frame step 1, and W22.1's integration closes Backlog §5's row.

## Risks

1. **The draw list is laid out twice.** Extraction lays the UI out for each view and the session for its phases; both are the same pure function, so they agree at one scene resolution, and the hit test (W22.2) reads the session's. A view at another size (a screenshot) shows its own layout, which `ui.tree {width, height}` reproduces.
2. **Text without content sizing.** A label is not sized to its text (decision 6's limit): builders give text rectangles room; `ui.tree` reports each rectangle so an agent sees overflow, and W22.3's measurement layer can feed a later content-size rule without a signature change.
3. **Glyph runs and image runs interleave.** Painter's order splits the pass into a run per change of kind, so a UI that alternates panels and labels records one draw per element; UI element counts are small, and a run never reorders draws.
4. **The scene resolution with M21.** In W22.1 it is the view's size; the later lander of M21 and M22 wires PixelPerfectCamera's into the session's phases and extraction in one place (decision 3), checked by the combined test.
5. **AssetType values.** StringTable is 12 on M22's branch; if M21 lands first, M22 renumbers to 13 at its merge and rebuilds its checkouts' cooked caches (the values live only in cooked headers).
6. **The registered surface ahead of its implementation.** The contract registers components, `ui.tree` and `Loc` so the streams share stable references; until W22.1's integration the coverage gates name them uncovered, which no contract checkpoint runs.
7. **The edit VM's locale** rests on decision 17's amendment, granted on main (2026-10-29); stream L adds the initializer, and until it lands the edit evaluation reads each table's fallback, a difference only `script.eval {context: edit}` sees.
