# 0010 — M6 contract decisions

- **Status:** proposed by the M6 contract task; the streams implemented against decisions 1 to 30, the integration task (the contract owner) added decisions 31 to 37 for what changed after the freeze (Roadmap rule 3), and the milestone review's fixes added decision 38. The amendments listed at the end are for the docs owner.
- **Date:** 2026-10-07
- **Context:** The M6 contract task (Roadmap rule 3) froze the public headers of every M6 deliverable: `Engine/Source/Engine/Asset/`, `Engine/Source/Engine/AssetPipeline/`, `Renderer/GpuResourceCache.h`, `Scene/{PrefabAsset,EntityBounds}.h`, `Core/Aabb.h`, the M6 parts of `App/` and EditorCore (the asset commands, the `asset.*`, `prefab.*`, `project.refreshAssets` and `entity.bounds` methods), and the test support. It vendored MikkTSpace, wrote every Roadmap M6 acceptance test as a skipped skeleton (C++ and Python) and stubbed `Scripts/FetchAssets.py` and `Tests/Data/Generate/MakeGltfFixtures.py`. Writing complete headers exposed places where the Architecture and Roadmap are silent or cannot be followed literally. `AGENTS.md` ("Deviations") requires a record of each.

## Decisions

### 1. Module placement

- **`Asset` (layer 2: Core, Reflection, Platform)** holds everything the Runtime needs: the asset object model, references, metadata, diagnostics, the registry, the `AssetManager` interface, `IAssetLoader` and `AssetLoaderRegistry`, the cooked header and every payload codec (`MeshData`, `TextureData`, `MaterialData`, `FontData`, `DocumentData`, `EnvironmentData`), the pak read side (`PakFormat`, `PakReader`, `PakMount`), `RuntimeAssetManager`, the built-ins (`BuiltinAssets`, `BuiltinMeshes`, `BuiltinTextures`) and the inverted interfaces `IEnvironmentBaker` and `IScriptDiagnosticsProvider` (§3 rule 4).
- **`IAssetImporter.h` lives in `AssetPipeline`, beside `ImporterRegistry`.** §3 rule 4 puts the importer registry's interface in `Asset`, but an importer's input (`ImportContext`: the VFS, the registry, the dependency reads and lookups the cache records, the environment baker, the script checker) and output (`ImportResult`) are editor concepts, and only the editor and the tests ever import. The Roadmap's parallelization freezes `IAssetImporter.h` as its own header. Keeping it in `AssetPipeline` keeps importer settings types and the import vocabulary out of the Runtime entirely; nothing below layer 5 includes it. `Asset` keeps the loader side, which both managers share (§7.2 "One load path").
- **`AssetPipeline` (layer 5, ≤4, no other layer-5 module)** holds the importers, `EditorAssetManager`, `AssetCache`, `AssetDependencyGraph`, `AssetWriter`, `AssetHotReloader`, `EngineAssetBaker` and `PakWriter`. Its third-party code is private (`ModuleRules.json` notes): cgltf, stb_image and stb_image_resize2, `imstb_truetype.h` and MikkTSpace. The implementation translation units go under `AssetPipeline/ThirdParty/` (matched by the existing `files:**/Engine/*/ThirdParty/**.cpp` NoPCH filter, so no premake change is needed): `CgltfImplementation.cpp` (stream C), `StbImageResizeImplementation.cpp` and the `STBTT_STATIC` rasterizer translation unit (stream B). `Asset` may not include stb, so the stb_image_resize2 implementation that ADR 0009 decision 11 placed in `Asset/ThirdParty/StbImplementation.cpp` moves to `AssetPipeline/ThirdParty/`.
- **`Core/Aabb.h`** (implemented header-only by the contract): `MeshData::Bounds`, `EntityBounds` and later culling (§8.3) and physics share one box type. Only IEEE-exact operations, so results are configuration-independent (§4.12).
- **`Scene/PrefabAsset.h`** (load and instantiate a Prefab asset through `AssetManager`, always through `PrefabInstantiator`, §5.5) and **`Scene/EntityBounds.h`** (world AABBs for `entity.bounds`) are in Scene because both need the scene and the `AssetManager` interface, which Scene may include.

### 2. Asset object model

`Asset` is the base of every loaded asset: a protected non-virtual destructor and the asset's `AssetType`, with a `StaticType` per derived class. Handles and versions stay with the manager (`GetVersion`), so a reloaded asset is a new object and old references stay valid. Loaded assets are immutable and shared as `AssetRef<T> = Ref<const T>` (§4.7: `Ref` for shared immutable data). `AssetCast<T>` checks `StaticType` instead of RTTI (first-party code never uses `dynamic_cast` or `typeid`). The `AssetDataType` concept constrains the template helpers.

### 3. References

`AssetReference` (§7.1) has three spellings: 16 lowercase hex digits (a handle), a project path `"Assets/..."` with an optional `"#<sub-asset key>"`, and an engine path `"engine://..."`. `ParseAssetReference` and `FormatAssetReference` round-trip them; responses always expand to `AssetSummary {id, path, type}`, registered from M6 with the `AssetType` enum by `RegisterAutomationCommonTypes`, wherever a result names an asset (the `asset.*` and `prefab.*` results). Component data in results (`entity.get`, `entity.duplicate`, `scene.get`) keeps its `AssetRef` values as handles, exactly as files store them, so a result's components round-trip through `entity.update` and compare equal across calls; `asset.info` and `asset.list` expand those handles (decision 38).

### 4. The .meta formats (frozen)

`AssetMetadata.h` documents both formats with their key order: the asset meta (`Format`, `Version`, `Handle`, `Type`, `Importer`, `ImporterVersion`, `Settings`, `SubAssets` sorted by key) and the dependency meta (`Format`, `Version`, `Handle`, `Type: "Dependency"`, `Owner`). "Dependency" is a meta kind, not an `AssetType`: a dependency is never loaded or imported on its own and moves, is deleted and is trashed with its owner. Sub-asset handles are `Hash64(owner handle, key)` (`DeriveSubAssetHandle`), so a reimport keeps every handle while its keys are stable. The glTF key scheme is `"<kind>:<index>[:<name>]"` (decision 15). Settings are stored as a `VariantValue` of the importer's registered settings struct, every field present in registry order. **A dependency has exactly one owner:** an import that reads a file which is already another asset's dependency fails with `ImportFailed` naming the file and its owner (hint "give each glTF its own copy of the file"), so moving or trashing an owner never takes a file away from another asset. Files several glTFs share are standalone assets (an image with its own `Texture` meta), which glTFs reference by handle. The alternative, an `Owners` array, would have needed move and trash rules for partly shared closures and was rejected.

### 5. Asset diagnostics

`AssetDiagnostic.h` owns the asset codes: `ASSET_MISSING`, `ASSET_TYPE_MISMATCH`, `ASSET_IMPORT_FAILED`, `ASSET_ORPHAN_META`, `ASSET_DUPLICATE_HANDLE`, `ASSET_ORPHAN_DEPENDENCY`, `ASSET_TANGENTS_APPROXIMATED`, `ASSET_UNSUPPORTED_UV_SET`, `ASSET_VERTEX_COLORS_IGNORED`, `ASSET_CONTENT_SKIPPED` (new: glTF content the engine does not import, such as points and lines primitives, skins, animations, cameras and lights, reported as an import warning instead of a log line, so it persists in the cache manifest and reappears on cache hits), `PATH_CASE_MISMATCH` and the runtime-only `ASSET_UPLOAD_FAILED`. `ProjectValidator.h` includes it and reports the same constants (its own duplicate of `AssetImportFailedCode` was removed), adding `PREFAB_MISSING_ASSET`. An `AssetDiagnostic` carries severity, code, asset, path, message, hint, subject and `AutoFixable`, and converts to `ProjectDiagnostic` in the validator.

### 6. The registry plans, the editor applies

`AssetRegistry` is rebuilt by scanning `Assets/**.meta` (§7.3). Moves, trashing and scan fixes are **pure plans** (`PlanMove`, `PlanTrash`, `PlanFix` returning `AssetFileMove` lists and `AssetScanFix {AssignNewHandle, TrashMeta, RenameMetaToSourceCase, RewriteImporter}`), so the registry never writes. `RewriteImporter` fixes `ASSET_TYPE_MISMATCH` (§7.3's type/importer mismatch): the .meta is rewritten for the importer that takes the source's extension, keeping its handle, with that importer's default settings and no sub-assets (the next import lists them); `ProjectValidator::Fix` writes the complete defaults (decision 38). The editor applies a plan as `AssetMoveCommand`, `AssetDeleteCommand` or `AssetEditCommand` through `EditorContext::Execute` (undoable, attributed, provenance kept); `ProjectValidator::Fix` applies scan fixes inside its fix transaction. A case-only mismatch between a source and its meta is `PATH_CASE_MISMATCH`, fixed by renaming the meta to the source's case.

**The keeper rule for duplicated handles never depends on byte order**, because file managers name copies so that they sort before the original (`"Wood - Copy.png"`, `"Models - Copy/"`, `"Wood copy.png"`: a space sorts before `/` and `.`), and keeping the handle with the copy would silently retarget every reference. In `AssetRegistry::Scan`: (1) orphan metas never take part (a copied sidecar such as `"Wood.png - Copy.meta"` is `ASSET_ORPHAN_META`); (2) the path the registry already holds the handle at keeps it (Refresh and hot reload rescan the same registry, so a copy made while the project is open always loses); (3) otherwise the handle's last known location keeps it: the `EditorAssetManager` writes `AssetRegistry::GetKnownLocations` after each scan to the local, gitignored `<CacheRoot>/AssetLocations.json` and passes it to the next cold open's scan, so it never conflicts in merges; (4) otherwise the shortest source path, then byte order (copies append to the original's name).

### 7. The AssetManager interface

`AssetManager` (frozen) is abstract over `Load`, `LoadAsync` (a `JobHandle<AssetRef<Asset>>`), `GetState`, `GetMetadata`, `GetAssetType`, `Resolve`, `GetReferencePath` and `WaitIdle`, with shared, implemented behaviour in the base class:

- **Placeholders** (§7.2 failure policy): `GetOrPlaceholder<T>(handle)` returns the asset, or the type's placeholder (`GetPlaceholderHandle`: the unit Cube mesh, the Missing checker texture, the Error material, the Default font) and records the failure. The base serves procedural built-ins itself (`GetProceduralBuiltin`), so both managers have placeholders without a cache or a pak.
- **Diagnostics:** `ReportDiagnostic` stores and logs each (handle, code) **once** ("AssetManager: missing texture yields the Missing placeholder and logs once"); `GetDiagnostics` and `HasErrorDiagnostics` read them; the editor's scan diagnostics are merged in through `SetScanDiagnostics`.
- **Versions:** `GetVersion(handle)` starts at 1 and `BumpVersion` increments it on every hot-reload swap, so GPU mirrors and material binding sets know to rebuild (§7.5, §8.14).
- **Diagnostic lifetimes:** `ASSET_MISSING` and `ASSET_TYPE_MISMATCH` recorded by `GetOrPlaceholder` are reference diagnostics: they report a use that failed, so they never count for `HasErrorDiagnostics` (play and export check the current references through `ProjectValidator` instead), `ASSET_MISSING` of a handle is cleared as soon as the handle is registered or loads (the undo of a delete), and `ASSET_TYPE_MISMATCH` at the next registry scan. `HasErrorDiagnostics` counts asset-state errors only (`ASSET_IMPORT_FAILED` and the scan's errors; not the runtime-only `ASSET_UPLOAD_FAILED`). A handle's diagnostics go when it is unregistered. Recording them forever would have blocked play and export after a transient problem until the editor restarted.
- **Failures are remembered:** after a failed load or reimport, `Load` returns the last good version (state Loaded) or the recorded error (state Failed) without importing again until the source, a dependency file, the settings or the importer changes, so per-frame lookups and batches never re-import a broken source.
- **Dry runs:** the protected `SaveSharedState` and `RestoreSharedState` copy and restore the versions, diagnostics and logged-once set, so `EditorAssetManager::EndDryRun` restores even versions, which otherwise only grow.

Main thread, except that loads decode on jobs. `EngineContext::SetAssetManager` injects the manager (a documented back-reference); engine code below `AssetPipeline` sees only this interface.

### 8. Cooked artifacts (frozen)

Every cooked artifact (project cache, engine cooked cache, pak entries) starts with the 32-byte little-endian `CookedHeader` (`CookedFormat.h`: magic `ECKD`, the payload's format version, the asset type, the producing importer's version, reserved flags that must be 0, the payload size and the payload's XXH64), validated by `ReadCookedArtifact` before any payload byte is parsed. `EngineCookVersion` (1) is not in the header but in every cache key (decision 12): bumping it rebuilds every cache entry. Payloads are read only through `BinaryReader`. Each payload's layout is documented beside its data type: `MeshData` (48-byte `MeshVertex`, submeshes, material slots, bounds; format version 1), `TextureData` (`RGBA8Unorm`, `RGBA8Srgb`, `R8Unorm`, full mip chains up to 16384 texels), `FontData` (SDF atlas, glyphs, kerning), `MaterialData` and `DocumentData`. The binary readers (the cooked header, mesh, texture and font payloads, the pak) each have a seeded 10,000-mutation test (§15.2); material and document payloads are canonical JSON, read through `JsonReader`. Block compression is not part of M6; a new texture format bumps the texture payload's format version.

### 9. Materials and documents

`MaterialData` is the reflected struct `"Material"` (with `AlphaMode`); `.material` files are its canonical JSON (`Format`, `Version`, then the registry fields), read through the registry: missing keys keep their defaults, unknown keys warn into a `MaterialLoadReport`, and wrong types or out-of-range values are located Validation errors. The cooked material is the minified canonical document, read strictly (`CookMaterial`, `LoadCookedMaterial`). Scenes and prefabs are cooked as their canonical JSON documents (`CookDocument`) and loaded as `Ref<const Json>` (`SceneData`, `PrefabData`), so the Runtime deserializes them with the same `SceneSerializer` as the editor. `EnvironmentData` (cube map plus SH9) is declared for `IEnvironmentBaker`; its cooked payload arrives with M8.

### 10. Importers

`IAssetImporter` declares `GetId`, `GetVersion`, `GetMainType`, `GetExtensions`, `GetSettingsTypeName`, `RequiresMainThread`, `ListDependencyFiles` and `Import(ImportContext&, const AssetMetadata&) const`. The built-in ids are `Texture`, `Material`, `Scene`, `Prefab`, `Font` and `Gltf`, each with a static `Id` and `Version`. `ImportContext::ReadDependency` and `FindAsset` record every dependency read (path, XXH64) and every registry lookup; they are non-const members and the importer receives the context by non-const reference (no `mutable` members, CodeStyle §6). The cache manifest stores the records (decision 12) and the `EditorAssetManager` turns external reads into dependency metas. `ReadDependency` accepts any path under the source scheme's asset root (`project://Assets`, or `engine://` for built-ins), so M13's `ScriptImporter` can record required modules anywhere under `Assets/`; importers add stricter rules (glTF URIs stay inside the source's directory tree, decision 15). `IScriptDiagnosticsProvider` reads required modules only through an `IScriptModuleReader` that `ScriptImporter` routes through `ReadDependency` (never a raw VFS), so a cached script is re-checked when a module it requires changes (§7.5). `ListDependencyFiles` lists a source's dependency closure without importing (decision 11). `SceneImporter` returns `RequiresMainThread` true: its scratch scene is an ECS registry, which jobs never touch (§4.11); `Prefab::FromJson` needs no scene, so `PrefabImporter` runs on jobs. `ImportResult` holds the artifacts (main first, then sub-assets by key), the dependencies (handles) and the diagnostics. Importers are deterministic: "Importers: importing twice gives identical hashes" sweeps every importer over every fixture.

### 11. The EditorAssetManager and the EditorContext

`EditorContext` owns the `ImporterRegistry`, the `AssetLoaderRegistry` and one `EditorAssetManager` for the editor's lifetime and injects the manager into the engine context. `OpenProject` and `CloseProject` open and close the project's assets (scan, metas for new sources, hot reload); `Update(nowSeconds)` drives hot reload once per frame from `EditorApp::OnUpdate`. The project write path (`WriteProjectFile` and the new `MoveProjectFile`, `RemoveProjectFile` and `CreateProjectDirectory`) routes through the manager's `AssetWriter`. `EditorContextSpecification::EnvironmentBaker` is the Renderer's baker from M8 (null with `--renderer none`). Read-only editors register transient metas instead of writing them.

- **Metas for new sources are written in batches** (OpenProject's and Refresh's scans, one poll's changes, `asset.import`'s copy). Within a batch the manager first resolves the dependency closure of every new or changed source (`ListDependencyFiles`), then writes the metas (a source without a meta inside a closure gets a dependency meta, every other one its importer's meta), and only then starts the batch's imports, whose lookup snapshots include all of the batch's metas. A file that has a meta is never converted: an image that got a `Texture` meta in an earlier batch stays standalone and is reused by handle (§6.4). So a glTF's image is a dependency whether it arrives before, with or after the glTF in one batch, and the cache manifest of the glTF stays consistent across sessions. Writes through the `AssetWriter` never create metas themselves; a source written without one gets it at the next Refresh.
- **Provenance for the manager's own writes:** `EditorAssetManager::SetWriteObserver` reports every `AssetWriter` event (with `AssetWriteEvent::ContentHash` for writes) after the manager processed it, including the metas it writes for new sources, dependency metas and sub-asset rewrites; `EditorContext` records or removes provenance with the current attribution (never during a dry run or read-only), so §13.12 rule 1 holds for files automation produced indirectly.
- **Overlapping imports of one handle** are allowed; tickets decide which completion is published (race rule 2) and the manager serializes the cache stores of one handle (`AssetCache`'s precondition), storing only current completions.
- **Path dependents:** `GetPathDependents(handle)` lists the assets whose last import found `handle` by path (a glTF reusing a standalone texture); `asset.move` refuses to move such an asset and `asset.delete` warns (decision 19).
- **Prefab updates (§5.5):** `EditorContext::UpdatePrefabInstances` rebuilds instances from the current prefab versions through `PrefabInstantiator` (overrides, user children and root IDs kept) and `CreatePrefabUpdateCommand` wraps it as an undoable `SceneEditCommand`. Every editor action that gives an instanced prefab a new version composes it with the asset command into one undo step (`prefab.apply`; `asset.setImportSettings` and `asset.reimport` of an instanced glTF, whose import then runs before the method returns). External changes raise `SceneChangedOnDisk`; `scene.open` (reload included) rebuilds the loaded scene's instances from the current prefab versions, so adopting the disk version adopts changed prefabs too (the scene opens dirty when that changed it).

### 12. The project cache

Key: `XXH64(source bytes ‖ importer id ‖ importer version ‖ canonical settings JSON ‖ engine cook version)`, each part framed by its 8-byte length (`AssetCache::ComputeKey`). Layout: `<root>/<artifact handle>/<key>.bin` and `<root>/<source handle>/<key>.import` (the manifest), handles and keys as 16 hex digits. The source's dependency files are not part of the key (it is computed before the import knows them); a hit is valid only while every recorded read still hashes the same and every lookup finds the same asset (`IsManifestCurrent`). A corrupted or incomplete entry is discarded and rebuilt, never trusted. Storing a newer key removes the source's older entries. The manifest member holding the import is `CachedImport::Import` (not `Result`, which would hide `Engine::Result<T>` in the struct's scope). The project cache's root also holds the manager's `AssetLocations.json` (decision 6), which the cache's own calls never touch.

### 13. Engine resources and the engine cooked cache

- **`EngineContextStep::EngineResources`** follows `UserData`: it mounts `engine://` read-only at `EngineContextSpecification::EngineResourcesDirectory` and `enginecache://` read-write at `EngineCacheDirectory`, each when set. `ApplicationSpecification` carries both through. Development builds of the editor pass `<repo>/Resources` and `<repo>/bin/EngineCache`, or the directory of the editor option `--engine-cache-dir <dir>`; exported games mount `Engine.pak` instead (M7). Unset directories mount nothing, so in-process tests and logic-only processes are unaffected, and the editor processes tests start pass `--engine-cache-dir` with a per-test temporary directory (the C++ `RunEditor` of `EditorAppTests.cpp` and the Python harness), so no test writes the checkout's cache (decision 38).
- **`Resources/EngineAssets.json`** names every built-in (format documented in `BuiltinAssets.h`): `Handle`, `Path`, `Type`, `Source` and every member of each entry: `File` and `Importer` (for `File` entries), `Settings` (an object merged over the importer's defaults, `{}` for the defaults; §8.6's `ClampLuminance` for the sun-heavy Sky HDRI needs it) and `Generator` (for `Generated` entries). The three sources: `Procedural` (generated by the Asset module in code, never cached), `File` (a file under `Resources/`, cooked by an importer with the entry's settings) and `Generated` (generated in code by a module above Asset through an `EngineAssetGenerator`: §8.4's blue noise, `Renderer/BlueNoise.cpp`, run by the bake into the engine cooked cache, which Asset could not call as a procedural built-in). "BuiltinAssets: EngineAssets.json names exactly the compiled-in handles" keeps the file and the constants in step.
- **`EngineAssetBaker`** cooks the `File` and `Generated` entries with the project cache's keys into `enginecache://` (`BakeEngineAssets`, and `GetOrBakeEngineAsset` on first use, which logs a bake it cannot store at Warn and still serves it: the cache is shared by every process of the checkout, and on Windows replacing an entry fails while another process reads it). A `File` entry's key uses the complete merged settings; a `Generated` entry's key uses the generator's id and version. `EngineBakeSpecification::Generators` and `EditorAssetManagerSpecification::EngineAssetGenerators` carry the generators (empty until M8 registers the Renderer's). `Editor --headless --bake-engine-assets` fills it and exits (0 when every entry is baked or current, 1 when a bake failed); entries whose importer or generator this build lacks (the HDRIs until M8's `EnvironmentImporter`) are skipped with a warning. The option joins `EditorCommandLine` (one-shot, exclusive with `--batch`, `--upgrade`, `--dump-reference` and `--automation`); CI.py's bake stage runs it after the build (§15.8).

### 14. Built-in handles (frozen)

Within §4.8's reserved range (`FirstBuiltinAssetHandle` to `LastBuiltinAssetHandle`): meshes `0x101` Cube to `0x107` Cone (Cube, Sphere, Plane, Quad, Cylinder, Capsule, Cone; centred, 1 m across, the capsule 2 m tall); materials `0x141` Default and `0x142` Error; textures `0x181` White, `0x182` Black, `0x183` FlatNormal, `0x184` Checker, `0x185` Missing; font `0x1c1` Default (Inter, SDF); environments `0x201` Studio and `0x202` Sky. Reserved for later milestones: `0x186` blue noise (M8, a `Generated` entry, generator `"BlueNoise"`) and `0x241`–`0x24a` the synthesized sound effects (M12). Procedural built-ins are generated deterministically in code and never fail; `File` built-ins come from `Resources/` through the engine cooked cache.

### 15. glTF import

`GltfImporter.h` documents the output and the rules: a Prefab mirroring the default scene's node hierarchy with stable prefab-local IDs, sub-asset keys `mesh:<i>[:<name>]`, `material:<i>[:<name>]`, `texture:<image>[:linear|:normal]`, MikkTSpace tangents when `TANGENT` is missing (`ASSET_TANGENTS_APPROXIMATED` without `TEXCOORD_0`), `ASSET_UNSUPPORTED_UV_SET` for `TEXCOORD_1`, `ASSET_VERTEX_COLORS_IGNORED` for `COLOR_0` and `ASSET_CONTENT_SKIPPED` for skipped content, URIs that escape rejected naming the URI as written, required extensions other than `KHR_materials_emissive_strength`, `KHR_texture_transform` and `KHR_mesh_quantization` rejected naming the extension, and an image with its own Texture meta referenced by its standalone handle instead of imported again. `ListExternalUris` gives `asset.import` the dependency closure to copy.

- **One URI rule, after decoding:** a URI starting with `data:` is a data URI; every other URI is percent-decoded once (a malformed escape or `%00` is rejected, the result must be valid UTF-8 without control characters) and must then be a relative path inside the source's directory tree: no backslash, no `:` anywhere (drive letters and schemes), no leading `/`, no empty, `.` or `..` segment. `Import`, `ListExternalUris` (which returns exactly these decoded paths), `ListDependencyFiles` and `asset.import` share it, so `"%2e%2e/Outside.bin"`, `"..%5COutside.bin"` and `"%2FModels/Box.bin"` are rejected like their literal forms (fixtures `Encoded*.gltf`), and `"Encoded%20Data/Box.bin"` names `"Encoded Data/Box.bin"`. `asset.import` also refuses symbolic links, reparse points and closure files whose canonical path leaves the source's directory, so no file outside it is ever read.
- **`Scale` is baked into the imported data** (vertex positions, node translations, submesh and mesh bounds; normals, tangents, rotations and node scales unchanged), never into the prefab root's `Transform`, which every instance overrides implicitly (§5.5): a changed `Scale` then reaches placed instances through the prefab update of decision 11.

### 16. MikkTSpace

Vendored at commit `3e895b49d05ea07e4c2133156cfa94369e19e409` (zlib-style license; approved in M0, pinned and checksummed in `Vendor/MikkTSpace/VENDOR.md`; the approvals table points there) as a C static library built with the precise floating-point model, like Jolt. `CheckBuildConfig.py` checks the FP flags of the precise vendor projects (`PRECISE_VENDOR_PROJECTS`) and has a seeded fixture (`Tests/Data/BuildConfig/FastMathMikkTSpace`). Only `AssetPipeline/Private/TangentGenerator.cpp` may include it (`ModuleRules.json` `RestrictedThirdParty`). Every first-party project calls `UseMikkTSpace()`.

### 17. No-echo writes and hot reload

- **`AssetWriter`** (§7.5 race rule 1): atomic writes, moves, removals and directory creation that update the watcher's known state and notify the manager through a listener, which updates the registry and schedules the reimport itself; a dry-run mode writes into the overlay only. The `<file>.bak` that `project://` keeps of a replaced file (§4.10) is the write's too: `AssetWriter::Write` marks it known and reports it (`AssetWriteEvent::Backup`), and the manager records it as known, so neither a poll nor a refresh reports it. The old path of a case-only rename is recorded as absent (`PollingFileWatcher::MarkKnown` takes the case policy's mismatch for an absent spelling).
- **`AssetHotReloader`**: a `PollingFileWatcher` over `project://Assets` every 0.5 s (size and mtime, confirmed by content hash) with a 0.2 s debounce; reimports carry tickets whose generation is newer than every earlier ticket of the handle, and only the newest completion is published ("HotReload: a stale job completion is dropped"); `SetDeferred` holds changes while a deterministic session runs (race rule 4) and delivers them merged per path afterwards. Tests drive it through a `MemoryMount` and chosen times.
- **`SceneChangedOnDisk`** (race rule 3): an external change of the open scene's file, or of a prefab it instantiates, sets `EditorContext::IsSceneChangedOnDisk`, appends a `SceneChangedOnDisk` event and reports `sceneChangedOnDisk: true` in `_meta` (`MetaState::SceneChangedOnDisk`); the scene is never reloaded silently. Saving or opening a scene clears it.
- **Refresh takes the poll's path:** every external change `EditorAssetManager::Refresh` detects (`project.refreshAssets`, and the implicit refresh of every path-taking automation call) is marked known on the watcher, reaches the external-change listener once and is reimported and published once, so race rule 3 holds whichever observer sees a change first and no change is imported twice. A poll computes its changes on a job and delivers them at a later frame, possibly after a Refresh (or a deferral's end) processed the same change; the manager therefore drops every polled change whose state its known files already hold (size, time and content hash; a deletion it already saw). While reloads are deferred (race rule 4), Refresh registers new metas but holds the reimports (`AssetRefreshReport::Deferred`).

### 18. Asset edits write through

`AssetEditCommand` writes the new bytes when it executes and restores the previous bytes (or removes a created file) when undone, like `ProjectSettingsCommand`. There are therefore **no dirty native assets**: `project.save` saves only the open scene, and autosave covers only the scene (§3's autosave and §13.5's `project.save` mention dirty native assets; amendment below). Rationale: a file the editor has changed but not written would be invisible to the cache, the registry, hot reload and agents reading the project, and an undo stack that spans file writes needs the file to match the command history at every step.

### 19. Commands

`AssetEditCommand` (`AssetFileEdit {Path, Kind, Before, After}`; `CreateForWrite`, `CreateForWrites` for several files in one step), `AssetMoveCommand` (an `AssetRegistry::PlanMove`; the meta and dependency metas move with the source; refused with `InvalidState` naming them when another asset found the asset by path, decision 11, since a glTF's URI would break) and `AssetDeleteCommand` (an `AssetRegistry::PlanTrash` into `project://Library/Trash/<handle>`, or the first free `-<n>` variant; undo moves everything back; a warning names the assets that found it by path). Both record the folders their Execute created and their Undo removes them while empty, deepest first, so Execute then Undo restores the exact prior state and Redo the state after Execute (§12.3). Every effect goes through the context's write path, so provenance follows (`ProvenanceRecorder::Remove` joins for moves into the trash and undone creations).

### 20. Methods

- **`asset.*` (eleven, `AssetMethods.h`)**, **`prefab.*` (five, `PrefabMethods.h`)**, **`project.refreshAssets`** (`ProjectMethods.h`; a synchronous rescan, metas for new sources and reimports, complete when the call returns) and **`entity.bounds`** (`EntityMethods.h`; moved here from M4 by the Roadmap). Params and results are frozen registry structs; flags (tools, `Mutates`, `SupportsDryRun`, `AllowedInBatch`, launcher availability) are documented above each `Register*Methods`.
- **`asset.import` and `asset.reimport` are pending operations** (they wait for an import job), so they are not `AllowedInBatch`; `asset.import` copies the source and its dependency closure into `destDir` as one `AssetEditCommand` before importing.

- **Every call that takes a path refreshes the registry first** (§7.3), so a just-written file never races the watcher.
- **Registration lands with stream E.** The contract's `RegisterAssetMethods`, `RegisterPrefabMethods`, `RegisterAssetMethodTypes` and `RegisterPrefabMethodTypes` are stubs that register nothing, and `project.refreshAssets` and `entity.bounds` are not registered yet, so the method catalogue, `Tools/MCP/catalog.json`, the reference dump and the coverage checks are unchanged until E registers them together with the catalogue update (as in M4).

### 21. Entity bounds

`ComputeEntityWorldBounds(entity, assets, {IncludeDescendants = true})`: each MeshRenderer mesh's local bounds transformed by its entity's world matrix (computed, so correct between TransformSystem updates) and merged; effectively disabled entities are skipped; `Visible` does not matter; a missing mesh counts with its placeholder's bounds. `entity.bounds` returns per entity `{entity, hasBounds, min, max, center, size}` (the vectors empty without bounds). Collider bounds are M11's.

### 22. The GPU resource cache

`GpuResourceCache` (Renderer) mirrors mesh and texture assets per (handle, version) through the M5 upload paths (`HostImageUpload` for textures, `CreateBuffer` plus one command list for meshes). A failed upload serves the placeholder's mirror and records `ASSET_UPLOAD_FAILED` once; this completes the M5 acceptance "oom-texture yields a placeholder plus diagnostic" that ADR 0009 decision 8 deferred to M6. `CollectStale` releases mirrors of old versions (and unused ones on request) through the device's deferred release. Materials and environments join in M8.

### 23. Paks (frozen layout)

`PakFormat.h` documents the layout: a 64-byte header (`ENGPAK01`, version, entry count, TOC offset, size and XXH64), 16-byte-aligned entries, and a canonical JSON TOC `{Format, Version, Entries, Metadata}` sorted by (Handle, Path). Entries are cooked assets (complete cooked artifacts) or plain files (`Type: "File"`, null handle: the SPIR-V of `Engine.pak`, M7), which `PakMount` serves read-only. The TOC hash is verified at open and each entry's hash on its first read in every configuration. `PakWriter` is deterministic ("Pak: writer is deterministic"). `RuntimeAssetManager` serves the paks added at startup; versions stay 1 (no hot reload in an exported game).

## Integration (contract owner)

The integration task merged streams A to F and reviewed every request they sent (Roadmap rule 3: frozen headers change only with the contract owner's review). Decisions 31 to 37 record what changed after the freeze and why.

### 31. Frozen-header wording made exact

- **`EditorContext::OpenProject`** also opens the project's assets (`EditorAssetManager::OpenProject` on `project://Assets`, which is created first for a writable project); its errors join the documented list, and the project stays closed after one.
- **`TextureImporter`, `NormalMap`:** the generated mip levels are renormalized; level 0 keeps the authored texels. Renormalizing level 0 would requantize an author's 8-bit normals and change every normal map's bytes for no visible gain, while filtered levels are no longer unit length and need it. Architecture §7.4's "renormalized per mip" means the generated levels.
- **`GltfImporter`:** the importer supplies every buffer and image itself (the `.glb` binary chunk, data URIs, external files through `ImportContext::ReadDependency` after the URI rule), so cgltf parses from memory and never opens a file; the URI rule applies to the URI's JSON-decoded string (cgltf keeps escapes such as `"\/"` as written).
- **`EditorAssetManager::Refresh` imports new sources:** a refresh also imports every main asset its rescan registered that was never imported, and a poll's batch starts the same imports on jobs (published by the next `WaitIdle`, which `Refresh` calls first). A glTF's sub-assets exist in its `.meta` only after an import, so `asset.list {type: "mesh"}` after `project.refreshAssets` would otherwise miss a new model's meshes, and an agent learns of a broken new file from the refresh's diagnostics (`ProjectRefreshAssetsResult::Diagnostics`) instead of at its first use. Deferred reloads (race rule 4) hold these imports with the others. `OpenProject` stays lazy.
- **Asset diagnostics made from an `Error`** carry its hint only in `AssetDiagnostic::Hint`; the message is the error without its hint, so `AssetDiagnosticToString` prints the hint once.

### 32. Asset references in automation params (convention 13)

§7.1 and §13.4 let every `AssetRef` in params use a project path, a sub-asset path or an engine path, as §13.10's batch example does (`"Mesh": "engine://Meshes/Cube"`), but M4's protocol had no asset manager and read `AssetRef` values as handles only, so `entity.create` with a path failed InvalidParams. The protocol module (layer 1) cannot include `Asset`, so it gains an inverted interface:

- `IAssetReferenceResolver` (`Automation/Protocol/MethodContext.h`): `ResolveAssetReference(reference, assetTypeName)`; `MethodContext::GetAssetReferenceResolver` returns the host's (null by default, so hosts without assets are unchanged).
- `MethodRegistry::Invoke` rewrites every `AssetRef` value that is not 16 hex digits, anywhere in the params (component values and resolved `Variant` values included), to the handle the resolver gives, before the params are validated and read, and locates each failure at its value: a reference that names nothing is NotFound (as for asset params), a malformed one or an asset of another type is InvalidParams, any other resolver error keeps the host's code (InvalidState for a project path while no project is open, a refresh's Io) and outranks the others, and the handler does not run. A handle is kept as given and never reaches the resolver, so a handle of a missing asset is still accepted (§7.2's placeholder stands in). Resolving in `Invoke` rather than in `PrepareParams` means it runs after `AdmitRequest`, so the refresh a project path causes during a dry run stays in the dry run's sandbox, and the ops of `edit.batch` resolve through their nested contexts the same way. `MethodContext` befriends `MethodRegistry` so `Invoke` can store the resolved params, which handlers and `HasParam` then read.
- EditorCore's `AutomationServer` implements the resolver through `EditorAssetManager` (a project path refreshes first, §7.3; an engine path resolves without a project, a project path without one is InvalidState) and checks the asset's type against the field's (`TypeInfo::GetAssetTypeName`); every `EditorMethodContext` returns it (`AutomationServer::GetAssetReferenceResolver`).
- `Utils::ResolveAssetReference` (EditorCore `Automation/Private/AssetMethodSupport`) is the one resolution rule of asset params and asset references in values.
- The JSON Schemas that `rpc.discover` and `component.schema` publish give an `AssetRef` the pattern `^([0-9a-fA-F]{16}|Assets/.+|engine://.+)$` (an `EntityRef` keeps the handle pattern), so the advertised contract accepts what `Invoke` accepts; `SchemaValidator` supports both patterns.

Tests: "MethodRegistry: Invoke resolves asset references in params through the context's resolver", "EntityMethods: asset references in component values accept handles, project paths and engine paths" and "JsonSchema: an AssetRef accepts a handle, a project path or an engine path, an EntityRef only a handle".

### 33. Overrides are recorded when an edit commits (§5.5)

§5.5 says the change tracker records field-level overrides when an edit commits on an instance member; M3 and M4 never did, which was harmless while scenes stored expanded instances only. Since decision 11, `scene.open` rebuilds instances as prefab + recorded overrides, so a member edit that was saved but never recorded was lost at the next open (stream E's finding). `SceneEdit::Commit` now refreshes the override records of every instance whose root or linked members the edit touched (`ChangeTracker::NeedsSnapshot`; user children and nested instances do not count) against the prefab's current version (`PrefabInstantiator::RefreshOverrides`), while the tracker still runs, so the new records are part of the same undo step. An instance whose prefab is not registered keeps its records; one whose prefab cannot be loaded or diffed keeps them with a warning. Prefab operations (instantiate, update, revert, apply's override recording) diff against the version they just used, so the refresh changes nothing for them. Known limit: between an external change of a prefab and the scene's reload (`SceneChangedOnDisk`), the instance still holds the older prefab's values, and a member edit in that window records them as overrides; reloading first avoids it. Test: "PrefabMethods: an edit of an instance member is recorded as an override and survives reopening the scene".

### 36. Choices the streams made where the contract was silent (accepted)

- **A:** Refresh's change detection compares size and modification time with what the manager last saw and confirms with the content hash when it knows one, so a never-read file that is rewritten with the same bytes is reported once as Modified. After a failed import, a change anywhere in the source's folder subtree retries it (a missing dependency file leaves no recorded read). `ProjectValidator::GetCodes` lists 25 codes (the asset codes except the runtime-only `ASSET_UPLOAD_FAILED`, plus `PREFAB_MISSING_ASSET`).
- **B:** `TextureImporter` identifies the format by its signature and refuses GIF, PSD, PIC, PNM and Radiance HDR content whatever the extension; mips are made level by level with stb_image_resize2's box filter (in linear light with alpha weighting for `Color`). `FontImporter` validates the sfnt table structure before stb_truetype reads it, refuses font collections, and reads kerning with its own bounds-checked reader (the GPOS `kern` feature for `latn`, then `DFLT`, then all; lookup types 2 and 9; the legacy `kern` table as a fallback), because stb_truetype ignores extension lookups; the atlas holds ASCII and Latin-1 at 48 px with spread 8, shelf-packed in codepoint order into the smallest power-of-two square.
- **C:** sub-asset keys depend only on the source file, never on the existing `.meta`, so renaming a glTF mesh or material changes its handle; `MeshRenderer.Materials` stays empty and each mesh slot's default material points at the material sub-asset; `MergeMeshes` keeps the node entities without renderers and the root draws `mesh:merged`; node scale components below 1e-4 in magnitude are raised to 1e-4 (the `Transform` bounds); `GltfImportSettings::Scale` is limited to 0.0001–10000; `Import` reads only the images that imported materials bind, while `ListExternalUris` lists every external buffer and image.
- **D:** the pak TOC starts at the next 16-byte boundary and must end the pak; an empty entry may end the entry data; a `{}` TOC `Metadata` reads back as `{}`; a manifest lookup that found a dependency is written with `Type: "Dependency"` and no owner; the bake reports its warnings and errors under `ASSET_IMPORT_FAILED`; `RuntimeApp` logs one Info line with its pak and built-in counts; the bake runs without a renderer until M8.
- **E:** `AssetEditCommand` never creates a missing folder (callers add `Directory` entries, so undo removes exactly what was created); `asset.move` keeps the file extension; an unchanged patch writes nothing and reports `undoIndex` 0; `scene.open` refreshes before it rebuilds instances and, when a rebuild fails, opens the instances as saved with a warning; `prefab.apply` and `asset.setImportSettings` of an instanced prefab record the instances' overrides against the current version in the same undo step; `CreatePrefabUpdateCommand` returns a command built unapplied, so the history records the earlier revision; `asset.reimport`'s instance update is its own step after the import resolves.
- **F:** built-in geometry is computed in double with DetMath plus exact operations and rounded to float once, with the glTF tangent convention (every sign +1); built-in mips use a fixed 256-entry sRGB table; `FetchAssets.py defaults --check` verifies the committed files offline; `Sky`'s `ClampLuminance` waits for M8's `EnvironmentImporter` settings struct (its entry has `Settings: {}` until then); the `Inter-4.1.zip` pin is trust-on-first-download over HTTPS, since the release publishes no digest.

### 38. Fixes of the milestone review

The review of the integrated milestone found these; each fix has its regression test.

- **Hostile glTF accessors** (§7.4 "validation of index bounds"; ReviewChecklist §1: hostile input never crashes). cgltf_validate's size check wraps around for a huge count (`4 * (2^62 + 1)` is 4 in 64 bits) and then scans the indices far past the buffer, and a count without data made the importer allocate until `std::bad_alloc`. `GltfImport::CheckAccessors` runs before cgltf_validate: every buffer view must fit its buffer, every accessor (sparse indices and values included) must fit its buffer view, computed overflow-safely with the stride cgltf reads with, a sparse count may not exceed its accessor's, and an accessor without a buffer view may have at most 2^24 elements. Failures are ImportFailed naming `bufferViews[i]` or `accessors[i]`.
- **Cache hits read like fresh imports.** A manifest does not record a dependency lookup's owner, so an import served from the cache had lookups that never equalled the registry's entries, and every refresh reimported it. A cache hit now takes each lookup's entry from the snapshot `IsManifestCurrent` matched.
- **One publication per external change** (decision 17), **editor backups** and **case-only renames** are no external changes (decision 17); `AssetWriteEvent` gains `Backup`, and `PollingFileWatcher::MarkKnown` records an exact spelling that exists only under another case as absent.
- **`ASSET_TYPE_MISMATCH` is auto-fixable** (decision 6); `AssetImporterDescription` gains the importer's `Version` for the rewritten .meta.
- **Undo of moves and deletes** removes the folders they created (decision 19).
