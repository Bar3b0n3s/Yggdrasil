# 0014 — M11 contract decisions

- **Status:** proposed by the M11 contract task. The streams implement against decisions 1 to 20; the integration task (the contract owner) adds what changes after the freeze (Roadmap rule 3). The amendments listed at the end are for the docs owner.
- **Date:** 2026-10-08
- **Context:** The M11 contract task (Roadmap rule 3) froze the public interface of physics: the process-level `PhysicsEngine`, the ECS-agnostic `PhysicsWorld` with its shapes, layers, contact buffer, queries and character controller (`Engine/Source/Engine/Physics/`), the play session's `PhysicsSystem` with the composition rules, the scene-level validation and collider visualization (`Engine/Source/Engine/Scene/`), `physics.bodyInfo` (`Engine/Source/Engine/Automation/Methods/`), the `PHYSICS_*` codes, and the hooks in `ProcessContext` and `PlaySession`. It wrote every Roadmap M11 acceptance test as a skipped skeleton (C++ and Python). M11 runs in parallel with M8 (Renderer I) and M12 (Audio), which the lead merges afterwards; several decisions below exist to keep that three-way merge easy. Writing complete headers exposed places where the Architecture and Roadmap are silent or cannot be followed literally; `AGENTS.md` ("Deviations") requires a record of each.

## Decisions

### 1. The physics engine (process level)

- `Physics/PhysicsEngine.h`: static functions over Jolt's process-level state (§3 rule 5), in the pattern of `GlfwLibrary`. `Initialize(PhysicsEngineSpecification)` does §9.1's steps in order (default allocator, Trace and AssertFailed routed to the logger and the assert handler, `VerifyJoltVersionID` (fatal on failure), `Factory::sInstance`, `RegisterTypes`, one `JobSystemThreadPool(MaxPhysicsJobs 2048, MaxPhysicsBarriers 8, threads)`); `Shutdown` reverses it and asserts that no world and no body is alive (§4.1 "teardown asserts that every live-object counter is zero"; the counters are `GetLiveWorldCount` and `GetLiveBodyCount`).
- **Worker threads.** `PhysicsEngineSpecification::WorkerThreads` (nullopt: §4.11's `clamp(hardware concurrency - 2, 1, 4)`; 0 to 64 accepted). `SetWorkerThreadCount` (`JobSystemThreadPool::SetNumThreads`) changes it between steps; that is how "Physics: state hash identical with 0, 1 and 8 Jolt threads" runs three counts in one process. Results never depend on it (§9.1).
- **ProcessContext.** A new step `ProcessContextStep::Physics` between `CrashHandler` (whose assert handler Jolt's asserts report to) and `VulkanLoader`, configured by the new `ProcessContextSpecification::Physics`. §4.1 named this place; the frozen M2 enum gains the enumerator and `ProcessContextStepToString` its name. The contract wired the step and updated `ProcessContextTests.cpp` (the step list and the windowed child's log lines). Until stream A lands, `PhysicsEngine::Initialize` is a stub that succeeds without doing anything, so every process keeps starting.

### 2. Files, module placement and the physics vocabulary

- **`Physics` (layer 1, includes Core and Reflection; Jolt only in `.cpp` files and `Physics/Private/`):** `PhysicsTypes.h` (`BodyHandle` = Jolt's BodyID value, `PhysicsMotionType`, `PhysicsMotionQuality`, the `PhysicsDofs` flags, `PhysicsLayerMask`, `PhysicsPose`, `PhysicsWorldLimits`; header-only, complete), `PhysicsDiagnostics.h` (decision 9; header-only, complete), `PhysicsEngine.h|.cpp`, `PhysicsLayers.h|.cpp`, `PhysicsShape.h|.cpp`, `ContactBuffer.h|.cpp`, `PhysicsQueries.h` (data only), `PhysicsWorld.h|.cpp`, `PhysicsWorldQueries.cpp`, `CharacterController.h|.cpp`, `Private/PhysicsWorldState.h` (decision 17).
- **`Scene` (layer 3):** `PhysicsComposition.h|.cpp`, `PhysicsSystem.h|.cpp` with `PhysicsSystemQueries.cpp` and `PhysicsSystemCharacters.cpp`, `PhysicsValidation.h|.cpp`, `ColliderDebugDraw.h|.cpp`, `Private/PhysicsSystemState.h`.
- **`Automation/Methods` (layer 5):** `PhysicsMethods.h|.cpp` (decision 18): its own domain file, so M12's `audio.stats` in the observe domain and M11's method never edit the same file.
- **Physics cannot include `Asset` or `Project`** (layer 1). Its API takes mesh geometry as vertex and index arrays (`MeshShapeGeometry`, `ConvexHullShapeGeometry`) and layers as names (`PhysicsLayerTable::Create`); Scene converts `MeshData` (§3 rule 2 "Physics reads MeshData from Asset" is realized by Scene handing the data over). **Scene cannot include `Project`** (§3): `PhysicsSystemSpecification` copies `PhysicsSettings`' members, and `PlaySession` fills them.
- Physics has its own enums (`PhysicsMotionType`, `PhysicsMotionQuality`), as `RenderSnapshot` does (ADR 0012 decision 6): it cannot include Scene's `BodyType`.
- No premake, `Dependencies.lua` or `ModuleRules.json` change was needed: the globs pick the new files up, Jolt was linked into every project since M0, and every new include edge was already allowed.

### 3. The physics world

`PhysicsWorld.h` follows §9.1's list in engine types, with these refinements:

- `CreateBody(BodyDescription) -> Result<BodyHandle>`; `BodyDescription` is §9.2's "Body settings" (`Shape`, `MotionType`, `Pose`, `Layer`, `IsSensor`, `CollideKinematicVsNonDynamic`, motion quality, `AllowedDofs`, mass, friction, restitution, damping, gravity factor, maximum velocities, sleeping, `EnhancedInternalEdgeRemoval`, initial velocities, 64-bit `UserData`, `CollisionGroup`). The world itself refuses what Jolt must not see (decision 9): a Dynamic sensor, a Dynamic body without a degree of freedom, a Dynamic body whose shape holds a mesh, non-finite values, a full world; so even a caller that forgets a check cannot reach a Jolt assert.
- **Settings Jolt asserts on are made safe, not refused**, because they are valid content: `AllowedDofs` and `Mass` act on Dynamic bodies only (a Kinematic body gets `PhysicsDofs::All` and fixed mass properties, `MassAndInertiaProvided` 1 kg with a unit sphere's inertia, never its shape's: `MeshShape` has no mass and Jolt asserts "Invalid mass" and "Can't lock all axes" otherwise, so Kinematic mesh bodies and implicit mesh triggers work); starting velocities are clamped to the maxima, as `BodyInterface::SetLinearVelocity` clamps (Jolt asserts on a longer starting velocity); `SetShape` keeps a Dynamic body's `Mass` (inertia recomputed from the new shape and scaled to it) and never recomputes another body's mass from its shape. Jolt has no mesh-versus-mesh collision and asserts on such a pair, which a mesh sensor and a Kinematic mesh body could form (sensors detect kinematic bodies): the world's filters drop pairs whose shapes both hold a mesh before the narrow phase.
- **`CollisionGroup`** (64 bits, 0 = none): bodies of the same non-zero group never collide and never report each other (a Jolt `GroupFilter` the world installs, mapping the 64-bit value to Jolt's group IDs; queries are not affected). `PhysicsSystem` gives each body its plan's group (decision 10), so a trigger attached to a moving ball or a character never reports its own body or character; adding the member later would have changed a frozen header.
- §9.1's `SetPose` and the pose getter are `SetPose(body, pose, activate)` and `GetPose`; `IsBodyValid`, `GetUserData`, `GetMotionType`, `IsSensor`, `GetLayer`, `GetShape`, `SetShape` (a compound rebuilt in place), `GetStats`, `GetLayers`, `GetLimits` and `GetContactBuffer` (for the character listener) are added.
- **The void mutators** (forces, velocities, `MoveKinematic`, `SetPose`, `DestroyBody`) assert on a dead handle or a wrong motion type and ignore the call: callers validate external input first (`PhysicsSystem` returns `Result`s for every such case, decision 13), so an assert is never the only guard (§4.5).
- **`Step(deltaTime, collisionSteps)`** takes the collision step count explicitly. §9.3's `max(1, ceil(fixedDt × 60))` is computed by `PhysicsSystem` in integers as `max(1, ceil(60 / FixedHz))`: `1.0 / 60 * 60` need not round to exactly 1 in floating point, and an extra collision step would change results.
- `DrainContactEvents` returns the records unsorted; sorting is the consumer's (decision 12).

### 4. Layers and filters

- **16 layers, as §9.2 says.** ADR 0006 decision 11 allowed 1 to 32 layers in `PhysicsSettings` "where §6.1 gives none", without noticing §9.2's "up to 16 named project layers". The contract brings the settings validator in line (`ProjectSettings.cpp`: 16, its field description and header comment; `ProjectSettingsTests.cpp` checks that 16 are accepted and 17 refused, and a `static_assert` ties the two limits together, since Project cannot include Physics). Without this a project with 17 to 32 layers would load and then fail to play. This amends ADR 0006 decision 11.
- Object layer `(layerIndex << 2) | kind` and the three broad-phase layers (`PhysicsLayers.h`, complete in the contract); the kind rule `PhysicsObjectKindsCollide` excludes Static–Static, Sensor–Static and Sensor–Sensor (§9.2). `PhysicsLayerTable` holds the names and the symmetric 16 × 16 matrix and answers the two Jolt filter questions; the three Jolt filter classes live in `Physics/Private/` (stream A).
- **Masks** are `uint32_t` (`PhysicsLayerMask`), the width Luau's `bit32` works in (M13's `Physics.LayerMask`); bits at or above the layer count select nothing. `MakeMask` reports an unknown name as NotFound with a "did you mean" hint.
- `PhysicsLayerTable`'s default constructor (one layer "Default" colliding with itself, `PhysicsSettings`' defaults) is implemented by the contract, because every specification that holds a table default-constructs one.

### 5. Shapes

- `PhysicsShape` is an immutable pimpl over `JPH::RefConst<JPH::Shape>`, shared as `Ref<const PhysicsShape>` by bodies and, through `SharedShapeGeometry`, by the compounds that place a cached mesh shape (§9.2 "Mesh shapes are cached per (mesh handle, version, scale)"); §4.7 allows `Ref` for shared immutable data, and the Jolt reference lives inside it, never wrapped itself.
- `BodyShapeDescription` lists `ColliderShapeDescription`s: geometry (box, sphere, capsule along Y, convex hull of points, triangle mesh, or `SharedShapeGeometry`: an already built one-collider `PhysicsShape`), `Scale` in the collider's own axes, then `Rotation` and `Position` within the body (Jolt's `RotatedTranslatedShape`), and `UserData` (the collider index of §9.2). One collider is its own shape; several form a `StaticCompoundShape`. Without `SharedShapeGeometry`, a body's shape could only be described as raw geometry, so every compound rebuild would rebuild every mesh BVH and the cache §9.2 requires could not exist.
- **Collider identity.** A collider's index is the compound's sub-shape user data (`CompoundShapeSettings::AddShape(..., userData)`), resolved from a `SubShapeID` by its first level (`GetSubShapeIndexFromID`, then `GetCompoundUserData`); a one-collider shape reports its collider's `UserData` for every hit. §9.2's "resolve a `SubShapeID` through `Body::GetShape()->GetSubShapeUserData()`" cannot work with shared leaves: Jolt returns the leaf shape's own user data there, not the compound's (Jolt `CompoundShape.h`), so colliders sharing a cached mesh would be indistinguishable.
- `Create` checks everything before Jolt (finite, positive dimensions, unit rotations, non-zero scales, indices in range, `IsValidScale`) and turns a `ShapeResult` error into Validation `"PHYSICS_INVALID_SHAPE: collider <i>: <Jolt's text>"`. `IsValidScale` is a static function over the unscaled geometry.
- `PhysicsWorld` and `CharacterController` are friends of `PhysicsShape` to reach the Jolt shape through `Physics/Private/PhysicsWorldState.h`; the Jolt type never appears in a public header.

### 6. The contact buffer

`ContactEvent` carries the kind, both body handles as Jolt reported them, both raw `SubShapeID` values (the per-sub-shape reference count of §9.4 step 1 is keyed by them), and, for `Added` only, both collider indices (resolved as decision 5 says, while Jolt holds the bodies), the first contact point, the normal from A to B, the relative normal speed, `IsSensor` and `FromCharacter`. Removed records carry no user data: their bodies may already be gone when Jolt reports them. `Append` is the only call made from worker threads.

### 7. Queries

`PhysicsQueryFilter {Layers, IncludeSensors = true, IgnoreBody}`. §9.5 does not exclude sensors from queries, and a game can then ask whether a point lies inside a checkpoint; scene-level queries (`PhysicsSystem`) always include them (M13 may add an option with its bindings, with an ADR). World-level results are unordered; `PhysicsSystem` maps them to entities and sorts by distance, then collider UUID (overlaps by collider UUID, each collider once).

### 8. The character controller

- `CharacterController::Create(world, description)` makes the `CharacterVirtual`, its inner body (§9.6: a kinematic capsule of the controller's size on its layer, with the entity's UUID as user data) and its `CharacterContactListener` over the world's buffer. `CharacterControllerDescription::CollisionGroup` is the inner body's group, and `Update`'s body filter ignores the inner body and every body of that group, so the triggers attached below a character (decision 10) never report it.
- **The inner body's ID.** The inner body is created as the world's next body at `Create`; `PhysicsSystem` creates characters in canonical order among the bodies (decision 10), so the inner body gets the same ID every run. Stream C may set `mInnerBodyIDOverride` to that ID explicitly; either way the ID comes from the canonical body-ID sequence (§9.6).
- **Conventions §9.6 leaves open:** the entity's origin is the character's base (the bottom of its capsule); `Height > 2 × Radius` (else `PHYSICS_INVALID_SHAPE`); a step's velocity is the desired velocity's horizontal part plus, while grounded, the ground's vertical velocity and the desired vertical part (a jump), and in the air the previous vertical velocity plus gravity × `GravityFactor` × dt.
- **`Move` is consumed by one PreStep** (`PhysicsSystem::MoveCharacter`): a script moves its character by calling `Move` in every `OnFixedUpdate`, and a jump is one `Move` with an upward part. A sticky desired velocity would re-trigger a jump every grounded step.

### 9. Diagnostics

`PhysicsDiagnostics.h` defines the ten codes §13.7 lists, in its order, the `PhysicsDiagnostic` struct (code, severity, entity, component, field, message, hint, subject, auto-fixable, fix target) and `GetPhysicsDiagnosticCode(const Error&)`, which reads a `"<CODE>: "` prefix (the convention of `StructuralValidator`). Severity and run-time behaviour, where §9 and §13.7 leave them open:

| Code | Severity | At run time |
|---|---|---|
| `PHYSICS_NONCONVEX_DYNAMIC` | Error | body not created |
| `PHYSICS_MIXED_TRIGGER` | Error | body not created |
| `PHYSICS_DYNAMIC_TRIGGER` | Error | body not created (§9.1) |
| `PHYSICS_ALL_DOFS_LOCKED` | Error | body not created (§9.1) |
| `PHYSICS_INVALID_SHAPE` | Error | body not created (§9.1) |
| `PHYSICS_ADJACENT_STATIC_BODIES` | Warning, auto-fixable unless the common ancestor is missing or has trigger colliders of its own (decision 15) | simulated as authored (§5.3) |
| `PHYSICS_UNKNOWN_LAYER` | Error | body created on layer 0 "Default", so the scene still plays |
| `PHYSICS_NONUNIFORM_SCALE` | Warning | the largest axis is used (§9.2) |
| `PHYSICS_DYNAMIC_UNDER_MOVING_PARENT` | Warning | simulated in world space, not carried by the parent (§9.3); PostStep rewrites its local transform so the entity stays where the body is (decision 11) |
| `PHYSICS_LIMIT_EXCEEDED` | Error at a limit, Warning past 90 % of one | bodies beyond the body limit not created (§9.1) |

The play session logs each diagnostic once, at Error or Warn, as `"<CODE>: <message>"` with the entity's name and id (`PhysicsSystem::GetDiagnostics`), so `_meta` counts it and tests expect it with `Test::ExpectLog`, then passes it to `IPhysicsEventListener::OnPhysicsDiagnostic` (decision 12). "Script error at run time" for a refused body (§9.1) arrives with M13 through that callback.

### 10. The composition rules

`Scene/PhysicsComposition.h`: one pure function, `ComposePhysicsBodies(scene, layers, maxBodies)`, used by the session (to create bodies), the validator and the collider visualization, so the rules exist once. It returns one `PhysicsBodyPlan` per body (owner, origin, motion type, sensor flag, resolved layer, colliders in sub-shape order, creatable flag) and the composition's diagnostics; `DescribePhysicsBodyShape` turns a plan into a `BodyShapeDescription`. Where §5.3 is silent:

- **Implicit static bodies gather like a RigidBody:** the solid colliders of collider-only descendants below an entity that has no RigidBody above it join that entity's implicit static body; a tree of collider-only entities is one static compound, so `PHYSICS_ADJACENT_STATIC_BODIES` fires only between separate trees.
- **Implicit sensor bodies hold only their entity's own trigger colliders.**
- **Implicit bodies take the layer of the nearest ancestor RigidBody, else layer 0:** collider components have no layer field (§5.3), and a checkpoint under a level root then shares the track's layer.
- **A sensor RigidBody of Type Static is planned Kinematic** (a goal or kill zone authored that way): §9.2 creates triggers Kinematic and kept active so they also detect sleeping bodies, which a Jolt static sensor would not; it follows its entity through `MoveKinematic` like an implicit sensor body, and `physics.bodyInfo` reports its type as Kinematic.
- **A RigidBody without any collider** (a level root whose children are all triggers, a collider removed at run time) is listed, not creatable, without a diagnostic: Jolt needs a shape, and the body would collide with nothing.
- **Collision groups:** each plan's `CollisionGroup` is the nearest entity at or above its owner with a RigidBody or a CharacterController (the owner for RigidBody and Character bodies, the carrier of an implicit sensor body, none for implicit static bodies). §5.3 says "a trigger attached to a moving ball ... just works"; without the group, its implicit sensor body would overlap the ball (or a pickup radius the character's inner body) for its whole life and report its own owner.
- **The mesh shape cache:** `PhysicsMeshShapeCache` (in `PhysicsComposition.h`, stream B) builds each (mesh handle, version, convex, scale) once; `DescribePhysicsBodyShape(scene, plan, assets, meshShapes)` then describes mesh colliders as `SharedShapeGeometry` of the cached shape (Scale 1) instead of copied vertices. The session owns one cache and prunes it after rebuilds; the validator and the collider visualization pass none.
- **Characters:** a CharacterController's shape is its capsule; solid colliders on its entity and on collider-only descendants form no body. Trigger colliders there still get implicit sensor bodies (a pickup radius around the player).
- **Order:** bodies in canonical order of their owners (the solid body before the sensor body of one owner); a body's colliders are the owner's own in `BuiltinComponents` order, then each gathered descendant in canonical order. A collider's index in that order is its sub-shape user data.
- Effectively disabled entities make no bodies (§5.2).
- **§5.3's runtime components `PhysicsBodyRuntime` and `CharacterRuntime`** are realized as the system's private entries (`PhysicsBodyEntry`, `PhysicsCharacterEntry` in `Scene/Private/PhysicsSystemState.h`), keyed by body handle and owner UUID, not as EnTT components: nothing outside the system reads them. Stream B may add private tag components for EnTT's dirty marks.

### 11. The physics system

- One `PhysicsSystem` per play session, owned by it and created in `PlaySession::Create` after the scene loaded; `Create` builds every body and character in canonical order (§5.6 "Session setup"), so `physics.bodyInfo` and queries work at tick 0 and scripts' `OnCreate` (M13) can query.
- §5.7 steps 5 to 8 as the header documents: `PreStep` (rebuilds, pairs across rebuilds, `MoveKinematic` for Kinematic and implicit sensor bodies, teleports, character updates), `Step`, `PostStep` (write-back in canonical order, then drain, map, collapse, sort, dispatch), `FlushDestroyed` (synthesized exits, then body and character removal, repeated until nothing is left; called before `Scene::FlushPendingDestroys` in both flushes).
- **Rebuild triggers** beyond §9.2's "RigidBody, a collider or `Active`": a compound whose gathered collider moved relative to its body (a script moving a track piece), a hierarchy change above or below a collider, a world scale change of an owner or gathered collider (scale is baked in), the `MeshRenderer.Mesh` a mesh collider falls back to, and a new asset version of a collider's mesh (hot reload). Otherwise physics and rendering would silently disagree.
- **Rebuilds and their pairs.** A rebuild caused by colliders alone that keeps the motion type and sensor flag uses `PhysicsWorld::SetShape` (handle, pose, velocities and Jolt's contact bookkeeping kept); any other destroys and creates the body with its current velocities (the `Initial*` ones apply only to a body created for an owner that had none). Jolt reports no `OnContactRemoved` for a destroyed body, so pairs are keyed by owner UUIDs and kind: a destroyed body's pairs become unconfirmed, PreStep wakes the partners, and at PostStep a pair that no contact re-established ends with a synthesized exit; one that was re-established continues without a new enter. Entities disabled or destroyed in steps 3 and 4 keep their bodies until `FlushDestroyed`, as §5.7 step 8 says, so PreStep never removes them.
- **Exact teleport detection.** `WorldTransformComponent` is a matrix, so a pose decomposed from it differs in the last bits from the quaternion PostStep wrote; comparing it would teleport and wake every awake body each tick, and nothing would sleep. Dynamic bodies and characters therefore compare the owner's local `Translation` and `Rotation` bit for bit with the values PostStep wrote (round-trip exact; a moving parent then does not drag a Dynamic body, as `PHYSICS_DYNAMIC_UNDER_MOVING_PARENT` says), and Static bodies the world matrix bits with those they were created or last teleported at. PostStep writes back every Dynamic body that is active or has a parent, so the entity always shows where the body is.
- **Teleporting characters and kinematic bodies.** A character whose local values differ from the written ones is moved with `CharacterController::SetPose` before its update (§11.5 gives `CharacterController` no `Teleport`, and a respawn writes the Transform); a Kinematic body whose entity carries `InterpolationResetTag` at PreStep (teleported in steps 1 to 4) is placed with `SetPose` instead of swept by `MoveKinematic`, which would fling what rests on it.
- **The flush loop.** Callbacks dispatched by `FlushDestroyed` may destroy or disable more entities; the flush repeats its close, dispatch and remove pass until a pass finds nothing (each entity once, so bounded by the entity count), so no destroyed entity keeps its body or a stale "inside" state (§9.4). M13's `OnDestroy` joins that loop.
- The Architecture's step-6 `PhysicsWorld::Step` errors (full caches) become a `PHYSICS_LIMIT_EXCEEDED` diagnostic; the session keeps running.

### 12. Events and their dispatch (the interface M13 consumes)

- `IPhysicsEventListener::OnPhysicsEvent(const PhysicsEvent&)` receives one callback per entity of a body-pair event: `{Type, Self, Other, Contact {Point, Normal (from Self towards Other), RelativeSpeed, Collider, OtherCollider}, Synthesized, Tick}`. The system resolves both sides, so M13's dispatcher only finds the scripts on `Self` and calls `OnCollisionEnter(other, contact)` and the others (§9.4 step 4).
- Order: pair events sorted by (lower UUID, higher UUID, `PhysicsEventType`), each dispatched first to the lower UUID. Trigger events carry the colliders and a zero point.
- **Dropping (§9.4 step 3).** Events of a pair with an entity already pending destruction or disabled when the dispatch starts (destroyed in `OnFixedUpdate`, while its body still simulated) are not dispatched: an enter is dropped and the pair never becomes active, an exit is left to `FlushDestroyed`. A callback whose `Self` was destroyed or disabled by an earlier callback of the same dispatch is dropped, but its partner's callback is still delivered (its `Other` then invalid or inactive), and that partner gets its exit at the flush. A side that got the enter gets exactly one exit unless its own entity is destroyed or disabled first; a side that did not gets none.
- `OnPhysicsDiagnostic(diagnostic)` (empty by default) hears each run-time diagnostic once, in raise order: §9.1 requires a script error for a body refused at run time, and comparing the accumulated `GetDiagnostics` after every PreStep, or adding the virtual function in M13, would be worse.
- The listener may change the scene and call the system's body, character and query functions, never the step hooks; destroying an entity is deferred (§5.7) and its exits are synthesized at the flush ("Physics: destroy inside a contact callback is safe").
- `GetLastEvents` keeps the dispatched events of the last `PostStep` and the flushes since, for tests and observability before scripts exist.

### 13. Body control (the RigidBody and CharacterController script API, M13)

- Every function takes the owner's UUID and returns a `Result`: NotFound without a created body, InvalidArgument for non-finite values, InvalidState for the wrong motion type. Static bodies cannot take velocities; forces and impulses need Dynamic.
- **`MoveKinematic(entity, position, rotation)`** sets the entity's world pose (through its parent's inverse); the next `PreStep` moves the body there with `MoveKinematic` over the step (§9.3), so the entity's Transform stays the single source of a kinematic body's pose.
- **`Teleport`** sets the entity's world pose and the body's at once, tags the entity `InterpolationResetTag` (as `PlaySession::MarkTeleported`, which Scene cannot call) and keeps the velocity (§9.3; a respawn zeroes it separately).

### 14. The play session's hooks (small, delimited edits for the M12 merge)

- `PlaySession.h`: a forward declaration, the three physics phase comments, and one delimited block with `GetPhysics()` documenting everything else. `PlaySession.cpp`: one include, one helper (`MakePhysicsSpecification`), the `Physics` member (declared after the scene, destroyed before it), the creation in `Create`, the calls in the fixed step and the frame-phase flush, `GetPhysics`, and `AppendStateHash` in `ComputeStateHash`. The DestroyFlush and AudioUpdate comments are left alone for M12.
- The physics phases run in Play and Simulate alike (Simulate is Play without scripts and audio, §5.6). "Simulate mode wired into PlaySession/EditorPlayController" needs nothing else: the editor already starts Simulate sessions and views them through the scene-view camera (`EditorApp::ExtractViewportView`, M7).
- **State hash:** `AppendStateHash` appends, per created body and character in canonical order, the owner's UUID, the pose, both velocities (float bit patterns) and the sleeping flag, and nothing for a session without bodies, so the hashes of M7's physics-free scenes do not change (a real test checks the empty append).
- Until stream B lands, `PhysicsSystem::Create` returns an inert system without a world and the hooks do nothing, so M7's tests stay green.

### 15. Validation

- `Scene/PhysicsValidation.h`: `ValidateScenePhysics(scene, layers, assets)` is the composition's diagnostics plus `PHYSICS_INVALID_SHAPE` (it builds each creatable body's shape; characters' capsules included) and `PHYSICS_ADJACENT_STATIC_BODIES` (pairs of implicit static bodies whose world AABBs are within 1 mm, overlap included; one diagnostic per pair on the owner first in canonical order, `Subject` the other owner, `FixTarget` their nearest common ancestor; two roots have none and are not fixable). A common ancestor with trigger colliders of its own is not fixable either: the added RigidBody would gather the solid pieces with its triggers, and the composition would refuse the whole track with `PHYSICS_MIXED_TRIGGER` where it only warned before; the hint says to move the triggers to a child.
- **The project validator:** the contract added the ten codes to `ProjectValidator`'s code list after `PREFAB_MISSING_ASSET` (§13.7 order) and updated the count test, plus a real test of the position. Stream D calls `ValidateScenePhysics` from the scene checks (the layer table from the project's settings), maps each diagnostic (entity, component, field, subject into the id), and implements the fix of `PHYSICS_ADJACENT_STATIC_BODIES` in `FixOpenScene`: a `RigidBody {Type: Static}` added to the fix target, inside the one undoable fix command.
- Gate 6's fixtures (`Tests/Data/Validation/`) arrive with M14.

### 16. Collider debug draw and the render snapshot (the M8 seam)

- `Renderer/DebugDrawList.h` is M8's (§3, §8.10), written in parallel; M11 does not create it, so the merge has no add/add conflict. `Scene/ColliderDebugDraw.h` builds renderer-agnostic records in the DebugDrawList's vocabulary (Box, Sphere, Capsule, and Lines for mesh triangle edges), in world space, coloured by category (Static, Kinematic, Dynamic, Sleeping, Trigger, Character, Invalid), from the components and the composition rules, so edit scenes show exactly the bodies play will create and play sessions add the sleeping state.
- **After the M8 merge** (stream D in the integration): `AppendColliderDebugDraw(records, DebugDrawList&)` maps Box, Sphere and Capsule one to one and Lines to one `Line` per vertex pair, with the record's colour, duration 0 and `DepthMode::Tested`; render extraction calls it when the request asks for colliders (the flag M8's snapshot gains for `RenderViewFlags::Colliders`; the editor's `viewport.setOptions {colliders}` is M10's, `annotate.colliders` M9's). The M11 tests check the records, not pixels.

### 17. Frozen headers, private state, stubs

- As in M7 (ADR 0012 decision 17): stateful frozen classes keep their state behind `struct State; Scope<State> m_State;` (`PhysicsShape`, `PhysicsWorld`, `CharacterController`, `PhysicsSystem`); public and protected declarations are frozen, private members and `State` are not.
- **Initial private layouts:** `Physics/Private/PhysicsWorldState.h` (`PhysicsShape::State`, `PhysicsWorld::State`; stream A owns it, stream C adds its members in the marked section) and `Scene/Private/PhysicsSystemState.h` (`PhysicsSystem::State`, `PhysicsBodyEntry`, `PhysicsCharacterEntry`; stream B owns it, stream C adds its members in the marked section). They give the streams one place to share state from the start; they change without review.
- Every stub body starts with `ENGINE_CONTRACT_STUB();` and returns Unsupported or a neutral value; none can hang, open a device, start a thread, spawn a process or write a file. Two stubs return success on purpose, because the contract wired their callers: `PhysicsEngine::Initialize` (the ProcessContext step) and `PhysicsSystem::Create` (the play session).
- **What the contract implemented:** the header-only `PhysicsTypes.h`, `PhysicsDiagnostics.h`, the object-layer helpers of `PhysicsLayers.h` and `GetColliderDebugColor`; `PhysicsLayerTable`'s default constructor; `PhysicsBodyOriginToString` and `PhysicsEventTypeToString`; the ProcessContext step and the PlaySession wiring; the validator's code list; the 16-layer settings limit; `Tests/Source/Support/PhysicsTestScene.h|.cpp`.

### 18. physics.bodyInfo

- Wire format (`PhysicsMethods.h`): `{entity}` → `{entity, body, origin, type, isSensor, layer, colliders, position, rotation, linearVelocity, angularVelocity, sleeping, boundsMin, boundsMax, contacts: [{other, collider, otherCollider, isTrigger, sinceTick}], grounded, groundNormal, tick}`. `body` differs from `entity` for a collider gathered into an ancestor's compound. `type` uses the registered `BodyType` enum and is the body's motion type (Kinematic for a Static RigidBody whose colliders are triggers, decision 10); `origin` a new registry enum `PhysicsBodyOrigin`. Character fields are plain members (the registry has no optional fields, ADR 0006 decision 11).
- The system's struct is `PhysicsBodyReport` (`PhysicsSystem::GetBodyInfo`), not `PhysicsBodyInfo`: the handler `Automation::PhysicsBodyInfo` would hide a type of that name inside `namespace Automation` (MethodRegistry.h convention 1 renames for the same reason).
- It always reads the play session (bodies exist only there): InvalidState "not playing" in Edit mode, with the hint `play.start {mode: "simulate"}`; NotFound at `/entity` for an entity without a body.
- Read-only, `AllowedInBatch`, `AvailableInRuntime` (§13.5's Runtime subset); not a tool (§13.8 lists none for physics).
- As in M7 (ADR 0012 decision 13), `RegisterPhysicsMethodTypes` and `RegisterPhysicsMethods` are stubs that register nothing, wired by the contract in `RegisterSharedMethods.cpp`, so the catalogue and the coverage gate change only when stream D registers the method with its tests (and regenerates `Tools/MCP/catalog.json`).
