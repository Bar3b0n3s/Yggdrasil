## Context

- **The brief.** S01 (high priority, needed first) asks for:
  - a water body, an unbounded ocean or a bounded area, at a base height scripts change (the tide);
  - waves as a pure function of position and `Tick × FixedDelta`, a few directional Gerstner or sine waves the storm raises;
  - the look: depth colour, the bottom refracted through the shallows, reflections, the sun's glint, shore foam, detail normals, fog, a horizon at a fixed cost;
  - fixed-step queries (height, normal, velocity, under water) from scripts and physics;
  - floating, by a component or a documented script recipe;
  - an underwater view and the surface seen from below.
- **S05's grotto.** The Hollows' crystal grotto holds a lake 30 m under the plateau, today the sea's placeholder plane showing through the floor. A bounded water must work at any height, under rock, below the sea's level.

### 3. Design defaults: M47 Water

**What M47 adds:** two components in a new category; one enum and one struct; a wave function; a point rule; four proxy methods and one `Physics` function; one automation method; three validation codes; one snapshot member; two pass declarations (three rows, three pipelines, one program); two stats fields and one readout member; two built-in textures; three goldens; three perf metrics.

**What it does not add:** a namespace, a settings section, an `AssetType`, a `PlaySessionPhase`, a fuzz target, a state-hash block, a format version, a render stage, a module, a `ViewConstants` or `DrawConstants` member, a draw flag, an `IScriptHost` member, a callback or a vendored library.

- **`Water`, version 1, category Water** (`Scene/Registration/WaterRegistration.cpp`, `RegisterWaterComponents`; a new category appended after M46's `Wind`, the phase's last new category). Requires Transform; script-visible; several per scene.
  - `Shape`: `WaterShape` {`Ocean`, `Rectangle`}, default `Ocean`. An Ocean is unbounded in XZ and below; a Rectangle is a box in the entity's local XZ.
  - `Size`: vec2, default (20, 20), each in [0.1, 100000] (Rectangle; local units, scaled by the entity's world X and Z scale).
  - `Depth`: float, default 5, [0, 100000] m below the base (Rectangle). `Headroom`: float, default 10, [0, 100000] m above it (Rectangle).
  - `Waves`: array of `WaterWave`, at most `MaxWaterWaves` (8; refused past it on every write path, as Terrain's `Layers`). Empty is a calm surface. Each wave:
    - `Direction`: float, degrees about +Y in the entity's local XZ, finite;
    - `Wavelength`: [0.1, 2000] m, default 20;
    - `Amplitude`: [0, 20] m, default 0.2;
    - `Steepness`: [0, 1], default 0.5 (Gerstner's Q; 0 is a sine wave);
    - `Speed`: [0, 200] m/s, default 0, which takes deep-water dispersion `ω = sqrt(g k)`, g = 9.81 (`WaterGravity`);
    - `Phase`: degrees, default 0, finite.
  - `WaveScale`: [0, 10], default 1, multiplies every amplitude (the storm). `Current`: vec2, default 0, local XZ m/s, each in [-100, 100]. `Density`: [1, 20000] kg/m³, default 1000.
  - **The look** (presentation only):
    - `ShallowColor` (0.10, 0.55, 0.50) and `DeepColor` (0.01, 0.07, 0.12), linear;
    - `Clarity` [0.01, 1000] m, default 4;
    - `Roughness` [0.02, 1], 0.05; `RefractionStrength` [0, 1], 0.3;
    - `FoamAmount` [0, 1], 0.5; `ShoreFoamDepth` [0, 10] m, 0.5;
    - `DetailNormalStrength` [0, 1], 0.5; `DetailScale` [0.1, 1000] m, 4; `DetailDrift` vec2, (2, 1) m/s, each in [-100, 100] (the detail normals' drift);
    - `UnderwaterColor` (0.02, 0.10, 0.12); `UnderwaterVisibility` [0.1, 10000] m, 15;
    - `NormalMap` and `FoamTexture`: Texture handles, null for the built-in `WaterNormal` and `WaterFoam` (procedural, never compressed, the texture block's next two handles, `Asset/BuiltinAssets.h:77`).
  - **The frame.** The base height is the entity's world Y. Only its yaw orients it; a Rectangle's footprint takes its world X and Z scale. A pitched, rolled or sheared Water draws and samples level, reported by `WATER_INVALID`.
  - **One Ocean per scene:** the first effectively enabled one in canonical order. A later one is neither drawn nor sampled, and is reported.
- **`Buoyancy`, version 1, category Water.** Requires `RigidBody`; script-visible.
  - `Water`: EntityRef, default null (the point rule per collider); set, that water's own surface (a Rectangle only within its footprint and volume).
  - `BuoyancyScale` [0, 10], default 1 (1 is physical); `LinearDrag` [0, 100], 0.5; `AngularDrag` [0, 100], 0.05 (Jolt's drag model).
- **Which water holds a point** (`Scene/WaterQueries.h`: `FindWaterAt`, `SampleSceneWater`).
  - A Rectangle's **volume** is its footprint from `Depth` below its base to `Headroom` above it.
  - A point's water is the effectively enabled Rectangle whose volume holds it with the highest surface there, ties by canonical order; else the scene's Ocean; else none.
  - **Rectangles mask the Ocean:** inside any Rectangle's volume the Ocean is neither sampled nor drawn. So a cave lake below the sea's level, under a `Headroom` up to its ceiling, is dry above its own surface (S05's grotto), and a pool on a cliff is its own water.
  - `SceneWaterSample {UUID Water; double Height; glm::dvec3 Normal; glm::dvec3 Velocity; double Depth}`, `Depth` = surface height minus the point's y, positive under water.
- **The wave function** (`Physics/WaterWaves.{h,cpp}`, Physics layer 1, ECS-agnostic, on the simulation path).
  - `ResolveWaterSurface` turns the component's fields and the world frame into a `WaterSurfaceDesc`: per wave the world direction, k, ω, amplitude × `WaveScale`, Q and phase.
    - Q is scaled so that `Σ Qᵢ kᵢ Aᵢ ≤ 0.9` (`MaxWaterSteepnessSum`), so the surface never folds.
  - `EvaluateWaterSurface(desc, xz, time)` gives `{Height, Normal, Velocity}` in double precision with DetMath's double `SinCos`.
    - It finds the grid point whose Gerstner-displaced position lies under `xz` with a fixed number of Newton steps on the analytic 2×2 Jacobian (`WaterInversionSteps`: 4, or more if the 1 mm case needs it at the clamp, as the W47.1 record fixes). Every configuration runs the same operations.
    - The normal and the velocity (the surface particle's orbital velocity plus `Current`) are analytic at that point.
  - `ComputeWaterWavePhases(desc, time)`: each wave's phase at `time`, wrapped into [0, 2π) in double, for the renderer.
  - **Time** is the world's: `SimStep::Time` in PreStep, `Time.GetTime()` in scripts. So waves hold under the world pause, and a tick gives the same surface in Debug, Release and Dist.
- **Queries and scripts** (`Scripting/Bindings/Water.cpp`, `RegisterWater`, Terrain's pattern; reads, allowed in read-only evaluation and on an entity pending destruction).
  - Water proxy methods, `time` defaulting to `Time.GetTime()` (0 in an edit scene's evaluation):
    - `Water:SampleHeight(position: vector, time: number?) -> number?`, nil outside a Rectangle's footprint;
    - `Water:SampleNormal(...) -> vector?` and `Water:SampleVelocity(...) -> vector?`;
    - `Water:IsUnderwater(position, time?) -> boolean`: this water's own surface and volume, masking aside.
  - `Physics.SampleWater(position: vector, time: number?) -> WaterSample?` (alias `{Water: Entity, Height: number, Normal: vector, Velocity: vector, Depth: number}`): the point rule. `RegisterWater` reopens the `Physics` module, so `Bindings/Physics.cpp` is untouched.
  - The proxies read and write every field (generated). The float-point recipe (`Physics.SampleWater` with `RigidBody:AddForceAtPosition` in `OnFixedUpdate`) and the wading idiom go in a new luau-gameplay page, `water.md`.
- **Buoyancy** (Physics and Scene).
  - **The world.** `PhysicsWorld::ApplyBuoyancy(body, std::span<const PhysicsFluidPlane> planes, const PhysicsBuoyancySettings&, float deltaTime) -> Result<PhysicsBuoyancyResult>`:
    - `planes` holds one plane per collider in collider-index order (`{bool InWater; glm::vec3 Point, Normal, Velocity}`);
    - the walk descends the body's decorated shapes to its leaf or its compound's sub-shapes. Each sub-shape takes `Shape::GetSubmergedVolume` at its centre-of-mass transform against its own plane, and the volumes and centres of buoyancy are summed (`CompoundShape::GetSubmergedVolume`'s loop, one plane each);
    - then Jolt's second `ApplyBuoyancyImpulse` overload, under the body lock, with `B = BuoyancyScale × Density × V_total × invMass`, so Jolt's fluid density is the water's and the force is `ρ g V_sub`;
    - the fluid velocity is the submerged-volume-weighted mean of the planes' velocities;
    - it refuses a non-finite plane (`InvalidArgument`) and returns the volumes.
  - **The planes.** Each solid collider's world bounds centre (`GetSubShapeBounds`) samples its water at the tick's world time: the plane through the surface point under it, with the surface normal and velocity there. So one hull pitches with the local slope, and four pontoons ride a swell shorter than the boat.
  - **Where it runs:** PreStep item **4c, Buoyancy**, after the kinematic moves and teleports and after M44's vehicle item (4b), before the characters (item 5). It is a world phase, in Play and Simulate.
    - It visits the `Buoyancy` view sorted by canonical position, never a walk of every entity (M43's rule). On the milestone branch it sorts the view by `Scene::GetCanonicalOrder()`; at its merge it uses M43's `CollectCanonical<BuoyancyComponent>` and adds its visits to M43's `EntitiesVisited`.
    - An effectively enabled `Buoyancy` whose owner holds a created Dynamic body is applied. Any other is skipped and reports `PHYSICS_BUOYANCY_INVALID` once per entity through the physics diagnostics (§9.1).
  - **Sleep.** A buoyant body whose planes are bit-identical to its last tick's may sleep and is skipped while asleep; one whose planes changed (waves, a tide, a `WaveScale` write) is woken. The planes are runtime state, never hashed.
  - **Hash.** Nothing new: scenes without `Buoyancy` step bit for bit as before.
- **Rendering: the snapshot** (`RenderSnapshot.h`, after M46's `Wind`, the last member, with its types after M46's `RenderWind`; a frozen-header change in M43's file):
  - `WaterItem {World; Shape; Size; Depth; Headroom; Waves[MaxWaterWaves] {Direction, WaveNumber, Amplitude, Steepness, Phase}; WaveCount; look fields; DetailOffset; NormalMap; FoamTexture; PreviousWorld?; PreviousPhases?; Entity; PickId}`. `RenderWaterShape` and `MaxWaterWaves` live here too, the one header both Scene and Renderer include, as M42's bounds do.
  - **Extraction** (`WaterComponent` appended to M43's `CollectCanonical` list after the terrains), in every view, edit scenes included:
    - each effectively enabled Water (not a second Ocean) at its rendered world matrix (so the tide is smooth);
    - waves resolved by `ResolveWaterSurface`, phases by `ComputeWaterWavePhases` at `request.SimulationTime`, so edit views are at time 0;
    - `DetailOffset` = `DetailDrift × time`, wrapped by `DetailScale`;
    - PickIds after the terrains'.
  - **History.** `RenderViewHistory` fills `PreviousWorld` and `PreviousPhases` by Entity, emptied on a reset, as for meshes.
  - **Bakes and mirrors.** `MakeCaptureSnapshot` clears `Waters`, as it clears the fog. M42's mirror views never record the water.
- **Rendering: geometry** (`Renderer/WaterGeometry.{h,cpp}`, pure CPU; buffers made in `SceneRendererPipelines::CreatePipelines`, place 1):
  - camera-centred clipmap rings of one fixed 64 × 64 quad grid, each ring's cell twice the inner's, snapped to its cell so vertices never swim, stitched as `TerrainLod` stitches;
  - a flat skirt at the base height out to `WaterHorizonDistance` (100 km) under the infinite reverse-Z projection; an orthographic view to its far range;
  - a Rectangle draws the same rings clamped to its footprint, so a canal and a pool cost the same;
  - the vertex shader displaces forward (grid point to surface point) with `Common/Waves.slang`, the GPU mirror of `EvaluateWaterSurface`'s sum, relative to the rings' snapped origin (the origin's phase offsets computed in double on the CPU), so precision holds at the archipelago's 2.5 km;
  - each wave fades to flat where its wavelength nears the ring's cell. The CPU never fades.
- **Rendering: the `Water` pass** (Forward stage, after the sky, M45's, before `Ssr`; rows `WaterRefraction` and `Water`; target `WaterRefraction`; 2 pipelines, the surface and the surface with `EntityId`; program `Water`, `Passes/Water.slang`):
  - **When.** It records in a Lit view with a camera outside the wireframe (SSR's condition) whose snapshot has a water. Data views, debug views and the wireframe draw none.
  - **The copy.** `copyTexture` of `SceneColor` into a pooled `WaterRefraction` (`SceneColorFormat`), once a view, as `TaaPass` copies (`TaaPass.cpp:153`).
  - **The draws.** Each water in snapshot order, CullNone, into `SceneColor`, `SceneNormals`, `SceneVelocity`, `SceneRoughness` (and `EntityId` with Picking), with `SceneDepth` tested and written. `SV_IsFrontFace` picks the shading from above or below.

- **The wave function** (`Physics/WaterWaves.{h,cpp}`):
  - A wave's local direction at `Direction` degrees is the image of local +X under a turn about +Y: (cos, -sin) in (x, z), so 0 travels along +X and 90 along -Z. `MakeWaterFrame(world)` takes the translation and the X column's horizontal part, normalized (the Z column's, turned, when X is within a millionth of vertical; the world axes when both are); Z is a quarter turn from X.

From `x0 = x`, each step solves the Jacobian for Newton's step and halves it (down to `WaterInversionMinStep` = 1/1024) until the squared residual falls by Armijo's rule (`WaterInversionArmijo` = 1e-4); it stops when the residual is at most `WaterInversionTolerance` (1 nm) or after `WaterInversionMaxEvaluations` (32) evaluations of the waves, and the height, normal and velocity come from the last evaluation's sines and cosines. The step count depends on the inputs alone, through the same double arithmetic in every configuration, so the result is bit-identical in Debug, Release and Dist. **Correction:** C47 ran 8 fixed-point steps then 4 Newton steps and claimed at most 0.27 micrometres; that held only for C47's own sampling.   - "Water: a scene without water renders the same bytes": no Water, WaterRefraction or DepthPyramid row, no surface, and the same bytes before and after a render that drew a water. Committed with the others: it fails on C47 because the middle render must draw.
- **The geometry** (`Renderer/WaterGeometry.{h,cpp}`, pure CPU):
  - 11 levels (`WaterLevelCount`) of one 64 x 64 cell grid (`WaterGridCells`): level 0 a whole grid of 0.25 m cells (`WaterFinestCellSize`), each ring twice the cell of the level inside it with a 32 x 32 hole. Level 0's corner is floor((camera - 32 c0) / 2 c0) 2 c0 per axis, each ring's floor((corner below - 32 c below) / 2 c) 2 c (`PlaceWaterLevels`), so every corner is a multiple of twice its cell (no vertex swims), the hole lies 16 or 17 cells in on each axis (four ring meshes), and the camera lies 30 to 34 cells of every level from its corner. Each level's outer edge collapses its odd vertices onto their predecessors, TerrainLod's stitching, so it meets the next level's hole edge. The last level's cell is 256 m; it reaches about 8 km.
  - The skirt (`WaterSkirtMesh`): the last level's stitched outer edge and the same points pushed out from its centre by `GetWaterSkirtScale` (13), at least 100 km (`WaterHorizonDistance`) from the camera; flat, since every wave has faded there. Six meshes in all (`WaterMeshCount`), of cells (`RG16_SINT`) from the level's corner, counter-clockwise seen from +Y, made once in `WaterPass::Create` (place 1).
  - A Rectangle draws the levels (and the skirt) whose square meets its footprint's bounds (`GetWaterFootprintBounds`), each vertex's rest point clamped into the footprint in the shader, so a calm Rectangle draws exactly its footprint; an Ocean draws all twelve. With waves the edge's rest points are displaced like any other, so the drawn edge moves horizontally by up to the sum of Q A while the queries' footprint stays exact: an accepted limit for the landing's Backlog §6 rows (a Rectangle's waves meant for a pool or a canal are small).
  - **The fade** (`Common/Waves.slang`): at Chebyshev distance d of a rest point from the camera the level's cell is at most max(0.25, d / 15) m (`WaterLevelDistanceCells`); a wave keeps its amplitude down to four such cells a wavelength and fades to flat at two (`WaterFadeCellsPerWave`), and every wave fades to flat over the last level's cells 22 to 30 (`WaterHorizonFadeCells`, `WaterHorizonFadeEndCells`), where the skirt begins. The fade is a function of the rest point and the camera alone, so a vertex two levels share displaces alike in both and the levels meet without a crack. The CPU never fades. With 64-cell levels a 20 m swell is drawn whole to about 75 m and flat from about 150 m (decision 3's accepted "distant short waves are drawn flat").
- **The records** (`Shared/WaterConstants.h`, last in `ShadersTests.cpp`'s list; `MakeWaterRecord`): one `WaterRecord` (480 bytes) per snapshot water, in snapshot order, in one structured buffer of the view's (`WaterViewResources::Records`, grown to twice the waters when too small), and one `WaterDrawConstants` (16 bytes, the mesh pipelines' push-constant range) per draw: the level's corner from the records' origin, its cell size and the record's index.
  - The records' origin is level 0's corner. Each wave's phase at it, k dot(D, origin - water origin) + the snapshot's phase, is computed in double from the item's float wave numbers, directions and phases and wrapped, so a rest point's offset from the origin stays exact in float (a multiple of 0.5 m) and the shader's phase k dot(D, offset) + phase loses nothing to the archipelago's distances. The previous frame's phase at the origin uses the history's `PreviousPhases`.
  - Flags: `WaterRecordFlagRectangle`; `WaterRecordFlagAdvanced` when a previous phase differs; `WaterRecordFlagMoved` when `PreviousWorld` differs from `World`, with `PreviousFromCurrent` = PreviousWorld x inverse(World) in double. Without either motion flag a vertex's previous point is its current one, so a still water under a still camera has exactly zero motion.
  - The frame follows `MakeWaterFrame`'s rule in the renderer (which may not include Physics): the translation, the X column's horizontal direction (the Z column's turned when X is vertical); a Rectangle's half extents are Size / 2 times the X and Z columns' lengths (`ResolveWater`'s). The look is clamped into the registry's ranges, a non-finite value taking the default (a snapshot built by hand). `PlanarSlot` is `WaterNoPlanarSlot` until W47.3.
- **The pass** (`Renderer/WaterPass.cpp`, `Passes/Water.slang`, `Common/Waves.slang`; the program `Water` after `Upscale` in `Shaders.json`, entries `VSSurface`, `PSSurface`, `PSPicking`):
  - Two pipelines (the declaration's `PipelineCount` 2 and `Programs` {Water}: 79 startup pipelines on the branch): set 0 the forward view layout, set 1 t0 the records, t1 `WaterRefraction`, t2 the depth pyramid, t3 the normal map, t4 the foam map; nothing culled, front faces counter-clockwise, `SceneDepth` tested `GreaterOrEqual` and written; attachments `SceneColor`, `SceneNormals`, `SceneVelocity`, `SceneRoughness`, then `EntityId` for the picking pipeline.
  - `RecordSurface` writes the records, makes each water's set 1 (its `NormalMap` and `FoamTexture` through the cache, the built-in `WaterNormal` and `WaterFoam` for a null handle or a placeholder mirror) before drawing anything, then draws each water's levels in snapshot order. A buffer or set creation error is returned with nothing drawn.
  - **The shading** (decision 3's list): the wave normal and the Gerstner Jacobian per fragment at its interpolated rest point; two detail layers of the normal map (the second turned about 37 degrees, scaled 1.7 times and drifting at 0.75 of the first's `DetailOffset`) whiteout-blended by `DetailNormalStrength` in the water's local frame; F0 0.02, geometric specular anti-aliasing, the light loop with the view's shadows, the environment's or the probes' irradiance and specular. Under the surface, `WaterRefraction` at the pixel moved by the view-space normal times `RefractionStrength` times 5 % of the view's height (`WaterRefractionOffset`), or at the pixel itself where the moved one's pyramid depth lies in front of the surface; T = exp(-column / Clarity) over the column (the pyramid depth behind less the surface's, along the view ray); the body lerp(DeepColor, ShallowColor, T) times (1 - T) lit as a diffuse surface. Foam: FoamAmount times saturate(max(shore, crest) x 2 x the foam map), shore = 1 - column / ShoreFoamDepth, crest from the Jacobian below 0.75 (full at 0.35), a white diffuse albedo of 0.85 over the body; the specular term and the refraction scaled by 1 - foam. Fog by `EvaluateViewFog`.
  - A back face (the surface from below) flips the normals and shows the refraction unabsorbed; W47.3's Underwater pass adds the view under the surface, the waterline and Snell's window.
  - **SSR**: `SceneRoughness` word 0 holds the specular multiplier (multi-scatter x horizon occlusion x (1 - foam)) and roughness, word 1 the occlusion 1 (x) and the water flag 1 (y). `Ssr.slang`'s composite takes word 1's x alone where y is not 0, else min(x, GTAO) as before.
  - **The Ocean's mask**: an Ocean's fragment inside any Rectangle's volume (its footprint from Depth below its base to Headroom above, boundaries included) writes zero coverage.
- **The renderer** (`SceneRenderer.cpp`, `Private/SceneRendererState.h`):
  - `frame.Water`: a camera, a Lit view outside the wireframe, a snapshot with water. The Ambient stage ensures the targets first (`EnsureWaterTargets`: the pyramid's `ViewDepth` when GTAO and SSR did not, `WaterRefraction` from the pool, SceneColor's kind of target, and the surfaces' framebuffer, the picking one with `EntityId`), and the pyramid gate is `frame.Ao || frame.Ssr || frame.Water`; a failure clears `frame.Water` and is the render's error.
  - The Forward stage, after the sky and before SSR (`RecordWater`): the set-0 variant (the forward set with t6 the white AO and t9 the far-depth texture), the copy under the `WaterRefraction` row, `RecordSurface` under the `Water` row; `RenderStats::WaterSurfaces` is the snapshot's waters when it succeeds.
  - A render that draws no water drops `WaterRefraction` and the framebuffers (back to the pool). The water's sets are cleared with the target bindings and released when unused; the records and sets are the state's (place 2), the pipelines and meshes the pipeline set's (place 1), the maps the cache's.
- **History** (`TemporalHistory.{h,cpp}`): `RenderViewHistory` records each water's `World` and its eight phases by entity and fills `PreviousWorld` and `PreviousPhases` from them, empty for a water it did not see, one whose recorded values are not finite, and after a reset.
- **The built-in maps** (`BuiltinAssets.h` 0x018d and 0x018e, `BuiltinTextures`, `BuiltinAssets.cpp`'s procedural tables, `Resources/EngineAssets.json`): `WaterNormal`, 128 x 128 RGBA8Unorm, the normal of a four-octave value-noise height field (cells 32 to 4 texels, weights 8 to 1), its steepest texel leaning 45 degrees; `WaterFoam`, 128 x 128 R8Unorm, a three-octave noise (cells 16 to 4) past 45 % of its range, dense 30 % above it. Both tile, carry full mip chains of exact box means and are integer arithmetic only (an exact integer square root), so their bytes are the same in every configuration.
- **Out of memory and device loss**: `WaterRefraction`'s creation is the per-render rule of §8.14 item 7 (ADR 0029 decision 44): the render draws no water and returns the `Gpu` error, its host trims after the frame, and the next render draws it ("Water: a water whose refraction, set or records cannot be created is left out of the render, which returns the error, and the next render draws it", which also fails the water's set 1 and its records buffer), as M42's reflections do. **Departure from decision 3's wording** ("trim and retry, then ... returns OutOfMemory"): `RetryAfterTrim` may not run while a command list records (`Graphics/GpuOutOfMemory.h`), and a render's lazily created target follows decision 44's rule, as W47.1's review noted.
