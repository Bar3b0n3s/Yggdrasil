# 0041 — Script checks share one prepared environment

- **Status:** accepted
- **Date:** 2026-11-13
- **Decided by:** the lead, as a fix that reaches main outside the phase-3 milestones, on the program's setup branch before M24 and M26 land (ADR 0028's phase-3 ledger: "a record outside a milestone takes 0041 on"; its amendment "Main's script-check fix" names the files the milestones merge).
- **Context:** PreCommit's Debug automation run timed out in `Tests/Automation/test_feature_test.py`'s `test_scaffolds_reproduce_the_project_byte_for_byte`, which runs `Scaffold.py --check --config Debug` under a 3,600 s bound: about 4,070 s on a loaded machine (Release 578 s). A profile of the check on the same tree (the 54 scaffolds of phase 2's FeatureTest, run step for step as `Scaffold.py --check` runs them, with temporary per-request timers, per-subsystem counters and 136,137 stack samples of the Debug run's main thread; every run reproduced the project byte for byte) measured 2,812 s in Debug and 308 s in Release (the 54 editor processes' wall times, the loaded machine of the profile; startup was 2.8 % of the Debug time):
  - **Every check rebuilt its environment.** `ScriptTypeChecker::CheckScript` built a new `Luau::Frontend` and ran `registerBuiltinGlobals` and `loadDefinitionFile` of the 1,785-line generated `Engine.d.luau` before checking the script: 221.4 ms of each 268.7 ms check in Debug (10.3 of 13.6 ms in Release), 61 % of all Debug samples. Luau Analysis runs 20 to 24 times slower in Debug than in Release (the debug heap, `/JMC`, iterator debugging).
  - **Every new directory checked every script again.** `CaptureConfiguration` records an entry for every directory below `Assets/`, an absent `.luaurc` included, and both the editor's refresh hash (`EditorContext::RefreshScriptServices`) and the checker's environment hash covered those entries. So every directory a scaffold made replaced the checker, `EditorAssetManager::SetScriptDiagnosticsProvider` marked every script import `RecheckPending`, and the next asset refresh imported every script again: 19 such storms re-imported 1,594 scripts (662 s in Debug), and the cached imports of earlier processes missed for the same reason, 4,115 imports where 262 would do. The unit case "ScriptTypeChecker: configuration snapshots distinguish missing present and inherited configs" pinned the rule (a new directory changed the hash), though a directory without a `.luaurc` changes no check: `CheckerConfigResolver` reads present files only.
  - **Every import registered the whole script API.** Each import's load-time VM (`Sandbox::Create` without `SandboxSpecification::Api`) built, registered and froze a `TypeRegistry` of the built-in components and a `ScriptApiRegistry` of every binding: 56.4 ms of each import in Debug, 8.4 % of the samples (`RegisterBindings` 91 % of that).
  - The checks: 7,599 in Debug, 2,042 s; 3,484 of them were play, recording and test starts checking every script of the project (`BlockPlayOnTypeErrors` and the test host), and 629 asset refreshes, one for each project-path asset reference, cost 360 ms each in Debug (decision 5).
  - A prototype of decisions 1 to 3 measured 652 s in Debug and 196 s in Release with the project's bytes identical in both, and its leased frontends gave the findings of fresh ones in all 3,746 checks of that run and in 168 checks of deliberately broken scripts.

## Decisions

1. **A checker prepares its frontends once.** `ScriptTypeChecker` keeps the `Luau::Frontend`s it prepared (the builtin globals and the generated definitions loaded and frozen once in each) and leases each to one check at a time from a mutex-guarded pool, as its class contract already allowed ("exclusively leases them"). A check sets its own file and configuration resolvers; a completed check clears every module, source and require trace (`Frontend::clear`) and require-cycle group and points the frontend back at stateless null resolvers before it is leased again, and a check that throws (`Luau::InternalCompilerError`) drops its frontend. `Create`'s validating frontend is the pool's first, so sequential checks load the definitions once per checker; a check that finds every prepared frontend in use by a simultaneous check prepares one more, and the idle ones stay with the checker, as many as checks ever ran at once. Nothing a check reads outlives it, the global types are frozen, and Luau's constraint generation binds a module's globals in the module's own scope, never in the global one, so findings do not depend on reuse. `ScriptTypeChecker::GetStatistics` reports the checks and the definition loads; the editor reaches its checker through `EditorContext::GetScriptChecker`.
2. **Only present `.luaurc` files configure a check.** The editor's refresh hash and the checker's environment hash (fingerprint version `v2`) hash only the present files' paths and contents. `CaptureConfiguration` still lists the project root and every directory under `Assets/`, so a `.luaurc` added to a new directory is seen. A new directory without a `.luaurc` keeps the checker and every script's check; a `.luaurc` added, changed or removed still replaces the checker and checks every script again. This reverses the rule the configuration-snapshot unit case pinned. The new fingerprint version changes every project's environment hash once, so every cached script import is checked again once; the hash lives only in the gitignored Library cache.
3. **Load-time VMs share one pure script API.** `PureScriptApi` (`Scripting/Sandbox.h`) is the registry pair a `Sandbox` without `SandboxSpecification::Api` builds for itself, every built-in component type and every binding, frozen; `Sandbox::Create` builds its own through it, so the two cannot differ. The editor builds one in `EditorContext::Create` and passes its registry to every script import (`EditorAssetManagerSpecification::LoadTimeScriptApi`, `ImportContext::Specification::LoadTimeScriptApi`), the manager's imports and `EditorScriptService`'s detached check imports alike; `ScriptImporter` gives it to `LoadTimeVm::Extract` (`LoadTimeVmSpecification::Api`), whose VM binds it. It is immutable once built, and a VM without an engine binds and dispatches it without touching its coverage counters (`ScriptApiRegistry`'s contract), so imports on different job threads share it. It is no global: the editor owns it, declared before the asset services that borrow it. An import context without one (a test, a tool that imports without the editor) still has each VM build its own, with the same result.
4. **Nothing the editor writes changes.** No cooked artifact, finding, `.meta`, scene or provenance byte changes, and the scaffold check passes in Debug and Release on the changed tree; only the Library cache sees the new environment hashes (decision 2).
5. **What is deferred.** The profile's other candidates are performance follow-ups in `Docs/Backlog.md` §3, each with its measured or estimated saving and its risk, since decisions 1 to 3 bring the Debug check well inside its bound: one asset refresh per request for project-path references unless something was written since (F5B); play, recording and test starts reusing the current import checks (F8); a cached checker configuration (F4); provenance saved once per request (F6); skipping superseded queued imports (S); Debug builds without `/JMC` and `/RTC` (F7); LuauAnalysis optimized in Debug (F9).

## Consequences

- The scaffold check after the change, on the same tree and with the project reproduced byte for byte: Debug 949 s (`test_scaffolds_reproduce_the_project_byte_for_byte` in the Debug automation run, beside sibling worktrees' builds that kept the CPU at 100 % for most of the run, 7 to 22 compilers at a time), against 2,812 s in the profile and about 4,070 s at the lead's load, so the check now takes about a quarter of its 3,600 s bound on a busier machine than the profile's; Release 218 s (the steps of `Scaffold.py --check --config Release --json`, 215 s of them the 54 editor processes, while four or five sibling unit suites kept the CPU at about 70 %), against 308 s in the profile.
- Every script check, import and write of the editor is cheaper, in every configuration: a check no longer loads the definitions, a new directory re-imports nothing, and an import's VM registers no API.
- An editor keeps its checker's idle frontends, one for each check that ran at once (the main thread and the import job workers), until the checker is replaced; before, each check built and freed one. Creating an `EditorContext` builds one `PureScriptApi` (what one import's VM used to build).
- `Docs/Architecture.md` §4.11 (the load-time VMs share only the frozen API), §7.4 (the `ScriptImporter` row), §11.2 (the load-time environment) and §11.9 (the prepared frontends and the configuration snapshot's hash) say so. No skill stated the old directory rule.
- ADR 0028's phase-3 ledger amendment "Main's script-check fix" names the files this change makes on main before M24 and M26 land, which they merge at their landings (M24's `GraphImporter` passes the context's API to `LoadTimeVm::Extract` as `ScriptImporter` does).

## Verification

- Tests: "ScriptTypeChecker: consecutive checks load the definitions once" (sequential checks keep one definition load; a request that reaches no analysis is not a check); "ScriptTypeChecker: a reused checker finds what fresh checkers find" (the checker's and the importer's script fixtures and deliberately broken scripts: type, syntax, lint, generic and engine API errors, a missing require, required modules with errors, a require cycle, refused type functions, nested `nocheck` and invalid configurations) and "... in FeatureTest's scripts" (all of `Projects/FeatureTest`'s scripts with its configuration), each checked twice by one checker, in order and in reverse, against a fresh checker per script; "ScriptTypeChecker: simultaneous checks are deterministic and failures never appear clean" now also counts the second frontend the overlapping checks prepare; "ScriptTypeChecker: configuration snapshots distinguish missing present and inherited configs" with the rule reversed (a new directory changes nothing; a new, a changed and a removed `.luaurc` each change the hash); "EditorScriptService: a new directory without a .luaurc keeps the checker and every script's check" (the regression case, which a `.luaurc` added to the directory then replaces); "ScriptImporter: imports that borrow one pure script API cook what imports with their own cook" (byte-identical artifacts, dependencies, diagnostics, checks, reads and lookups for a module, a behaviour with fields and a test suite, two imports borrowing the API at once on two threads; an API without the bindings fails the import, so the import binds what it borrows); "ScriptImport: the manager's script imports bind the load-time API its specification gives".
- Shown failing without their fixes, each run alone in Debug: with the refresh hash and the fingerprint counting absent files again, the EditorScriptService case (a new checker with 0 checks where the old one had 2, another environment hash, the script's check gone) and the configuration-snapshot case (a new directory changed the hash); with every check preparing its own frontend, "consecutive checks load the definitions once" (6 loads for 5 checks); with `ScriptImporter` ignoring the context's API, the importer case (the import without the bindings succeeded); and with `EditorAssetManager` not passing its API on, the manager case (the import succeeded and logged nothing).
- Runs on the final tree (2026-11-13): the Debug, Release and Dist builds (0 warnings); `Lint.py` (strict, 0 findings); `Format.py --check`; `CheckRuntimeMap.py --config Dist`; the Debug unit suite in full (4,717 cases passed, the 40 child-process targets skipped); the Release unit suite's Scripting and AssetPipeline suites (647 cases) and its `EditorScriptService` cases (10); `Test.py --suite automation --config Debug --filter test_feature_test,test_script,test_editor_script_host` (53 tests, the Debug scaffold check among them); `Scaffold.py --check --config Release`; `GenerateDocs.py --check --config Debug`.
