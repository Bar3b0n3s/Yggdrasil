## Context

M28 delivers World Tree's briefs 04 (display settings and a performance readout for scripts, with the game's additions: text that shows frame-paced values outside the state hash, and decisions on frame time recorded as input) and 03 (save data, with the game's addition: the session's audio mix kept across `Scene.Load`), in two waves (ADR 0042 decision 3): W28.1 display settings, the performance readout, presentation text and frame-time signals; W28.2 save data and the session's audio mix. The facts this record relies on, each checked in the code at `bb51e110`:

1. **`play.start` does not refresh.** `EditorMethodContext::StartRecordingSession` refreshes the project's assets (`Utils::RefreshAssets`) before `input.record` starts, but `StartPlay` calls `EditorPlayController::Start` directly, so a scene file written since the last refresh plays without its scene asset (`PrepareSession` finds no `AssetRecord` for its path): `Scene.GetCurrent` is nil and the play scene's summary falls back to the open scene's file (the F25 fix agent's open point 1). `EditorAssetManager::Refresh` is "the implicit refresh before every automation call that takes a path".
2. **The window.** `Platform/Window` is one GLFW class without OS backends; `WindowSpecification` has `Title`, `Width`, `Height`, `Resizable` and `Fullscreen` ("full screen on the primary monitor at its current video mode"); fullscreen exists only at `glfwCreateWindow` (`Window.cpp`), nothing calls `glfwSetWindowMonitor`, no monitor or video-mode query exists, and the window is visible from creation. `Window::GetNativeHandle` is the `GLFWwindow*`. `CheckPlatformWindowSupport` (`Platform/PlatformWindowSupport.h`, `Platform/Windows/PlatformWindowSupportWindows.cpp`, `Platform/Posix/PlatformWindowSupportPosix.cpp`) is the precedent of a Windows-only capability: Win32 GLFW platform only, a headless process refused, `Unsupported` on Linux and macOS.
3. **VSync.** `SwapchainSpecification::VSync` is set once at `Swapchain::Create`, kept in `m_Specification` and read by `ChoosePresentMode` at every `CreateSwapchain`; `Swapchain::RequestRecreate` recreates at the next acquire. There is no `SetVSync`. `Application::CreateFrameObjects` builds the window's swapchain with `device.GetSpecification().VSync`, also after a device loss, so a VSync changed on the swapchain alone would revert at the recovery.
4. **The project's window.** `WindowSettings` (`Project/ProjectSettings.h`: `Title`, `Width`, `Height`, `VSync`, `Fullscreen`, `Resizable`) becomes the `ApplicationSpecification`'s `WindowSettings` and `Graphics.VSync` through `ApplyGameSettings` (`App/ProjectSettingsApplication.cpp`); the Runtime's factory (`CreateRuntimeApp`) applies it from `Game.json` before `Application::Run` creates the window. `EngineContext::Create` mounts `user://` (`<UserData>/<Name>/`, atomic writes without a backup) before it creates the window. `ReadStartupPlatformWindowsPreference` (`EditorCore/EditorPreferences.cpp`) is the precedent for reading a `user://` file before the window exists, through a temporary read-only mount.
5. **The frame boundary.** `FrameLoop::RunFrame` runs events, the main-thread queue, `OnFrameSafePoint` (before the fixed steps), the steps, the update and the render; `Application::OnSafePoint` is the subclasses' hook, and the Runtime already consumes the session's quit request there.
6. **Scripts and hosts.** `IScriptHost` (`Scripting/ScriptHost.h`) holds `GetEnvironment()` (a `ScriptEnvironment`: `IsEditor`, `IsHeadless`, `IsFocused`, `Platform`, `Version`, `WindowSize`) and members with defaults (`GetPhysics2D`, `GetUi`, `GetText`), so `EditScriptHost` and the tests' `ScriptTestFixture` need no change for a new defaulted member. `PlaySession::State` implements it and forwards host questions to `IPlaySessionHost` (`GetScriptEnvironment`, the cursor), which `RuntimeApp::State` and the editor play controller's state implement. The `Application` module (`Scripting/Bindings/Application.cpp`) has `Quit`, `IsEditor`, `IsHeadless`, `IsFocused`, `GetPlatform`, `GetVersion` and `GetWindowSize`. Scripting is layer 4 (`Scripts/ModuleRules.json`, at most layer 3), so it includes neither Session nor App.
7. **The readout's sources.** `stats.get` (`Automation/Methods/StatsMethods.{h,cpp}`) builds `StatsGetResult` and `StatsViewSummary` from the host's `GetHostStatistics` (the Runtime's `ReadHostStatistics` lambda and the editor's, both outside Dist), `CountSessionBodies` and the script VM's `GetMemoryState`. Every type and function declared under `Automation/` is a forbidden Dist symbol family (`Scripts/Lib/runtime_map.py`), `CountSessionBodies` and the stats structs among them. `RenderStats` (`Renderer/RenderStats.h`) has per-pass CPU and GPU milliseconds, draw calls and triangles, the shadow counters and no light count; `SceneRenderStats` (`SceneRenderer.h`) counts `Lights` and `DroppedLights` in `RecordPrepareStage` without passing them on; `RecordDeformStage` marks each deformed mesh (`entry.Deformed`), which no counter counts. `ParticleSystem::GetStats().Particles` is the live particles after the step, which nothing reads; `PhysicsSystemStats` and `Physics2DSystemStats` have `BodyCount` and `ActiveBodyCount`. `FrameLoopStatistics` (`App/FrameLoop.h`) has `Fps`, `CpuMilliseconds` and `DroppedSeconds`.
8. **The frame-phase rule.** `ParticleEmitter:GetParticleCount` (`Scripting/Bindings/Particles.cpp`) raises an error when `call.Execution->Origin == ScriptExecutionOrigin::Gameplay` and the host's frame state is `InputPhase::Step`, so it is readable in `OnUpdate`, `OnLateUpdate`, test cases and evaluations.
9. **UI text.** `UiTextComponent` (v1) is drawn by `AppendUiDrawItems` (`Scene/UiExtraction.cpp`), which already substitutes a `UiTextInput`'s live text for its text element's `Text`; layout (`UiLayout.cpp`) and hit testing (`IsUiPointerTarget`) never read `Text`; `ui.tree` measures what extraction draws (`MeasureUiTreeTexts`). `UiSystem` keeps the interaction state, which its `AppendStateHash` hashes ("UiState1", empty while unused); the session reaches it through `IScriptHost::GetUi`. No UiText proxy type has methods.
10. **Input and replays.** `PlayInputEventType` has nine kinds (`Action` to `Text`); `PlayInput::ApplyTick` applies the queued events of a tick in the ApplyInput phase, after which the recorder captures them (`ReplayRecorder::CaptureAppliedInput`); `LatchFrame` latches the frame view. The hosts suppress live device input in test runs, replays and lockstep (`EditorPlayController::OnInputEvent`, `RuntimeApp`'s input), and recordings (`input.record`, lockstep sessions with a recorder) take it. The replay format is version 3 (`ReplayFormatVersion`, `ReplayData::FormatVersion`, `ReplayImporter::Version`); readers accept versions 1 to 3, version 2 added checkpoints and version 3 the fingerprint; `Tests/Data/Formats/Replay/` holds `v1.replay`, `v2.replay` and their `.upgraded.replay` files (no `v3.replay`). `input.inject` (`Automation/Methods/InputMethods.cpp`) and `Test.Inject*` (`Scripting/Bindings/Test.cpp`) queue events of the nine kinds.
11. **The audio mix.** `AudioSystem::InitializeMix` records the engine's Music, Sfx and Ui volumes and sets them to 1; `~AudioSystem` restores the recorded ones. `PlaySession::Activate` builds the scene's `AudioSystem` and initializes its mix, and `State::ConsumeRequests` resets it (restoring the volumes recorded before the session) and builds a new one that initializes the mix again at every `Scene.Load` and `Scene.Reload`, so a group volume a script set (`Audio.SetGroupVolume`, documented "for the rest of the session") is lost, in editor play, the Runtime and an export alike. `SessionScriptingTests.cpp`'s "startup audio gains survive callbacks and restore across scene replacement" pins today's reset. The editor also records the mix at a play start and restores it at the end (`EditorPlayController`'s `MixerBaseline`); the Runtime has no equivalent.
12. **Files.** `FileSystem::WriteFileAtomic` writes a temporary file, flushes the stream (no `FlushFileBuffers`), optionally keeps a backup and renames; `PublishedFile::Replace` renames with `FILE_RENAME_FLAG_POSIX_SEMANTICS` on Windows; nothing flushes durably (ADR 0003 decision 5: "it would come through a Platform hook if ever required"). `JsonWriter` writes 32-bit floats; nlohmann's `dump` writes the shortest round-trip double. `CheckJson` and `PushJson` (`Scripting/Private/BindingRegistration.h`) convert Luau values and JSON (nil, booleans, finite numbers, strings, arrays and string-keyed tables; cycles and mixed keys refused). `EditorPreferences` (`user://Editor.json`, `{"Format": "EditorPreferences", "Version": 1}`) is the user-data format precedent and a fuzz target.
13. **The state hash.** `PlaySession::ComputeStateHash` hashes the scene's canonical form, the tick, the `Random` state, the id draw count, then the physics, native, physics2d and ui blocks, each empty while unused.

## Decisions

### 1. Waves and checkpoints

- **W28.1:** decision 2 (`play.start` refreshes), the performance readout (decision 4), presentation text (decision 5), frame-time signals with the replay's version 4 (decisions 6 and 7) and the display settings (decision 3), each a checkpoint commit "M28: <what it adds> (W28.1)".
- **W28.2:** the session's audio mix (decision 9), then save data (decision 8), checkpoint commits "M28: <what it adds> (W28.2)".
- The readout, presentation text and signals come before the display settings inside W28.1 because the display settings carry the milestone's only platform risk (decision 3's tests) and touch the most host files; the order changes no interface, since no other stream works beside them.

### 2. `play.start` refreshes the project's assets (F25's open point 1)

`EditorMethodContext::StartPlay` refreshes the project's assets (`Utils::RefreshAssets`, `EditorAssetManager::Refresh`) before `EditorPlayController::Start`, as `StartRecordingSession` does, so a scene file written since the last refresh plays with its scene asset. Only a start the controller would admit refreshes (a project open, no session and no test run active): a refused start changes nothing. The method's description and `AutomationMethodContext::StartPlay`'s documentation say so; the Runtime's `StartPlay` stays `Unsupported`. Tests: "EditorMethodContext: play.start refreshes the assets first, so a scene file written since the last refresh plays with its scene asset" (fails before the fix: no scene asset) and "EditorMethodContext: play.start refused while a session runs leaves the assets unrefreshed".

### 3. Display settings (W28.1)

- **Types** (`Platform/DisplayModes.h`, new): `enum class DisplayWindowMode { Windowed, Borderless, Exclusive }`; `struct DisplayVideoMode { uint32_t Width = 0; uint32_t Height = 0; uint32_t RefreshRate = 0; }`; `struct DisplaySettings { DisplayWindowMode WindowMode = Windowed; uint32_t Width = 0; uint32_t Height = 0; uint32_t RefreshRate = 0; bool VSync = true; }`. `Windowed` is a decorated window of `Width` x `Height` screen units; `Borderless` an undecorated window covering the window's monitor at its current video mode (`Width`, `Height` and `RefreshRate` are the monitor's, never changed); `Exclusive` GLFW's full-screen monitor mode at `Width` x `Height` and `RefreshRate`, which must be one of the monitor's modes (without `VK_EXT_full_screen_exclusive`, ADR 0042 decision 3).
- **Platform** (Windows backend only, ADR 0028 decision 10): `Result<std::vector<DisplayVideoMode>> QueryDisplayVideoModes(const Window&)`, the modes of the monitor the window is on (the primary monitor for a windowed window), sorted by width, height and refresh rate, without duplicates; `Status ApplyDisplaySettings(Window&, const DisplaySettings&)`, through `glfwSetWindowMonitor` and the decorated attribute. `Platform/Windows/DisplayModesWindows.cpp` implements both for GLFW's Win32 platform and refuses a headless process (GLFW's null platform; `Unsupported`, "a headless process has no display"); `Platform/Posix/DisplayModesPosix.cpp` reports `Unsupported` ("only Windows has a backend"), as `PlatformWindowSupport` does. `WindowSpecification` gains `DisplayWindowMode DisplayMode` (default `Windowed`) and `uint32_t RefreshRate` (0: the monitor's current one), appended after `Fullscreen`; `Fullscreen` keeps its meaning (the project's setting: full screen at the monitor's current mode) and `Window::Create` applies `DisplayMode` when it is not `Windowed`.
- **Swapchain:** `Swapchain::SetVSync(bool)` changes the specification's `VSync` and requests a recreate when it changed (the present mode is chosen again at the next acquire); `GetVSync()` reads it.
- **Application:** `Result<std::vector<DisplayVideoMode>> GetDisplayVideoModes() const`, `DisplaySettings GetDisplaySettings() const` (the applied settings: the window's mode and size, the monitor's refresh rate in the full-screen modes, the VSync in force) and `Status RequestDisplaySettings(const DisplaySettings&)`, which validates at once (`Unsupported` headless or without a window, `InvalidArgument` for a zero size or an `Exclusive` mode not in the list) and applies the request at the next frame boundary (`Application`'s frame safe point, before the subclass's `OnSafePoint` and the fixed steps); the last request of a frame wins. `Application` keeps the chosen VSync and passes it to every swapchain it creates, so a device-loss recovery keeps it.
- **Persistence:** `user://Display.json`, `{"Format": "DisplaySettings", "Version": 1, "WindowMode": "<mode>", "Width": <n>, "Height": <n>, "RefreshRate": <n>, "VSync": <bool>}`, read and written by `App/DisplaySettingsFile.{h,cpp}` (`ParseDisplaySettingsFile`, `SerializeDisplaySettingsFile`, `ReadStartupDisplaySettings`); a missing file keeps the project's `Window` settings, an unreadable one is logged and ignored. The Runtime's factory reads it before `Application::Run` (as the editor reads its platform-windows preference) and applies it to the specification's window and VSync, so the first window shows in the chosen mode; the Runtime writes it after each applied request. A headless Runtime neither reads nor writes it. The reader is a fuzz target (decision 12).
- **Script API** (`Application`, appended after `GetWindowSize`): `GetDisplayModes() -> {DisplayMode}`; `GetDisplaySettings() -> DisplaySettings`; `SetDisplaySettings(settings: DisplaySettings) -> (boolean, string?)`, with the aliases `DisplayMode = {Width: number, Height: number, RefreshRate: number}` and `DisplaySettings = {WindowMode: string, Width: number, Height: number, RefreshRate: number, VSync: boolean}` (`WindowMode` one of `Windowed`, `Borderless`, `Exclusive`; a member left out keeps its current value). `SetDisplaySettings` returns true when the request was accepted for the next frame boundary, and false with the reason where the calls do nothing; a malformed table is a script error.
- **Where the calls do nothing:** the editor (its game view and every editor session), headless runs and every fixed-view session (suites, replays, recordings, lockstep: the sessions whose view is the project's window size). There `GetDisplayModes` returns an empty list, `GetDisplaySettings` returns `Windowed`, the session's view size, refresh rate 0 and the project's `Window.VSync`, and `SetDisplaySettings` returns false with its reason; nothing touches the project's `Window` settings or the state hash.
- **Hosts:** `IScriptHost` gains `GetDisplayModes`, `GetDisplaySettings` and `RequestDisplaySettings`, each defaulted to the "do nothing" answers, and `IPlaySessionHost` the same three with defaults; `PlaySession` answers them itself for a fixed-view session and forwards the others to its host; `RuntimeApp::State` implements them over `Application`.
- **Tests:** the file's reader and writer (round trip, defaults, refusals, unknown keys kept out), its fuzz case, the binding in every session kind (fixed view, editor) through `ScriptTestFixture` and FeatureTest, `Swapchain::SetVSync` in a gpu case, and a windowed child of the unit suite that switches the Runtime's window between `Windowed` and `Borderless` and back and renders after each; `Exclusive` mode changes the desktop's video mode, so no default suite switches to it (ADR 0042's risk "display modes on the one test machine"), and it is covered by the Dist export check the game makes (Acceptance).

### 4. The performance readout (W28.1)

- **Struct:** `ScriptPerformanceStats` in `Scripting/ScriptHost.h` (Dist-safe; outside `Automation/`): `bool RenderAvailable`, `bool GpuAvailable`, `double Fps`, `double CpuMilliseconds`, `double GpuMilliseconds`, `uint32_t VisibleLights`, `uint32_t DroppedLights`, `uint32_t ShadowedLights` (shadowed spot and point lights), `uint32_t DrawCalls`, `uint64_t Triangles`, `uint32_t Particles`, `uint32_t SkinnedMeshes`, `uint32_t Bodies`, `uint32_t ActiveBodies`, `uint32_t Entities`, `uint64_t ScriptHeapBytes`. The render counters are the game view's last rendered frame (GPU times from the frame the profiler last read back), zero with `RenderAvailable` false without a renderer.
- **Session:** `Session/SessionStatistics.{h,cpp}` (new): `struct SessionStatistics { uint32_t Entities; uint32_t Bodies; uint32_t ActiveBodies; uint32_t Particles; }`, `SessionStatistics ReadSessionStatistics(const PlaySession&)` and `CountSessionBodies`, moved here from `StatsMethods` (both worlds' bodies, as today). `IPlaySessionHost` gains `std::optional<HostFrameStatistics> GetFrameStatistics() const` (default nullopt), `HostFrameStatistics { double Fps; double CpuMilliseconds; RenderStats View; }` in `Session/PlaySession.h`; `IScriptHost::GetPerformanceStats()` (default `Unsupported`) is answered by `PlaySession` from the host's frame statistics, its own counters and its VM's heap.
- **Renderer:** `RenderStats` gains `VisibleLights`, `DroppedLights` and `SkinnedMeshes`, appended; `SceneRenderer::Render`'s stats block fills them from `SceneRenderStats::Lights` and `DroppedLights` and a new count of `RecordDeformStage`'s deformed meshes.
- **Script API:** `Application.GetStats() -> PerformanceStats` (alias of the struct's members, PascalCase), an error in a fixed-step gameplay callback (`GetParticleCount`'s rule and check), readable in `OnUpdate`, `OnLateUpdate`, test cases and evaluations; available in every configuration, Dist included.
- **`stats.get`:** `StatsGetResult` gains `activeBodies` and `particles`, `StatsViewSummary` `lights`, `droppedLights` and `skinnedMeshes`, appended (ADR 0042's `stats.get` row), filled from `SessionStatistics` and `RenderStats`; the editor's Stats panel shows them (the Runtime's F1 overlay, an ImGui view outside Dist, keeps its rows).

### 5. Presentation text (W28.1)

- **API:** `UiText:SetPresentationText(text: string?) -> ()` and `UiText:GetPresentationText() -> string?`, methods of a new `UiText` proxy type (`Scripting/Bindings/Ui.cpp`'s registration); nil clears. Both raise an error in a fixed-step gameplay callback (the readout's rule), and the text is at most `MaxScriptPresentationTextBytes` (4 KiB, `ScriptLimits.h`) of valid UTF-8.
- **Storage:** `UiSystem` keeps a map from entity id to presentation text beside its interaction state, never serialized, hashed (`AppendStateHash` leaves it out) or recorded; a scene replacement clears it, and an entry whose entity is gone or no longer holds a `UiText` is dropped at the next frame's UI layout.
- **Drawing:** `RenderExtractionRequest` gains a borrowed `UiPresentation` pointer (a `UiPresentationTexts`, `Scene/UiInteraction.h`), set where `UiInteraction` is, which `AppendUiDrawItems` reads to draw the presentation text in place of the element's `Text` (a text input's own text keeps precedence; an empty one draws no item); layout and hit testing keep the authored text and rect. `ui.tree`'s entries gain `presentationText` (appended after `active`): the play session's text, cut as `text` is, empty without one and in the edit scene; their `textBounds` measure what the element draws.

### 6. Frame-time signals (W28.1)

- **API:** `Input.PostSignal(name: string) -> boolean` posts a named signal for the next fixed step; it raises an error in a fixed-step gameplay callback (a fixed-step decision is deterministic and acts directly) and returns whether the session takes live signals. `Input.WasSignalled(name: string) -> boolean` reads, in the fixed step, the signals the tick latched and, in the frame phase, those latched by the ticks since the last frame (the frame view's rule). Names are 1 to `MaxScriptSignalNameBytes` (64) bytes of valid UTF-8; a name posted twice for one tick counts once, and a tick takes at most `MaxScriptSignalsPerTick` (64) distinct live signals, each later one a located error (both in `ScriptLimits.h`, which `PlayInput` reads).
- **Latch:** a signal is an input event of the new kind `PlayInputEventType::Signal` (`"Signal"`, member `name`), appended after `Text` (the registry enum `InputEventType` and the codec follow); `PlayInput::QueueSignal` queues a live one for the next tick as an injected event (never previewed by the frame view) and `ApplyTick` latches it in ApplyInput with the device input (no new phase), so `ReplayRecorder::CaptureAppliedInput` records it like any applied event; `PlayInput::WasSignalled(phase, name)` reads the step's or the frame's latch. `IScriptHost` gains `PostSignal` and `WasSignalled` (defaults: `Unsupported`, false), which `PlaySession` answers.
- **Which signals a session takes:** ordinary live play and recordings take live ones; replays, suites, FeatureTest runs and lockstep sessions without a recorder ignore them (`PostSignal` returns false) and take only those a replay plays back, a test injects (`Test.InjectSignal(name)`) or automation injects (`input.inject`'s event type `signal` with `name`).

### 7. The replay's version 4

- `ReplayFormatVersion`, `ReplayData::FormatVersion` and `ReplayImporter::Version` become 4; `ReplayFingerprintFormatVersion` stays 3. Version 4 adds the header member `SaveData` after `Config` (an object: the save-data store's contents at the recording's start, `{}` when empty; decision 8; canonical as `Parameters` are, numbers written as float by `JsonWriter`, so a recording's store is canonicalized at its start as its parameters are and every playback seeds the same values) and the event type `Signal` (cooked tag 9, its `Name` a string of 1 to 64 bytes). Readers accept versions 1 to 4; a file of version 1 to 3 migrates with an empty `SaveData`, and a `Signal` event in a file below version 4 is refused as an unknown type.
- Fixtures: `Tests/Data/Formats/Replay/v3.replay` and `v3.upgraded.replay` (new), `v1.upgraded.replay` and `v2.upgraded.replay` written again at version 4; `Replay.schema.json`'s `Version` and event types and the reference generator's replay example follow. FeatureTest's 14 scaffold-recorded replays are recorded again by `Scaffold.py`; the demos' eight committed replays are rewritten by a recorded `Editor --headless --project <P> --upgrade` on this branch, which the lander repeats on the merged tree if main changed them (the ledger's demo row). No hash moves (decision 10).

### 8. Save data (W28.2)

- **Script API** (`SaveData`, `RegisterSaveData` after `RegisterTerrain`): `Get(key: string) -> any` (nil when absent), `Set(key: string, value: any) -> ()` (nil deletes), `Delete(key: string) -> boolean` (whether it held the key), `GetKeys() -> {string}` (sorted), `Commit() -> (boolean, string?)` and `GetLoadError() -> string?`. Keys are 1 to 256 bytes of valid UTF-8; values are what `CheckJson` converts (nil, booleans, finite numbers, strings, arrays and string-keyed tables). Reads and writes work in every callback; the store serialized is capped at 1 MiB (`MaxSaveDataBytes`), a `Set` past it a located error naming the size.
- **Store:** `Session/SaveDataStore.{h,cpp}`, owned by the session and kept across `Scene.Load` and `Scene.Reload`; its values in key order, serialized by a double-preserving writer (nlohmann's shortest round-trip doubles, keys sorted, tabs), never `JsonWriter`. The file: `{"Format": "SaveData", "Version": 1, "Values": {...}}`.
- **Backends:** the Runtime's live session reads and commits `user://SaveData/Store.json` (published atomically and, on Windows, flushed durably through a new Platform hook, `PublishedFile::WriteDurably`, `Unsupported` on Linux and macOS: the write then falls back to the atomic write and logs once); a headless Runtime, the Dist smoke test among them, reads it and never writes it (`Commit` returns false with the reason). Editor play uses `<project>/Library/SaveData/Store.json`, and a `--read-only` editor a private temporary store that lives as long as the editor. Fixed-view sessions (suites, replays, recordings, lockstep, FeatureTest) use an in-memory store, empty by default: a suite seeds it through `Test.SetSaveData(values)`, a replay through its header, and a recording records the store it starts with (the editor's play store's contents, seeded by `saveData.set`), never the machine's real store; their `Commit` returns true and writes nothing.
- **Corruption:** an unreadable or invalid file is logged, moved aside as `Store.corrupt-<n>.json` (the first free `n` from 1), reported by `SaveData.GetLoadError()`, and the session starts with an empty store.
- **Methods** (editor, after M26's terrain methods, exposed as MCP tools): `saveData.get` (the editor's play store, or the running session's with `target: "play"`), `saveData.set` (seeds the play store: `values` replaces it, or merges with `merge: true`) and `saveData.clear`; an editor panel "Save Data" (its own file, registered by `EditorLayer.cpp`) lists, edits and clears the play store. `--read-only` editors seed their private store.

### 9. The session's audio mix (W28.2)

The mix belongs to the session: `PlaySession` records the engine's Music, Sfx and Ui volumes and sets them to 1 once at its activation, and restores them once at its end; a scene replacement builds the new `AudioSystem` without initializing the mix again, so the volumes a script set before `Scene.Load` or `Scene.Reload` hold after it, in editor play, the Runtime and an export alike. `AudioSystem::InitializeMix` and the restore move to the session's lifecycle (`AudioSystem` gains the session-owned mix's handover; ADR 0042's `AudioSystem` row). `SessionScriptingTests.cpp`'s case that pinned the reset is changed to the documented behaviour, and a regression test, "PlaySession: a group volume set before Scene.Load holds after it", fails before the fix; FeatureTest covers it in every run mode.

### 10. Determinism and the state hash

- The display calls never reach the hash (decision 3); the readout and presentation text are frame-phase reads and writes that the fixed step cannot make (errors), and presentation text is never serialized or hashed; signals are input, outside the hash as all input state is, recorded and played back.
- **The save-data block** follows the ui block in `ComputeStateHash`: nothing while the store is empty, else a marker ("SaveDat1") and each key and value in key order (the value's canonical text), so every committed hash stays. M35's world-pause block follows it whatever the landing order (the ledger).
- Every replay with a signal or a seeded store verifies in Debug, Release and Dist (decision 11's FeatureTest replays).

### 11. Run modes and FeatureTest coverage

- **Run modes:** every new script function is available in every run mode (`RunModes::All`), Dist included; the display calls do nothing in the editor and fixed-view sessions (decision 3), so FeatureTest's coverage observes their refusal there, and their effect is covered by the windowed child test and the Dist check (Acceptance).
- **FeatureTest:** scaffolds of M28's own, seeded from 2501 on (the ledger's 2500–2599), listed after main's and before `Suites.jsonl` and `Replays.jsonl`: suites that call every new function, method and their errors (gates 2 and 7 in every mode), a replay whose HUD shows the frame time through presentation text, a replay of a run ended by a signal, a suite that seeds the store and checks the gated branch, a replay whose game reads the store, and a suite that sets a group volume across `Scene.Load`. No new component, field, enum value or project setting, so gates 1, 1b, 4 and 8 change only by the replay's version (none); gate 5 gains the `saveData.*` methods' Python tests; gate 6 gains no code (a corrupt store is reported to scripts, not by `project.validate`); gate 9 gains no format (the two user-data files are engine-written, not imported).

### 12. Fuzz targets

## Departures from ADR 0042's design defaults

- **The replay's SaveData stores numbers as float** (decision 7): ADR 0042 has the header record the store's contents; the replay format writes every number as float (`JsonWriter`, §6), so a recording canonicalizes its store at its start, as it does its parameters, and a double the store held is rounded to float for the recording and every playback alike. The run still verifies whatever the machine's store holds; only a recording's starting values lose precision. Writing the header with a double-preserving writer would make the replay the only authored format with two number precisions.
- **The display calls return `(false, reason)` from `SetDisplaySettings` only** (decision 3): the getters return values where the calls do nothing (no modes, the view as a window), so an options menu populates in the editor too; a malformed request raises, as every binding's does.
