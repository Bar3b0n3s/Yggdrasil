### 3. Design defaults

Each default goes into its milestone's contract, which may change it only with a stated reason (ADR 0028 decision 15's rule).

**M28 Game services**
- **W28.1, display settings.** `Application` gains the window mode (Windowed, Borderless, Exclusive), the resolution from the monitor's mode list, which scripts can read, and VSync, each applied at a frame boundary.
  - **Platform:** a GLFW monitor and video-mode query and a set-mode call in `Platform/`, Windows backend only, reporting `Unsupported` on Linux and macOS (ADR 0028 decision 10; `PlatformWindowSupport` is the precedent).
  - **Swapchain:** `Swapchain::SetVSync` triggers a recreate, and `Application` keeps the chosen VSync, so device-loss recovery does not revert it.
  - **Persistence:** the engine persists the chosen display settings itself in `user://Display.json` and applies them when the Runtime starts, so a restored fullscreen mode never flashes a window first.
  - **Where the calls do nothing:** the editor's game view, headless runs and every fixed-view session (suites, replays, recordings, lockstep). There the calls return false with a reason and never touch the project's `Window` settings, so they never reach the state hash.
  - **Exclusive mode:** GLFW's monitor mode, without `VK_EXT_full_screen_exclusive`.
- **W28.1, performance readout.** A script call (for example `Application.GetStats()`) that returns frame time (CPU and GPU), visible, dropped and shadowed lights, draw calls, triangles, live particles, skinned meshes drawn (a new counter), bodies (all and active), entities and the script heap.
  - **Dist:** it is available in every configuration, Dist included. The readout's struct moves out of `Automation/` (whose symbols Dist forbids), and `CountSessionBodies` moves to Session.
  - **Phase rule:** `ParticleEmitter:GetParticleCount`'s rule applies: an error in fixed-step gameplay, readable in `OnUpdate`, `OnLateUpdate` and test cases.
  - **Parity:** `stats.get` gains the counters it lacks.
- **W28.1, presentation text** (brief 4's addition). A `UiText` shows a frame-paced value without reaching the state hash: a presentation string (C28.1 names the call, for example `UiText:SetPresentationText(text)`) that scripts set outside the fixed step only (the readout's phase rule: an error in fixed-step gameplay), drawn in place of `Text` while it is set, and never serialized, hashed or recorded, nor read by layout and hit testing, which keep the element's authored text and rect, so no frame-paced value reaches the UI's hashed state.
- **W28.1, decisions on frame time** (brief 4's addition: horde mode ends a run when the frame time stays over 33 ms). A decision taken on frame time is outside input, so it is recorded as input: a frame-phase call (C28.1 names it, for example `Input.PostSignal(name)`) posts a named signal that the next fixed step latches beside the device input, where gameplay reads it (for example `Input.WasSignalled(name)`). Signals follow device input's rule: live play and recordings take live ones, which `input.record` records; a replay plays back its recorded ones and ignores live ones; suites, lockstep and FeatureTest runs ignore live ones and take those a test injects through `Test` or automation through `input.inject`. The replay's version 4 (one version for M28's two waves: the store's seed and this event kind) carries them, so a horde run that ended on frame time verifies at its hash in every mode.
- **W28.2, save data.** A `SaveData` script namespace: get (nil when absent), set, delete, list keys, and an explicit commit.
  - **Values:** what Luau already converts to JSON, held by a session-owned store that survives `Scene.Load`. It is written by a double-preserving serializer (not `JsonWriter`, which writes 32-bit floats) and capped at 1 MiB with a clear error.
  - **Runtime:** the store file is `user://SaveData/Store.json`, published atomically and, on Windows, flushed durably through a new Platform hook (owner's answer 5).
  - **Corruption:** an unreadable file is logged, moved aside as `Store.corrupt-<n>.json`, reported to scripts, and the game starts empty.
  - **Determinism:** fixed-view sessions use an in-memory store, empty by default. A suite seeds it through its settings or `Test`; a replay header (format version 4) records the store's contents at the recording's start, so a replay verifies whatever the machine holds. The store's contents form a state-hash block that is empty when unused, so every committed hash stays.
  - **Editor play:** a store of its own in the project's `Library/`, a private temporary store in a `--read-only` editor, and methods to read, seed and clear it, with an editor panel (parity).
  - **Headless:** a headless Runtime, the Dist smoke test among them, reads the real store but never writes it.
  - **The session's mix** (brief 3's addition). `Scene.Load` and `Scene.Reload` keep the group volumes a script set: the mix belongs to the session, recorded and set to 1 once at its start and restored once at its end, not at each scene's replacement (today's `InitializeMix` on the new `AudioSystem`, a bug in editor play, the Runtime and an export alike), with a regression test that fails before the fix. A volume set in the game's options outlives the run only through the store.

**M29 Light limits**
- **Light cap.** A `Rendering` project setting for the shaded lights per view: 256, 512, 1,024 or 2,048, default 256.
  - The cluster mask's word count follows the setting at run time. The shaders already read the stride from `Clusters.Grid.w`, so only the CPU sizing and the light buffer change.
  - Validation, `stats.get`, the readout and every description that names a cap read the setting.
- **Shadowed lights.** 16 point lights and 16 spot lights per view, ranked by importance with hysteresis, so they stop popping.
  - **Point lights:** the four most important keep today's face size; the rest get half-size faces in a second cube array.
  - **Spot lights:** the existing 4096 atlas holds 16 tiles of 1024.
  - **Lookup:** each shaded light carries its shadow slot in `ShaderLight`'s padding, so the shader no longer searches the shadowed lights linearly.
- **Static shadow caching** (owner's answer 2b). A shadowed light that has not moved, with no caster in its range that moved or deformed, reuses last frame's map. The cache is renderer state that a history reset, a capture's warm-up and a device loss drop, so every capture and golden renders as before.
- **Below the old caps nothing changes.** The ClusteredLights, PointShadows and SpotShadows goldens, the brute-force equality case and the out-of-memory fallback stay byte-identical. The 32-pixel cluster tile is not included (it is compiled into the shaders; a later item if a game needs it).

**M30 Navigation**
- **Recast and Detour** (recastnavigation, zlib licence), vendored as two projects at a pinned release under the standing vendoring rules (owner's answer 3): Recast for the editor's bake only, Detour for the runtime.
  - Both join `CheckBuildConfig.py`'s precise-floating-point list with their FastMath fixtures and their ABI define families.
  - Their process-level allocator and assert hooks are set by `ProcessContext` and listed under §3 rule 5.
  - The vendored code's calls are audited for CRT transcendental functions: walkable slopes are marked first-party with `DetMath`, never by Recast's `cosf`, and a random point is picked first-party from a seeded `RandomGenerator`, never through Detour's global `frand` callback.
- **The bake input** is a pure Scene function over `ComposePhysicsBodies`: static, non-sensor, creatable bodies on the layers the bake names, each collider triangulated first-party in canonical order (primitives tessellated, mesh colliders' triangles, height fields through `TerrainGeometry`), in world space.
  - Its XXH64, together with the settings and modifiers, is stored in the asset and recomputed by `project.validate`, which reports `NAV_MESH_STALE` (and `NAV_MESH_NOT_BAKED`).
  - Triangulating first-party leaves M11's frozen `PhysicsShape.h` unchanged.
- **Asset.** A `NavMesh` asset type with a first-party, validated payload (polygons, detail meshes, areas, agent settings, input hash). Detour's data is built from it at load with `dtCreateNavMeshData`, never trusted as bytes. A `NavMeshData` fuzz target joins `Targets.json`; its fuzz case runs in every gate's unit suite, and no 1,000,000-iteration fuzz step runs in the program (answer 9).
- **Components.** A unique-per-scene `Navigation` component holds the `NavMesh` reference, up to four agent types (radius, height, maximum slope, maximum step) and the bake settings. A `NavModifier` component is a box (yaw rotation only) that is either not walkable or carries an area cost.
- **`navigation.bake`.** Like `lighting.bake`: CPU-only, so it works with `--renderer none`; one undoable step; byte-identical rebakes that write nothing; an editor menu action (parity).
- **The `Navigation` script namespace** is usable in the fixed step: `FindPath` (corners, or nil, plus the partial path to the closest reachable point), `ClosestPoint`, `Raycast` along the surface, and `RandomPoint` from a seeded generator. Queries read only the baked data and their arguments, so they are deterministic; a corner cap goes in `ScriptLimits.h`.
- **Debug view.** A navigation view flag for the scene view and an `annotate.navMesh` option for `viewport.screenshot`, drawn as polygon edges.
- **Cost.** A perf case with 150 agents each finding a path two or three times a second, measured within the 60 Hz fixed step.

**M31 Material parameters**
- **A new component,** not new `MeshRenderer` fields: they would re-hash nearly every 3D scene and force every replay's re-recording. Its fields: a tint (multiplied with the base colour), an emissive colour and strength (added), a texture-coordinate offset, and a scroll velocity that advances with simulation time. Simulation time is plumbed into render extraction.
- **GPU path.** The values ride in the instance record (grown from 144 bytes), so instancing keeps its batches and skinned meshes work unchanged. An entity without the component renders byte-identically.
- **Dissolve** (owner's answer 2d): an amount from 0 to 1 with an edge colour and width, over a new built-in noise texture, through the Mask variant in the forward and shadow paths.
- **Fade** (World Tree's brief 5, added 2026-11-15: a wall or pillar between the isometric camera and the player fades while it hides the player): an opacity from 0 to 1 drawn as a dithered (screen-door) alpha clip in the opaque path, through dissolve's Mask variant, so the faded entity keeps its depth, its sorting and its shadow and never moves to the transparent list; TAA resolves the dither.

**M32 Fog**
- **A new unique-per-scene `Fog` component,** not new `PostProcess` fields (they would change the canonical form of every scene with a PostProcess). Its fields:
  - exponential distance fog: density, start distance, maximum opacity;
  - height fog: density falling off above a base height;
  - colour, optionally tinted by the environment's ambient light;
  - a sun glow toward the first directional light;
  - whether the skybox is fogged.
- **Where it applies.** One `Common/Fog.slang` function, applied in the forward opaque and transparent shading, terrain, the skybox (optional), the SSR composite (multiplied by the transmittance) and the 3D sprites' quad pipelines through a fog constant buffer. Particles get fog in M33.
  - Distance is view depth, so an orthographic, isometric camera fogs sensibly.
  - Additive quads fade rather than tint.
  - World-space UI keeps its accepted no-fog limit.
- **What stays the same.** A scene without fog renders byte-identically. Probe and environment bakes exclude fog. The cost stays under 0.5 ms at 1920 × 1080.
- **Volumetric light** (the brief's stretch item) is not in M32 unless the owner keeps it (owner's answer 2a).
- **SSR's cost follows the glossy area** (World Tree's brief 09, added 2026-11-15; low priority, in M32 because M32 already owns the SSR pass's composite). The trace skips, early and per tile, every pixel above `SsrMaxRoughness` and the sky, so a mostly rough scene pays for its glossy pixels only, with the same image: the Ssr golden and every golden of a scene with SSR stay byte-identical. A `Rendering` project setting traces at half resolution, upsampled with GTAO's depth-aware filter, beside `SsaoHalfResolution` (a project setting, not a `PostProcess` field, which would change the canonical form of every scene that holds a PostProcess and move its replays' hashes); off by default, so nothing changes until a game turns it on. `stats.get`'s SSR row and M28's readout report how many tiles the trace covered.

**M33 Particle look**
- **A component of its own** beside the emitter holds every setting below, so `ParticleEmitter` stays v1 and no committed hash moves (the ledger's ParticleEmitter row).
- **Flipbooks:** a `SpriteSheet` and a clip or frame range, played over the particle's life or picked per particle, with optional blending between frames (two UV sets).
- **Rotation:** a random start angle and spin range, drawn from a second random stream of the emitter's, so the committed particle digests of FeatureTest's `ParticleEmitter` suite keep their values.
- **Soft particles:** a fade distance against the scene depth, in a dedicated particle program that reads depth as a shader input (§8.3 avoids read-only depth attachments).
- **Alignment:** camera-facing, stretched along velocity, or flat on a plane.
- **HDR:** an intensity multiplier, so colours above 1 bloom.
- **Fog:** applied in the particle program at M33's merge.
- **TAA:** particle motion vectors, which remove Backlog §6's "particles write no velocity" limit (owner's answer 2e).
- **Lit smoke** stays out (owner's answer 2f).
- **What stays the same:** particles stay presentation only, and their fields' defaults render the Particles golden byte-identically.

**M34 Characters and input**
- **W34.1, characters versus Dynamic bodies** (World Tree's brief 11, high).
  - **The inner body never moves a Dynamic body.** The solver never resolves a contact between a character's inner body and a Dynamic body, through the inner body's layer and filters (`Physics/CharacterController`, the object-layer and contact filters); the inner body keeps taking part in queries, sensors and contacts with Static and Kinematic bodies.
  - **Pushing goes through `CharacterVirtual`'s own contacts** and its mass (the component's `Mass`), with a push strength if C34.1 exposes one. A pushed light body slides along the ground at about the character's speed, never through static geometry.
  - **No launch.** A character standing on, or stepping onto, a light Dynamic body gains no upward velocity beyond what stepping up that body's height needs.
  - **The frozen header.** `Physics/CharacterController.h` is M11's frozen interface (ADR 0014 decision 8), so a change to it is reviewed as one.
- **W34.2, input** (World Tree's brief 10, low to medium).
  - **Triggers as buttons.** A Button action can bind a gamepad axis, down past a threshold and up again only below a lower one (hysteresis), so `IsActionDown`, `IsActionPressed` and `IsActionReleased` work for a trigger like any button. The hysteresis carries a binding's state from one latch to the next: input state, outside the state hash as all input state is, which a replay reproduces from its axis events.
  - **Bindings checked when set.** `project.setSettings` validates the input actions as `play.start` does (`InputActionMap::Create`) and refuses the patch, each problem located under `/patch`; `project.validate` reports the invalid bindings a project already holds, with a new validation code (C34.2 names it).
  - **A ray from an explicit pose.** `Camera:ScreenToWorldRayFrom(x, y, position, rotation)` builds the ray from the pose it is given instead of the rendered, interpolated one, with `ScreenToWorldRay`'s `DetMath` projection and the session's view size, which every fixed-view session keeps fixed, so gameplay can aim in the fixed step from a pose it computes there.
- **Determinism.** W34.1 changes what a character does to a Dynamic body it touches, and so the state hash of every run in which one does. No committed replay has a character: FeatureTest's 14 replays play scenes without a `CharacterController` (FeatureTest's characters are in `Components.scene`, `Physics.scene` and `Scripting.scene`, and in suites, which commit no hash), and no demo (Tetris, Rolling Ball, Breakout, NativeTest) holds one. So M34 re-records no committed replay and needs no bridge window; it keeps or updates the expectations of FeatureTest's character suites (the CharacterController and Physics cases, the `PhysicsCarry` scaffold's), and a FeatureTest replay another milestone records with a character touching a Dynamic body is recorded again by `Scaffold.py` at the later lander's merge. W34.2 moves no hash: an axis in a Button action's `Bindings` is refused today, so no committed replay uses one. World Tree's own replays (its Arena 1 tour) are the World Tree session's to record again (brief 11).

**M35 Pause and entity state**
- **W35.1, the world pause** (World Tree's brief 12, medium).
  - **The state.** A world pause that scripts set and clear and automation reads and sets, distinct from the host's session pause (`play.pause`, `play.state`'s run state `Paused`), which stops every tick; C35.1 names both so that no one confuses them (for example `Time.PauseWorld()`, `Time.ResumeWorld()` and `Time.IsWorldPaused()`, and `play.state`'s `worldPaused`). A change takes effect at the next fixed step, so a tick runs wholly paused or wholly not.
  - **What holds.** While the world is paused, the fixed step skips the world's phases: the native step, sprite and skeletal animation, the physics and 2D physics steps (bodies keep their velocities for the resume) and the particles' step. `OnFixedUpdate`, `OnUpdate`, `OnLateUpdate` and tasks (`Task.Wait`, `Task.Delay`) run only for the behaviours that ask to run while the world is paused (C35.1 names the opt-in), and the world's clock, which gameplay and tasks read, holds while the session's tick goes on.
  - **What runs.** The input, text, UI input, UI event and UI layout phases, the `OnUi*` callbacks, the start and destroy flushes (so a menu creates and destroys its own entities) and the transform updates, deterministic as today from latched input, so a replay of menu input during a pause reproduces it.
  - **Audio.** The pause chooses whether the world's playing voices pause (`AudioSystem::SetPaused`) or finish; the `Ui` group's voices play on, so a menu still sounds.
  - **Determinism.** The world pause and the world's held clock form a state-hash block after M28's save-data block, empty while the session has never paused, so every committed hash stays. `play.step` and test cases step through a pause (the UI advancing, the world not), and a replay that pauses verifies in every mode. A world pause set by automation during a recording or a replay is refused (`InvalidState`), so every replay reproduces its pauses from its scripts.
  - **Parity.** `play.state` reports the world pause beside its run state, and a method sets it (C35.1 names it), with its Python test; FeatureTest covers the calls, the opt-in and the held systems in every run mode.
  - **The time scale** is unchanged and independent of the world pause; `Docs/Backlog.md` §6's row on a time scale of 0 points at the pause as the way to freeze the world while the UI runs.
- **W35.2, entity state** (World Tree's brief 13, medium).
  - **An unflushed disable keeps the instances.** An entity switched off and on again before the disable is flushed keeps its behaviours' instances, so the instances `GetScript` returned are the ones that start, as Architecture §11's rule (instances recreated "when an entity is enabled after its disable was flushed") says; a regression test plays the brief's sequence (instantiate, switch off, switch on, call a method that writes fields, in one tick) and fails before the fix.
  - **A prefab instance's overrides apply together.** A rebuild applies an entity's component overrides as one write and validates the combined component, as `entity.update` with the same fields would; an override is stale only when its target is gone or the combined result is invalid (then C35.1 decides which overrides drop, each one reported). Each dropped override is reported in `scene.open`'s `diagnostics` and in the result of every editor path that rebuilds instances (`prefab.apply`, `prefab.revert`, an import or reimport of a prefab, through `EditorContext::UpdatePrefabInstances`, and `edit.undo` and `edit.redo` when they step over a prefab write), not only in the log.
  - **A script-field patch at instantiation** (brief 13's third item, added after the fork, before W35.2 began; decision 6): `prefab.instantiate {components}` merges a patch into a script slot after the instance's member references are mapped, so the slot's other entity fields name the instance's own members; a reference that cannot be stored is refused with its error, never kept behind a warning. The brief's case (a `Warden` field patch leaving `Menus` naming the instance's own `Menus`, with nothing logged) is its regression test.
  - **Determinism.** The instance fix changes a run only where a script writes to an entity it switched off and on in one tick; C35.1 finds, with a test, which committed replays (FeatureTest's and the demos') do so. FeatureTest's are recorded again by `Scaffold.py` at M35's merge; a demo's would need a bridge window, which the lead coordinates with the World Tree session. The overrides' fix changes only what a scene holds after a rebuild in the editor.

## Risks

- **Recast and Detour's determinism and trust.** Byte-identical bakes and identical paths in Debug, Release and Dist depend on the vendored float code under the precise model; the audit at vendoring and a committed path digest in FeatureTest catch a difference early. Detour data is rebuilt from a validated first-party payload, never trusted.
- **Display modes on the one test machine.** Exclusive fullscreen and resolution switches can disturb the desktop the GPU suites run on. Windowed child tests cover them in a guarded way, and the destructive cases stay out of the default suites.
- **Byte-identity below the old caps.** Growing the light buffers, the instance record and the quad constants must not reorder floating-point work; the existing goldens, the brute-force equality and FeatureTest's byte-compared probe bakes are the guard.
- **The shadow cache's invalidation.** A missed caster change shows a stale shadow. Captures and goldens never use the cache, so a dedicated test moves each kind of caster (transform, skinning, morph, visibility) and checks the map is redrawn.
- **Two sessions in one checkout.** The World Tree session works in `D:\Engine`; the program works in worktrees and never touches `Projects/WorldTree`. The bridge stays the World Tree session's, and milestone FeatureTest work uses `Scaffold.py`'s own editors.
- **The hardening it skips** (answer 9). No gate of the program runs AddressSanitizer, the debug heap's GPU run, the 1,000,000-iteration fuzz of its readers or the 10,000-tick soak, so a heap error, a reader crash that 10,000 mutations miss, a slow leak (navigation agents, particles, fog, the save store) or a GPU object's lifetime fault reaches main unseen until a later hardened gate. What still guards it: the unit suite's fuzz cases (each reader's 10,000 seeded mutations in Release, a tenth of them in Debug), the gpu suite under the validation and synchronization layers, which fails a test case on any GPU object still alive at its end, and `Docs/Backlog.md` §3's row, which keeps the debt in view.
- **Eight milestones at once.** Four of them (M29, M31, M32 and M33) change the same renderer files, which the ledger divides by region rather than giving whole to one owner; each later lander runs the gpu and golden suites on its merged tree, where the existing goldens and the brute-force equality catch a merge that moved a pixel.
- **Characters versus Dynamic bodies** (M34). Taking the inner body out of the solver's contacts with Dynamic bodies changes how every character meets them, so a game whose characters relied on today's push (or a replay recorded with it) behaves differently; no committed replay has a character (decision 3), FeatureTest's character suites are M34's to keep green, and World Tree records its own replays again. The change goes through M11's frozen `CharacterController.h`, reviewed as a frozen interface.
- **The world pause's reach** (M35). A world system the pause does not skip keeps moving behind a menu; the ledger's execution-order list names every phase as the world's or the UI's, FeatureTest's pause case checks that bodies, particles, animators, tasks and sounds hold, and a phase or system a sibling adds is classified at the later lander's merge.
- **The instance fix** (M35). Keeping instances across an unflushed disable changes a run that wrote to an entity switched off and on in one tick; a test finds the committed replays it moves before the fix lands, and World Tree undoes its own workaround.
