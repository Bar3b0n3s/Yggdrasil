# 0015 — M12 contract decisions

- **Status:** proposed by the M12 contract task; the streams implemented against decisions 1 to 22, and the integration task (the contract owner) added decisions 23 to 28 for what changed after the freeze (Roadmap rule 3). The amendments listed at the end are for the docs owner.
- **Date:** 2026-10-08
- **Context:** The M12 contract task (Roadmap rule 3) froze the public interface of the audio milestone: the Audio module (`Engine/Source/Engine/Audio/`), the audio clip asset, the audio and sound-effect importers, `Scene/AudioSystem`, the play session's audio hook, `audio.stats`, `asset.create {type: SoundEffect}` and the asset browser's preview. It vendored stb_vorbis (approved in `Docs/Decisions/0001-approvals.md`), implemented the built-in silent clip, wired every registration and call site so the streams touch no shared file, and wrote every Roadmap M12 and §10.4 acceptance test as a skipped skeleton (C++ and Python). Writing complete headers exposed places where the Architecture and Roadmap are silent or cannot be followed literally; `AGENTS.md` ("Deviations") requires a record of each.

## Decisions

### 1. Files and module placement

- **`Audio` (layer 1, includes Core only):** `AudioTypes.h` (header-only vocabulary: the mixing format, `MaxAudioVoices`, `Attenuation`, `AudioGroup`, `AudioSpatialization`, `AudioListenerPose`), `AudioEngine.h|.cpp`, `AudioVfs.h|.cpp`, `AudioDecoder.h|.cpp` (probing and decoding encoded files for the importer, and decoding the clips the engine decodes at registration) and `SoundSynth.h|.cpp`. The miniaudio glue goes under `Audio/Private/`. No public audio header names a miniaudio type (§3 rule 3): every miniaudio object lives behind an opaque `State`.
- **`Asset`:** `AudioClipData.h|.cpp` (the loaded clip, its cooked payload, the silent clip). Asset cannot include Audio (§3), so it has its own `AudioClipEncoding`; `Scene/AudioSystem.h`'s `MakeAudioClipSource` maps a clip to the engine's `AudioClipSource`.
- **`AssetPipeline`:** `Importers/AudioImporter.h|.cpp` and `Importers/SoundEffectImporter.h|.cpp`, which also holds the `.sfx` document functions (decision 11).
- **`Scene`:** `AudioSystem.h|.cpp`; the runtime component `AudioSourceRuntime` of §5.3 is private to it (`Scene/Private/`, stream C), so its content is not frozen (ADR 0006 decision 8 left it to M12).
- **`Automation/Methods`:** `AudioMethods.h|.cpp` (`audio.stats`, in the Runtime subset).
- **EditorCore:** `Audio/AudioPreview.h|.cpp`.
- **Tests:** `Tests/Source/Support/AudioTestData.h|.cpp` (deterministic tones and WAV files built in memory with DetMath, implemented by the contract), and the skeletons of decision 22.
- No `ModuleRules.json` or `Dependencies.lua` change was needed: Scene and AssetPipeline already may include Audio, and miniaudio is already Audio's private third-party library.

### 2. Ogg Vorbis through stb_vorbis

The approvals record (`0001-approvals.md`) approved stb_vorbis and states that Appendix C's fallback ("OGG rejected with a conversion hint") is not needed. The contract vendored `stb_vorbis.c` v1.22 from github.com/nothings/stb at the stb commit already pinned in `Vendor/stb/VENDOR.md` (SHA-256 `4c7cb2ff…5636`, byte-identical to miniaudio 0.11.25's `extras/stb_vorbis.c`) and built it the way `miniaudio.h` documents: the miniaudio project compiles the local translation unit `Vendor/miniaudio/miniaudio_vorbis.c` (the stb_vorbis declarations, `MINIAUDIO_IMPLEMENTATION` + `miniaudio.h`, then the stb_vorbis implementation) instead of upstream's `miniaudio.c`, which stays vendored unmodified. `MA_HAS_VORBIS` is decided inside miniaudio's implementation section, so no consumer struct or define changes (`CheckBuildConfig.py` is unaffected). stb_vorbis adds no MSVC warning; the existing C4244 suppression moved with the translation unit. Both `VENDOR.md` files and the approvals table record it. `AudioImporter` therefore takes `.ogg` (Ogg Vorbis; Ogg Opus is refused with a conversion hint).

### 3. The engine, its device and the context step

- `ma_engine` is always device-less, 2 channels at 48 kHz (§10.1). `AudioEngineSpecification::Device` is `None` (headless processes and tests), `System` (windowed runs) or `Null` (miniaudio's Null backend as a real device thread, for §10.4's device tests); `Decoding` is `Deterministic` (`MA_RESOURCE_MANAGER_FLAG_NO_THREADING`, jobs processed inline before every pull) or `Threaded`.
- **`EngineContextStep::Audio`** follows Graphics (§4.1: "… GraphicsDevice → AssetManager → AudioEngine"; the AssetManager is injected, not a step). `EngineContextSpecification::Audio` is optional: without it the context has no engine (`GetAudioEngine()` null), which keeps the hundreds of in-process contexts of the unit tests free of miniaudio; every Application has one. The engine is the context's last member, so it is destroyed first and its device thread stops before anything else goes.
- **`ApplicationSpecification::Audio`** (optional) overrides `GetDefaultAudioSpecification(WindowMode)`: windowed runs get `System` + `Threaded`, headless runs `None` + `Deterministic` (§10.1). No command-line option was added. Tests that start windowed applications in-process pass `None` (the windowed Application child does), so no test touches the machine's audio device (§15.1 T1); every Editor and Runtime process the tests start is headless. (Amended by decision 23: the engine option `--audio-device` exists, and windowed Editor and Runtime processes that tests start pass `--audio-device none`.)
- **Teardown (§4.1):** destroying the engine with live voices is a programmer error (asserted); play sessions and the preview release theirs first. Tests stop their voices before the engine goes.

### 4. Device notifications and re-creation

- The device's `notificationCallback` (miniaudio's device thread) only queues the notification in the engine; `AudioEngine::Update` handles the queue on the main thread. This is §10.1's "posts to the main thread" without the `MainThreadQueue`, whose closures would have to outlive the engine.
- `Rerouted` is logged at Info and changes nothing. An unexpected `Stopped` uninitializes the `ma_device` (`AudioDeviceState::Recreating`) and schedules a re-creation `DeviceRecreationDelaySeconds` (1 s) later on Update's clock; a failed attempt schedules the next one 1 s later; after `MaxDeviceRecreationAttempts` (3) failed attempts the engine gives up with exactly one warning (`AudioDeviceState::Failed`, time source Host). A device that cannot be created at startup is the same warning, and `Create` still succeeds. `Started`, the interruptions and `Unlocked` are logged at Trace.
- While `Recreating`, nothing reads the engine, so every voice holds its cursor: §10.4's "a voice keeps playing with an unchanged cursor".
- **Clock:** `Update(nowSeconds, deltaSeconds)` gets the frame clock's accumulated unscaled time from `Application` (a ManualClock in headless runs, so the delay is deterministic there, and tests pass chosen times), never the wall clock.
- **Test instrumentation (§10.4 "a fake notification source"):** `InjectDeviceNotification` (thread-safe, a `Stopped` injected this way counts as unexpected), `InjectDeviceCreationFailures` for re-creations, and `AudioEngineSpecification::InjectedDeviceCreationFailures` for the startup creation. Applications never use them.

### 5. Time ownership

- **Three time sources, one reader at a time:** `Device` (the callback reads in real time), `Simulation` (`BeginSimulationTime(fixedHz)`; the callback outputs silence without reading the engine, waiting for a read in progress first; `AdvanceSimulationTick` pulls) and `Host` (no device: `Update` pulls the frames of each frame's unscaled delta with a fractional accumulator; tests pull with `ReadFrames`). `ReadFrames` is `InvalidState` while the device reads.
- **Exact tick accumulator:** after n ticks at F Hz the engine has pulled exactly round(n × 48000 / F) frames, rounded half up, computed in integers. That is 800 per tick at 60 Hz (§10.1's example) and makes the "fractional accumulator" exact for every integer FixedHz (the project setting is an integer).
- **Owner:** the play session owns simulation time while it is in lockstep (`PlaySession::SetLockstep`: automation lockstep, an in-process lockstep driver) and, for its whole life, when `PlaySessionSpecification::OwnsAudioTime` is set: §10.1's "or a test run is active". M13's FeatureTest runner sets it for every suite, because a suite with a `Clock` runs on a `ScriptedClock` and is not in lockstep (§11.10). A paused session that is not in lockstep (Runtime `--paused`, Step(n) of a paused editor session) does not take time: its voices are paused (§10.2) and `play.step` advances only the simulation. A lockstep session's voices follow its ticks whatever its paused flag (`play.start {lockstep: true, paused: true}` is accepted and `play.resume` is refused in lockstep, so `play.step` is its only clock).
- **Pulls per tick, not per frame:** the session remembers the tick up to which the engine has pulled, and each `AudioUpdate` phase pulls one tick of frames for every tick run since (one per `Tick`, 0 to `MaxStepsPerFrame` per frame of a `ScriptedClock` suite). Ticks run before the session took time are never pulled.
- **Order against the device:** voices pause before time goes back to the device and resume only after the session has taken it. `PlaySession::Create` starts the `AudioSystem` with its voices held (paused) until the first `AudioUpdate` phase, so the paused and lockstep state a host applies after `Create` (`EditorPlayController`, the Runtime's `--paused`) is in force before a voice can reach a device, and PlayOnStart cursors are 0 at tick 0. `play.pause` and a lockstep owner's disconnect call `SetPaused(true)` before `SetLockstep(false)`, and the session's destructor releases the voices before it gives time back.
- **Capture (Test.CaptureAudio, M13):** `StartCapture`/`StopCapture` record every frame the engine pulls itself, never the device's reads, up to 10 minutes (`AudioCapture::Truncated` after that); `MeasureAudioLevels` gives `{RmsLeft, RmsRight, Peak}`.
- **Open point for M13:** a test run in a *windowed* editor has a `Threaded` resource manager (§10.1 keeps the job thread for windowed runs), so streams there do not decode at a deterministic point. M13 decides whether windowed editors create their engine `Deterministic` or the runner refuses streamed clips; nothing in M12 depends on it.

### 6. Clips and the AudioVfs

- A clip is named by the 16 hex digits of its `AssetHandle` and has a version (`AssetManager::GetVersion`); registrations are reference-counted (each `RegisterClip` balanced by `UnregisterClip`), and a hot-reloaded version is a new registration while voices of the old one keep playing it.
- **Resource names carry the version.** miniaudio never replaces the data of a name that is already registered: `ma_resource_manager_data_buffer_node_acquire` finds the existing node, adds a reference and skips loading, and the node outlives an unregister while a sound uses it. So the engine registers each version under `MakeAudioResourceName(Name, Version)`, `"<16 hex digits>@<version>"`, with miniaudio and in the `AudioVfs`; `AudioClipSource::Name` and `AudioVoiceInfo::ClipName` stay the bare 16 hex digits, and a name containing `'@'` is refused.
- **Decoded once at registration.** Registered encoded data stays encoded (`ma_resource_manager_register_encoded_data` is "the raw file data"), and every voice built on it would run its own decoder; `MA_SOUND_FLAG_DECODE` has no effect on a name that is already registered. So an `Encoded` clip without `Stream` is decoded once in `RegisterClip` with `Audio/AudioDecoder`'s `DecodeEncodedAudio` (interleaved f32 at the clip's own rate and channels, on the calling thread in both decoding modes; such a clip is at most `MaxDecodedClipSeconds` by default) and registered with `ma_resource_manager_register_decoded_data`, as `Pcm16` clips are. `register_encoded_data` is not used. The resource manager decodes streams to the same f32 (`decodedFormat = ma_format_f32`, rate and channels 0), so streamed and decoded playback of one clip are sample-identical.
- **Streaming needs the VFS.** miniaudio's resource manager finds registered data only for data buffers; data streams (`MA_SOUND_FLAG_STREAM`) always open their file through the VFS. So a streamed clip's bytes are served by the `AudioVfs` as a memory file under its resource name, and every other name resolves through the engine VFS (`project://…`, `engine://…`). That is §10.1's "custom ma_vfs backed by the engine VFS": loose files (through their cooked cache entry) and `Game.pak` entries play through identical code.
- The bytes are shared, never copied: `MakeAudioClipSource` hands the engine an aliasing pointer that keeps the loaded `AudioClipData` alive. The engine keeps a registration's data (those bytes, or the PCM it decoded) until the registration is removed and its last voice has ended.

### 7. Voices and stealing

A `HandlePool` of 64 voices. A full pool steals the voice with the lowest priority, then the farthest from the listener (non-spatial voices count as distance 0), then the oldest (the smallest start sequence), but only when that voice's priority is not above the new one's; otherwise `PlayVoice` fails with InvalidState. Priorities: `AudioSystemEffectPriority` 0 (Sfx and Ui sources, every one-shot), `AudioSystemMusicPriority` 1 (Music sources), `AudioPreviewPriority` 2 (the editor's preview), so effects never steal the soundtrack and a game never cuts off what a user auditions. A voice that reaches the end of a non-looping clip is released at the end of the pull that played its last frame (or the next Update) and its handle becomes stale. `AudioVoiceDescription::Owner` is an opaque number the engine only reports; AudioSystem stores the source entity's UUID so `audio.stats` can name it.

### 8. Shared enums moved down

`Attenuation` and `AudioGroup` moved from `Scene/Components/AudioSourceComponent.h` to `Audio/AudioTypes.h` (names, values and registrations unchanged; the component header includes it), as did the registration's `MinAudioDistance` and `MinAudioPitch`, so the ECS-agnostic engine validates voices with the component's bounds without a second enum and a mapping.

### 9. The audio clip asset and the built-ins

- **`AudioClipData`** (frozen): `Encoding` (`Pcm16`, `Wav`, `Flac`, `Mp3`, `Vorbis`), `SampleRate` (8 to 192 kHz), `ChannelCount` (1 or 2), `FrameCount`, `Stream` and `Bytes` (the original file, or the PCM). Payload v1: `uint8 Encoding; uint8 Stream; uint16 Reserved; uint32 SampleRate; uint32 ChannelCount; uint64 FrameCount; uint64 ByteCount; bytes`. The loader is registered in `RegisterBuiltinLoaders` by the contract.
- **Built-in handles (frozen):** the ten presets `0x0241`–`0x024a` (Click, Blip, Coin, Jump, Hit, Explosion, PowerUp, LineClear, Win, Lose, as ADR 0010 reserved them) and the silent clip `0x024b`, `engine://Audio/Silence`: 0.1 s of 48 kHz mono 16-bit zeros, a procedural built-in implemented by the contract and `GetPlaceholderHandle(AudioClip)` (§7.2's "silent clip"). The presets are `File` entries (`Resources/Audio/<Name>.sfx` through `SoundEffectImporter`), added with their files and their `EngineAssets.json` entries by stream B; the engine cooked cache and `Engine.pak` then carry them like the font (§7.6).

### 10. The audio importer

- Extensions `.wav`, `.flac`, `.mp3`, `.ogg`; the format is detected from the bytes, so a mislabelled file imports as what it is. The import probes and validates the whole file through `Audio/AudioDecoder` (every frame decoded once), so AssetPipeline never includes miniaudio; the cooked clip keeps the original bytes (§6.8).
- **`AudioImportSettings {Stream: AudioStreamMode}`** with `Auto` (stream above `MaxDecodedClipSeconds`, 10 s), `Stream` and `Decode`. §7.4 describes a boolean "Stream" whose default depends on the clip's length, but a `.meta` is written before the import knows the length; `Auto` is that default, resolved by the import.
- Refused with `ImportFailed` and the decoder's message: corrupt or truncated files, other Ogg codecs, more than two channels ("convert to mono or stereo"), sample rates outside 8 to 192 kHz.

### 11. Sound effects (`.sfx`) and the synthesizer

- **Format (§6.6, frozen):** the registry structs `SoundEffect` (`Seed`, `Volume`, `Layers`), `SoundLayer` (`Wave`, `DutyCycle`, `Notes`, `Duration`, `StartFrequency`, `EndFrequency`, `Volume`, `Envelope`, and two keys §6.6 does not show: `LowPass`, §10.3's "optional low-pass", and `Delay`, a layer's start offset) and `SoundEnvelope`, and the enum `SoundWave`. The Audio module includes only Core, so `SoundEffectImporter::RegisterTypes` registers them (contract-implemented, called by `RegisterAssetPipelineTypes`); stream B adds `ValidateSoundEffect` as the struct's Validate hook. The document functions (`SoundEffectToJson|ToText|FromJson|FromText`) mirror the material ones and are what `asset.create`, `asset.getProperties` and `asset.setProperties` use.
- **Semantics** (`SoundSynth.h`, frozen because every `.sfx` depends on them): notes `"<Name><Octave>:<seconds>"` in equal temperament (A4 = 440 Hz) or `"R:<seconds>"`, played back to back; a tone of `Duration` sweeping exponentially otherwise; a linear ADSR per note whose release follows the note's end (tails overlap and sum); Sine, Square (duty), Triangle, Saw, and Noise as seeded sample-and-hold at the frequency (layer i's generator: `Random(Hash64(Seed, i))`); an optional one-pole low-pass; the sum times `Volume`, clamped and quantized half away from zero to 48 kHz mono 16-bit. Limits: 1 to 16 layers, 256 notes per layer, 10 s (`MaxSoundEffectFrames`, 480,000 frames).
- **Timing in whole frames:** every duration (each note's, `Duration`, `Delay`, `Attack`, `Decay`, `Release`) is converted to frames once from its stored float, F(s) = floor(double(s) × 48000 + 0.5) (exact in double), and notes, envelope segments, layer spans and the sound's length are sums of those frames; `ComputeSoundEffectFrameCount` is the length, `ComputeSoundEffectDuration` that over 48,000. A rule over seconds such as ceil(duration × 48000) lands one frame off for ordinary decimals: the acceptance sound `"A3:0.05"`, `"E4:0.1"` with the default 10 ms release sums to 0.16000000201 s in floats and would give 7,681 frames, where the frame rule gives 2,400 + 4,800 + 480 = 7,680, the length `test_sound_effect_create_and_play_in_lockstep` asserts. The envelope's segment boundaries are given in frames too, so the semantics are bit-exact.
- **Determinism:** the synthesizer uses Core/DetMath (no CRT transcendental functions) in double precision, so "SoundSynth: presets hash to committed values" holds in every configuration and on every platform, not only within one build.

### 12. AudioSystem

- One per Play session, owned by `PlaySession` (none in Simulate mode, §5.6, and none without an engine), constructed infallibly over the session's scene; it connects to the registry's construct and destroy signals of `AudioSourceComponent`.
- **Sources:** `Start` plays the scene's `PlayOnStart` sources in canonical order (§5.6); a source created later with `PlayOnStart` starts at the first Update after it exists; a source whose entity becomes effectively disabled is released and a `PlayOnStart` source starts again when re-enabled; destroying the component or entity releases the voice at the destroy flush; every Update applies every field (a changed `Clip` restarts a playing voice with the new clip) and, for spatial sources, the world position, the forward axis (−Z) and the velocity from the world-position delta over the frame's delta (0 for a zero delta). (Amended by ADR 0016 decision 8: the position, the axis and the velocity come from the rendered (interpolated) pose, as the listener's do, and a pose that stops interpolating has no velocity for that frame.)
- **Listener (§10.2):** the first active primary `AudioListener` in canonical order, else the primary camera, else the origin pose (`SelectAudioListener`).
- **One-shots (§11.5):** non-spatial without a position, spatial with default `AudioSpatialization` at it, group `Sfx` unless given.
- **Pause and stop:** `SetPaused` pauses and resumes every voice of the system (new voices start paused; idempotent); script-level `Pause` survives a session resume; destroying the system is Stop.
- **Mixer (§11.5 `Audio.SetGroupVolume`/`GetGroupVolume`, bound in M13):** `AudioSystem::SetGroupVolume` and `GetGroupVolume` are the session's route to the engine's group volumes. `Start` records the engine's Music, Sfx and Ui volumes and sets them to 1, and destroying the system restores them, so every session and FeatureTest capture starts from the same mix (§11.10 restarts the scene between suites) and Stop leaves the editor's mixer as it was. Binding the script API straight to the per-context engine would leak a game's mix into Edit mode, the preview and later sessions. The Master volume stays the host's.
- **Clips:** loaded through `GetOrPlaceholder<AudioClipData>` (a missing clip records its diagnostic once and plays the silent clip, §10.4), registered once per (handle, version), unregistered at destruction.
- **Validation (§13.7):** `AUDIO_NO_LISTENER` (Warning, not fixable: spatial sources, no primary listener and no primary camera) and `AUDIO_MULTIPLE_PRIMARY_LISTENERS` (Warning, fixable: one issue per extra primary listener, the fix clears `Primary` on each), produced by `FindAudioSceneIssues` and reported and fixed by `ProjectValidator`. §5.3 calls the first in canonical order the winner, so a warning (not an error like `SCENE_MULTIPLE_PRIMARY_CAMERAS`) fits a scene that still plays as authored.
- Scene is a simulation-path module (§4.12), so AudioSystem uses no CRT transcendental function; audio is not simulated state and never reaches the state hash.

### 13. The play session's audio hook

Wired by the contract in `Session/PlaySession.cpp` (real code calling the frozen interfaces, which stay no-ops until streams A and C land), as `PlaySession.h`'s "Audio" paragraph documents:
- `PlaySessionSpecification::Audio` (the context's engine; null: a silent session) and `OwnsAudioTime` (a test run, decision 5); `GetAudioSystem()` (named after what it returns, since the specification's `Audio` is the engine) and `IsAudioTimeOwned()`.
- `Create` builds the `AudioSystem`, holds its voices (paused), takes the engine's time for a test run, then calls `AudioSystem::Start`; the first `AudioUpdate` phase releases the hold.
- The `AudioUpdate` phase runs `AudioSystem::Update(frame.DeltaTime)`, then, while the session owns audio time, one `AdvanceSimulationTick` per tick run since the last pull.
- `SetPaused` and `SetLockstep` apply one rule: voices paused while held or while paused and not in lockstep; audio time owned while in lockstep or a test run; voices pause before time goes back and resume after it is taken.
- The destructor releases the `AudioSystem` (voices, clips, group volumes) and then gives time back.
- `EditorPlayController` and `RuntimeApp` pass `EngineContext::GetAudioEngine()`. `play.pause` (`PlayMethods.cpp`) and `ReleaseDisconnectedLockstep` (`SharedMethodSupport.cpp`) pause before they leave lockstep.

`PlaySession.cpp` and those two call sites are not a stream's files in M12; a change goes through the contract owner.

### 14. The application's frame

`Application::OnFrameUpdate` calls `AudioEngine::Update(accumulated unscaled time, unscaled delta)` after `OnUpdate`, so the frame phase's `AudioSystem::Update` (inside `OnUpdate`) has set the voices before a device-less engine pulls the frame. The host pull is unscaled because it stands in for a device, which plays in real time whatever the time scale.

### 15. audio.stats

- A shared method (`Engine/Automation/Methods/AudioMethods.h`), `NoParams`, read-only, `AllowedInBatch`, `AvailableInRuntime`, not an MCP tool (§13.8 does not list it; agents use `engine_call`). The result: device state and name, time source, sample rate, master and group volumes, voice count and capacity, stolen and pulled frames, and every voice with its handle (16 hex digits), clip (`AssetSummary`), owning entity (`EntitySummary`, empty for one-shots and previews), group, volume, pitch, loop, spatial, position (empty when non-spatial), paused, streamed, priority, cursor and length in frames. 64-bit counters saturate (ADR 0008 decision 8). Unsupported when the host has no engine.
- `AutomationMethodContext::GetAudioEngine()` is a reviewed addition at the end of the class (the editor's and the Runtime's overrides and the test stub's are wired); `RuntimeAutomationServerSpecification::Audio` carries the Runtime's engine.
- As in M6 and M7 (ADR 0012 decision 13), the contract's `RegisterAudioMethodTypes` and `RegisterAudioMethods` are stubs that register nothing, already called from `RegisterSharedMethods.cpp`, so the catalogue and the coverage gate are unchanged until stream C registers the method with its tests and regenerates `Tools/MCP/catalog.json`.

### 16. Sound effects through the asset methods

`asset.create {type: "SoundEffect", path, values?}` writes the canonical `.sfx` of `values` over the defaults, which must pass `ValidateSoundEffect` (at least one layer; every violation `InvalidParams` located under `/values`, amended by decision 28 to `Validation`, as for a material); the new asset is an `AudioClip` imported by `SoundEffectImporter`. `asset.getProperties` and `asset.setProperties` read and merge-patch a `.sfx` like a material (`AssetMethods.h` documents it). The registry entry text "not supported by this editor yet" of `AssetCreateType::SoundEffect` changes with the implementation (stream C), and so does the refusal checked by "AssetMethods: asset.create supports dry runs and rejects bad paths and values".

### 17. The asset browser's preview

`EditorCore/Audio/AudioPreview` (`EditorContext::GetAudioPreview`, null without an engine): one preview at a time, played once, non-spatial, Ui group, `AudioPreviewPriority`, through `AssetManager::Load` (a missing or broken clip is an error the panel shows, never the silent placeholder). `EditorContext::Update` forgets a finished preview; `CloseProject` stops it. No automation method: it is a UI convenience of M10's panel, and `audio.stats` shows a playing preview.

### 18. Test fixtures

- `AudioTestData` builds deterministic tones (PCM and WAV) in memory. `EditorTestFixture` and `AutomationFixture` take an optional `AudioEngineSpecification`, so editor tests opt into an engine.
- Format fixtures (stream A, with the decoder they test): `Tests/Data/Assets/Audio/Tone.wav` and `Tone.flac` from a committed stdlib generator `Tests/Data/Generate/MakeAudioFixtures.py` (FLAC with verbatim subframes is writable without a library), and `Tone.mp3` and `Tone.ogg` as small pinned files from an official upstream source with their licence and SHA-256 in `Tests/Data/LICENSES.md` (standing download permission, `0001-approvals.md`). They also make the cross-importer sweep "Importers: importing twice gives identical hashes" cover the audio importer.

### 19. Members of frozen headers

As in M2 and M5 to M7, stateful frozen classes keep their state behind an opaque `struct State; Scope<State> m_State;` (`AudioEngine`, `AudioVfs`, `AudioSystem`, `AudioPreview`). Every stub body starts with `ENGINE_CONTRACT_STUB();`, the constructors and destructors that still owe documented work included (`~AudioEngine`, the `AudioSystem` constructor and destructor, `~AudioPreview`), so the strict gate catches them too. Stubs fail fast and never open a device, start a thread or write a file: `AudioEngine::Create` returns Unsupported, and `EngineContext::CreateAudio` is a stub that creates no engine, so no application or test has one until stream A lands. Private members and `State` may change without review; public and protected declarations may not.

### 20. What the contract implemented

The stb_vorbis vendoring; `AudioTypes.h`; every `*ToString`; `MakeAudioResourceName`; `GetAudioClipDuration` and `CreateSilentAudioClip` with the silent built-in, its catalogue entry and `GetPlaceholderHandle(AudioClip)`; the AudioClip loader registration; `AudioImporter::RegisterTypes`, `SoundEffectImporter::RegisterTypes` and both importers' `GetExtensions`; `GetDefaultAudioSpecification`; the `EngineContext` step, accessor and `Application` wiring; the PlaySession hook with the pause-before-leaving-lockstep order of `play.pause` and the disconnect (decision 13); `GetAudioEngine` on every automation context; `EditorContext::GetAudioPreview` with its creation, update and stop; `EditorPlayController`'s and `RuntimeApp`'s engine hand-over; `RegisterSharedMethods`' audio calls; the test fixtures of decision 18. Tests of these run unskipped from the contract on.

### 23. Frozen headers: reviewed changes

No frozen declaration changed except `App/Application` (below); the other changes are comments that now say what the implementation does.

- **`Audio/AudioEngine.h`:**
  - "Clips": every voice is an `ma_sound_init_from_file` on the registration's resource name, which acquires the same data buffer node (what `ma_sound_init_copy` does inside); nothing decodes on the fly.
  - "Time" and "Deterministic decoding": a pull longer than 10 ms (480 frames) is read in chunks of at most 480 frames, with the pending jobs processed before each chunk, and `Update` processes them too. A stream's next page is then decoded before the mixer needs it, whatever the pull's length and when the device reads the engine.
  - `AudioVoiceInfo::CursorFrames` is the frames the engine has mixed of the voice: miniaudio's cursor minus the frames the voice read ahead and the mixer has not output yet (modulo the length for a looping voice). It is exact while the engine pulls its own frames (Simulation, Host) and a snapshot while the device reads.
- **`Audio/AudioTypes.h`:** `Attenuation::None` keeps the sound positioned (panned and Doppler-shifted) with no distance falloff. The engine maps it to miniaudio's inverse model with a rolloff of 0, because miniaudio's own "none" model turns spatialization off entirely.
- **`Audio/SoundSynth.h`** (the semantics every `.sfx` depends on, where the frozen comment was silent):
  - a note's seconds have at most 7 digits before and 8 after the decimal point, so the decimal rounds to the nearest float exactly through double;
  - every layer lasts at least one frame; that rule and the 10 s limit are checked per layer, located at `/Layers/<i>`, and only for a layer whose fields are valid;
  - a tone sweeps over its N frames and holds `EndFrequency` during its release tail;
  - Noise draws its first value at each note's start;
  - the low-pass runs over the layer's span only, from `F(Delay)` to the end of its last release, starting from 0, and the layer's `Volume` applies after the filter;
  - range checks compare the float with its bounds rounded to float, as the type registry does, so a file that spells `DutyCycle` 0.99 is accepted.
- **`AssetPipeline/Importers/SoundEffectImporter.h`** (`RegisterTypes`): `"SoundLayer"` has its own Validate hook (one layer's rules), so a bad layer is reported even when another field of the sound is invalid; `"SoundEffect"`'s hook runs `ValidateSoundEffect` except on an empty `Layers` list, which is the registry's default object. `SoundEffectFromJson` and `asset.create` still require a layer through `ValidateSoundEffect`. Both structs have Generate hooks, so the registry suite's random round trips cover them.
- **`App/Application.h|.cpp`: the engine option `--audio-device system|null|none`** (non-Dist, like `--renderer`). It sets `ApplicationSpecification::Audio` to `GetDefaultAudioSpecification(Window)` with that device; the decoding mode stays the window mode's, whatever the option's position relative to `--headless`. Decision 3 said "every Editor and Runtime process the tests start is headless", which is not true: "EditorApp: a windowed editor opens and closes within a 10 second timeout", "EditorApp: a windowed rendering editor draws its viewport without GPU errors" and the "editor already open" case of `Tools/MCP/tests/test_launcher.py` start windowed editors. With stream A's engine those editors opened the machine's default playback device (WASAPI on Windows; ALSA or PulseAudio under Xvfb on Linux CI). The C++ helpers that start Editor and Runtime processes (`RunEditor`, `RunRuntime` and the viewport case) pass their arguments through `Test::WithoutAudioDevice` (`Support/TestOptions.h`), which appends `--audio-device none` unless the arguments contain `--headless` or choose a device; the launcher test passes the option itself (the Python harness starts only headless editors). Both windowed editor cases check that the engine logged its device-less configuration and neither opened nor tried to open a device. So no process a test starts, in-process or child, headless or windowed, opens a real audio device (§15.1 T1); only miniaudio's Null backend runs as a device, in the device tests.
- **`AssetPipeline/ImporterRegistry.cpp`:** `RegisterBuiltinImporters` registers `AudioImporter` before `SoundEffectImporter` (stream B left it out until stream A's decoder was merged), so `Describe` starts with `"Audio"`.

### 24. Choices the streams made where the contract was silent (accepted)

- **A:**

### 27. Known limitations

- miniaudio identifies registered data by a 32-bit hash of the resource name, so two registrations whose names collide would share data. With the handle's 16 hex digits and the version in the name this is very unlikely; it is a miniaudio limitation.
- On Windows, opening the system device makes miniaudio's WASAPI backend initialize COM as multithreaded on the main thread. No first-party code uses COM yet; a native file dialog (single-threaded COM) would have to run on its own thread.
- The open point of decision 5 stays open for M13 (deterministic decoding of test runs in windowed editors).
- **GPU suite crashes on this machine: a suspected NVIDIA driver fault, an open follow-up for the lead.** The gpu stage crashed (SIGSEGV, in a different test case each time, under either API cap) in 4 of 16 suite runs made while three milestone integrations ran their gates on the same GPU, and in none of 20 other runs (8 alone, 8 four at a time, and the 4 of the full `CI.py`). A temporary vectored exception handler caught two of them: both faulted on a thread the driver created (thread procedure `nvoglv64.dll+0xa1ecc8`, NVIDIA driver 32.0.16.1692), once executing a freed heap address and once inside `ntdll` on a freed lock, right after a test case created its device. No engine frame was on that thread. The driver stays loaded for the whole process (only the validation layer is loaded per instance), so it is not a loader unload race, and the crashes predate M12 (stream A reproduced them on the contract tree, which creates no audio engine). That points at the driver but does not rule out an engine-side lifetime bug (a driver thread running freed memory right after a device is created also fits an object the engine freed too early), so the cause is not settled: the lead tracks it as an open follow-up, to be reproduced on another driver version or GPU, or under the debug heap with the GPU objects' lifetimes logged. Once in those runs the device-lost child editor of "EditorApp: --gpu-inject-fault=device-lost exits 4 ..." did not finish within 60 s; it finishes in under a second in every other run (12 more in a row), and it has no audio thread (headless editors run the engine without a device and without job threads).

### 28. Review fixes (integration)

The milestone review found defects in the integrated tree; their fixes changed behaviour where the contract was silent, and some frozen comments:
- **Non-finite samples.** `ProbeEncodedAudio` and `DecodeEncodedAudio` refuse a file with a sample that is not finite (an IEEE-float WAV can hold NaN or infinities, a 64-bit float WAV values beyond f32): Validation naming the frame, with a hint to re-export. The probe decodes every frame, so `AudioImporter` refuses such a file (ImportFailed) whether the clip streams or not, and `RegisterClip` refuses it for a clip that decodes at registration. As defence in depth for bytes that skipped the import (a hand-made pak entry or cooked cache) and for volumes whose product overflows, the engine replaces every non-finite output sample with silence in the device callback and in its own pulls, before the capture. `AudioDecoder.h` documents the new error.
- **Pitch and Doppler bounds.** miniaudio converts each voice's resampling ratio to a 32-bit fixed-point rate; an unbounded ratio overflowed that conversion (undefined behaviour: a voice ran about 1,000 times too fast, or kept its old rate). The engine plays a voice at a pitch of at most 16 (`AudioVoiceSettings::Pitch` stays as given and is reported so), and reduces a voice's Doppler factor where needed so that it times the voice's speed, and times the listener's, stays at or below half the speed of sound: the Doppler pitch then stays within [1/3, 3] (it divided by zero at a source speed of c / f). The bound is recomputed whenever the voice's settings or transform or the listener changes. AudioSystem reports no velocity for a position that moves at or above the speed of sound in one frame (a teleport, a respawn or a camera cut), which would otherwise chirp every voice for a frame. `AudioEngine.h` documents the bounds; no declaration changed.
- **Device notifications.** On Windows a default-device change made WASAPI stop the device, reroute it and start it again, and the engine handled the Stopped as a device loss: it uninitialized a device miniaudio was rerouting (possibly while the reroute ran on the COM notification thread) and re-created it with every voice frozen for a second. Now a Rerouted or Started after a Stopped cancels it; a real Stopped still pending `DeviceRecreationDelaySeconds` later is acted on only when the device has not started again, and the device is then re-created at once (so still one delay after the stop). An injected Stopped stays unexpected, at the end of the Update that handles it, unless a Rerouted or Started follows it there. Amends decision 4; `AudioEngine.h` ("Device notifications", `InjectDeviceNotification`) documents it.
- **Cursor.** `CursorFrames` subtracts the voice's read-ahead (a plain miniaudio field the mixing thread writes) only while nothing else mixes: the engine pulls its own frames or has no device. While the device may read the engine it is miniaudio's cursor alone, so `audio.stats` and `GetVoices` no longer race the device thread. Amends decision 23's `CursorFrames` bullet.
- **Startup log.** `AudioEngine::Create` logs a device-less engine at Info ("Audio engine: no device, <mode> decoding"), like an opened device, so the windowed editor tests assert the configuration positively.
- **Asset method errors.** Invalid sound-effect values in `asset.create` and `asset.setProperties` are `Validation` (`ValidationFailed`, -32003) located under `/values`, the code an invalid material's values have had since M6, so one rule covers both native asset kinds; values that are not an object, or that set `Format` or `Version`, stay `InvalidArgument` (`InvalidParams`). Amends decisions 16 and 24; `AssetMethods.h` documents it and no longer says "Unsupported for SoundEffect before M12".
- **Tests the review strengthened.** Streamed and decoded playback are compared sample for sample, and streamed playback captured twice, for each format fixture (WAV, FLAC, MP3, Ogg Vorbis), not only for in-memory WAV tones: the two paths differ most for Vorbis (a stream opens its decoder through the AudioVfs, where stb_vorbis runs in push mode; a decoded clip through memory, in pull mode), and they agree on every fixture, so decision 6's claim holds for every container. The lockstep acceptance test waits (`Test::WaitUntil`) until the Null device's callback has run while simulation time is owned and then checks that it read nothing, after checking that it reads the engine without simulation time; the re-creation test gives time back while Recreating and checks that a non-zero frame delta pulls nothing, then that the re-created device plays the voice on.
- **Shared importer helper.** `AudioImporter` and `SoundEffectImporter` share `Utils::MakeImportFailed` (`AssetPipeline/Private/ImportErrors.h`). The `.sfx` registry ranges keep their literal 20 Hz bound: SoundSynth's constant is private to `SoundSynth.cpp`, and exposing it would add a declaration to the frozen `SoundSynth.h`.
