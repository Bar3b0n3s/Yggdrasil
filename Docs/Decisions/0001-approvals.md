## Rules that still apply

The standing permission removes the need to ask. It does not change how downloads are handled:

- Download only from the official upstream source, pin the exact version or commit, and verify a checksum.
  - Assets: the checksum lives in `Scripts/FetchAssets.py`.
  - Vendored code: the commit SHA lives in `VENDOR.md`.
- Commit the license with every asset or library. Assets are listed in `Resources/LICENSES.md` or `Tests/Data/LICENSES.md`; libraries keep their license in `Vendor/<Lib>/`.
- Every new third-party library follows the vendoring rules in `AGENTS.md`: unmodified upstream sources, a `VENDOR.md`, and ABI defines checked by `Scripts/CheckBuildConfig.py`.

## Repository remote and CI

- **Remote:** `origin` = https://github.com/Bar3b0n3s/Yggdrasil.
- **Push policy:** GitHub is only an off-site backup of the repository: GitHub Actions is not part of the process, and nothing reads or waits for its results. Only main is pushed: once a phase's last milestone has landed, main is pushed to `origin` as an off-site backup, and a commit straight to main outside a milestone (after its review and its commit gate, Architecture §15.9) travels with the next such push. There is no push before review, no `ci/**` branch and no gh CLI (`Docs/Decisions/0028-backlog-program.md` decision 10, which removed the earlier `ci/**` exception).
- **CI:** from the program's setup commit, `.github/workflows/ci.yml` runs only when started by hand (`workflow_dispatch`), and no step of the process starts it. Windows is the only verified platform. First-party code stays portable by rule (the `Platform/` layering, no Windows-only shortcuts, the local portability stage's premake generation and clang-cl builds), but Linux and macOS are never verified: the Linux/macOS catch-up was dropped by the product owner, because there is no Linux or macOS machine without GitHub (ADR 0028 decision 10). From 2026-10-05 to that decision, GitHub Actions compiled and ran the unit tests on Windows, Linux (Ubuntu 24.04) and macOS (arm64).

## Consequences

- The fallbacks in Architecture Appendix C for declined items are not needed: no approximate tangents, no OGG rejection, no bitmap-only text, no missing format coverage.
- Linux and macOS compile errors showed up in CI until ADR 0028 decision 10; first-party code is still written to compile on GCC 14, Clang 19+ and Apple Clang, but nothing compiles it there any more.
