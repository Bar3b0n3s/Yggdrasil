## Decisions

### 1. The session's locale (W38.1)

- **The state.** `PlaySession::State` gains `Locale` (the session's) and `StartLocale` (the one it started in), both from the specification's `Project.Localization.Locale` at `Prepare`; `Prepare` refuses (`InvalidArgument`, naming `Project.Localization.Locale`) a start locale that is neither empty nor a tag. Both are session state that a scene transition keeps. Every VM the session creates, a `Scene.Load`'s and a `Scene.Reload`'s included, starts in the session's locale (the one initializer in `PrepareScripts`, `.Locale = Locale`).
- **The engine.** `ScriptEngineSpecification::Locale` is the VM's starting locale; `ScriptEngine` keeps a mutable copy (`m_Locale`) that `GetLocale` returns and `ScriptEngine::SetLocale(std::string)` sets, taking effect at the next `Loc` call and dispatching nothing. The edit evaluation's VM keeps the project's locale.
- **The session's API.** `PlaySession::GetLocale()`, `GetStartLocale()` and `SetLocale(std::string_view) -> Status`: `InvalidArgument` for a value neither empty nor a tag; otherwise it becomes the session's and its current VM's (`ScriptEngine::SetLocale`). It dispatches nothing: `OnLocaleChanged` is the binding's (decision 2), as `OnCreate` is `Scene.CreateEntity`'s.
- **The host.** `IScriptHost::SetLocale(std::string_view) -> Status` is appended after `GetNavigation` (phase 6's ledger: before M40's `GetMusic` in landing order), defaulting to `Unsupported` "this host has no session locale: Loc.SetLocale works in a play session"; the play session's host forwards it to `PlaySession::SetLocale`. `ScriptTestFixture` gains an optional `SessionLocale`: set, its `SetLocale` records the change there and sets the engine's copy; unset, it keeps the default refusal. `EditScriptHost` needs no change.
- **The tag rule** becomes public as `Engine::IsLocaleTag(std::string_view)` in `Asset/StringTableData.h` (1 to `MaxStringTableLocaleBytes` bytes of ASCII letters, digits and '-', starting with a letter), the one rule of a session's locale in Asset, Session, Automation, Testing, EditorCore and the Runtime; each caller also takes the empty locale where the rule allows it. Project keeps its copy (`ProjectSettings.cpp`'s `IsLocaleTag`, now also behind a suite's `Locale`), and `ProjectSettingsTests`' Localization case checks that the two agree.
- **Supersedes** ADR 0033 decision 11's rule that a VM's locale is fixed for its life (the project's `Localization.Locale` is now a session's default only) and `Docs/Backlog.md` §6's fixed-locale row.

### 2. `Loc.SetLocale` and `OnLocaleChanged` (W38.1)

- **`Loc.SetLocale(locale: string) -> ()`**, appended in `RegisterLoc` (no namespace, no `RegisterBindings.cpp` line; `Mutates`, the default, so a read-only evaluation is refused by the registry before anything runs). In order: the value is empty (every table's fallback) or a tag, else a located `InvalidArgument` "'<value>' is not a locale" (a value no tag can be, too long or not UTF-8, is named by its byte count, as `Loc.Get` names keys); then `ScriptEngine::CheckLocaleChange` refuses (`InvalidState`) while an `OnLocaleChanged` dispatch runs (no nested change) and while the engine stops (an `OnDestroy` of `Stop`, so a dispatch at teardown); then the locale in force is a no-op (no callback, no mutation notice); then `PrepareHostMutation` (an evaluation's or a test driver's change invalidates an input-only recording); then the host's change (`IScriptHost::SetLocale`, `Unsupported` without a session); then `ScriptEngine::NotifyLocaleChanged(previous)`. It is callable in every callback, phase, task and test case. `Loc.Get` and `Loc.GetLocale` read the new locale from the next call; `Loc.Has` is unchanged. A call inside `OnLocaleChanged` raises even for the locale in force, so the rule has no exception.
- **`OnLocaleChanged(self: ScriptInstance, locale: string, previous: string) -> ()`**, a behaviour callback appended after `OnAnimationEvent` in `Bindings/Script.cpp` and `ScriptData.cpp`'s reserved names (phase 6's ledger: beside M37's `OnJointBreak` in landing order; `ScriptImporter` stays 1). **Delivered synchronously (ADR 0052's choice)** by `ScriptEngine::NotifyLocaleChanged` before `Loc.SetLocale` returns, under the caller's deadline: to every started, enabled instance (not pending destruction, not fault-disabled) whose behaviour defines it, the caller's own included, in (ExecutionOrder, canonical entity, slot) order from a snapshot of `OrderedInstances(true)` with each instance's serial, taken before the first call; an instance is passed over when its turn comes if it no longer exists, its serial changed (one a callback created under the same key) or `Invoke`'s eligibility fails (destroyed, disabled or faulted meanwhile). An instance created during the dispatch receives nothing, its `OnStart` reading the new locale. A fault disables only its own instance (§11.7), and the dispatch goes on. Classified as the UI's under M35's world pause: no `WorldPaused` filter, so every behaviour that defines it receives it. A new scene's VM after `Scene.Load` or `Scene.Reload` starts in the locale without a callback. `ScriptEngine::State` gains `LocaleDispatching`; `Invoke` gains a trailing `const LocaleChange*` (the two strings) beside `OnAnimationEvent`'s record.
- **No phase.** `Loc.SetLocale` runs in the callback that calls it, and the dispatch inside it, so phase 6 adds no `PlaySessionPhase` (the ledger's execution order) and no pending state reaches the hash.

### 3. Where a session starts (W38.1)

- **`PlayStartOptions::Locale`** (`std::optional<std::string>`, appended after `SaveData`): the locale a session starts in, empty or a tag; absent, the project's `Localization.Locale`. Each host writes it into its copy of the project before the specification takes it (the editor's `EditorPlayController::PrepareSession`, refusing a bad value with `InvalidArgument`, and `ValidatePlayRequest`, which every play request runs first; the Runtime's `RuntimeApp::State::PrepareSession`), as a replay's FixedHz, so `PlaySessionSpecification` gains no member.
- **The precedence.** Live play: `play.start {locale}` in the editor (decision 7), the Runtime's `--locale` (decision 8). A suite: its entry's `Locale`, else the run's (`test.run {locale}`, or `--locale` with `--feature-test`), else the project's (decision 6). A recording: `input.record {action: Start, locale}`, absent the project's in the editor and the launch locale (`--locale`) in the Runtime. A replay: always its header's `Locale`, and a header without one (versions 1 to 4) plays in the project's `Localization.Locale`, given explicitly (`header.Locale.value_or(project's)`), so no run or launch locale ever reaches a replay.
- **No engine-persisted choice.** A game restores its player's choice from its save data with `Loc.SetLocale` at startup; a game that does so in its title's `OnStart` overrides `--locale` (ADR 0052's risks; told to the World Tree session through the product owner).

### 4. Determinism: the locale block and the start locale as an input (W38.1)

- **The locale block** follows M35's world-pause block in `ComputeStateHash`, whatever the landing order (phase 6's ledger): while the session's locale differs byte-wise from its start locale, its length as a little-endian 64-bit value, then its bytes; nothing otherwise. Not sticky: switching to `ar` and back to the start locale empties it again, which is exact because the locale is the block's only state. No committed hash moves: no committed run calls `Loc.SetLocale`, which did not exist, and FeatureTest's `fr-CA` runs keep their start locale.
- **The start locale is an input (ADR 0052's choice),** recorded in the replay header like the seed and the start store (decision 5) and enforced at playback, rather than hashed: hashing every non-empty locale would move FeatureTest's `fr-CA` replays and break every committed replay of a game whose default locale is set, and hashing it relative to the project's default would fail a replay whenever that default changed. `ReplayPlayer::Begin` refuses (`InvalidArgument`) a session whose start locale (`PlaySession::GetStartLocale`) differs from a header that names one (the empty locale included), naming both, beside its seed, rate and parameters check, before a tick runs. A change during a run reaches the next checkpoint through the block: one caused by input is reproduced by that input; one from `script.eval` invalidates the recording (`PrepareHostMutation`). This departs from the brief's words ("the session's locale is in the state hash") but meets its aim: a mismatch names the locale, and no committed hash moves.
- **The divergence hint** (`ReplayPlayer.cpp`'s `ReplayDivergenceCauses`, word for word in `ReplayDivergenceHint`) names a locale change among the causes of non-determinism: "or the play is not deterministic (a locale change the playback did not repeat among its causes)".

### 5. Replay format 5 (W38.1)

- **The header's `Locale`** (`std::optional<std::string>`), written after `SaveData` and before `Fingerprint`, a string or null; validation (`ValidateReplayDocument`) refuses a string that is neither empty nor a tag, at `/Locale`. Readers accept versions 1 to 5: in versions 1 to 4 a `Locale` member is unknown (a warning, an error when strict), and the file migrates with a null `Locale`; version 5 requires the member. Every recorder writes the session's start locale, never null (the editor's `PrepareSession` header, which `DescribeReplayHeader` returns for `test.run {record}`, and the Runtime's `PrepareSession`); null arises only from a migration, and `project.upgrade` writes it.

Cooked artifacts of versions 1 to 4 are `UnsupportedVersion`; the cache rebuilds them (the importer's version is in the cache key).

### 6. Suites in a locale (W38.1)

- **`Testing.Suites[].Locale`** (`TestSuiteSettings::Locale`, `std::string`, default empty: the run's locale, else the project's), appended after `Modes`; validated by `ValidateSuite` as empty or a tag, located at `/Testing/Suites/<i>/Locale`; `GenerateSuite` makes random text a tag (`MakeLocaleTag`, shared with `Localization`'s Generate hook). `ProjectSerializer::CurrentVersion` stays 1: a reader keeps a missing key's default.
- **One entry per locale:** a project lists its strings suite once per locale, each with its own `Modes`; selection stays by settings index. A suite whose **entry** names a locale is reported as `"<Name> (<locale>)"` (`MakeTestSuiteName` in `FeatureTestRunner.cpp`) in every row (`TestSuiteResult::Suite`, `TestCaseResult::Suite`, so `FailedCases` and JUnit), in `test.list`'s inventory and against the filter, so rows stay distinct and `filter: "Strings (ar)/"` selects one locale's run; entries without one, a run locale or not, are reported as before. The runner decorates the collected name as it decorates the discovered one, so its consistency check compares like with like.
- **`FeatureTestRunOptions::Locale`** (`std::string`, empty for none), the run's locale: `Begin` refuses (`InvalidArgument`) a value that is not empty and not a tag. Each selected suite's settings carry its effective locale (`State::Selection::Settings.Locale`, the entry's, else the run's), and the hosts apply a non-empty `suite.Locale` as the start locale (`PlayStartOptions::Locale`), so `IFeatureTestHost` is unchanged. Discovery's scratch sessions start in the same locale (`DiscoverSuite`'s new `runLocale`).
- **`TestSuiteResult::Locale`** (`locale`, appended after `failedCheckpointTick`): the locale the suite's sessions started in (`PlaySession::GetStartLocale`), a replay row's its header's (the project's for a header without one); empty for the empty locale and for a suite whose session never started.
- **`Scripts/Lib/games.py`** reads each entry's `Locale` into its `SuiteEntry` and keys suite rows by (script, effective locale), the effective locale being the entry's or the project's (the games suite passes no run locale).
- **Out:** a list of locales per entry, a locale in `Overrides`, and a suite choosing the empty locale (empty inherits; name the fallback's tag): `Docs/Backlog.md` §2.

### 8. The Runtime's `--locale` (W38.1)

## Risks

- **The hash rule departs from the brief's words** (decision 4): the brief asks for the locale in the state hash; the record hashes it only once it differs from the start locale and enforces the start locale at `ReplayPlayer::Begin`. The World Tree session is told through the product owner (ADR 0052's risks).
- **Synchronous `OnLocaleChanged`** (decision 2): a callback that creates or destroys entities, requests `Scene.Load` or faults inside the dispatch is handled by the serial snapshot, `Invoke`'s eligibility, the refusal of a nested change and the caller's deadline; a dispatch at teardown is refused.
- **The format bump rewrites every replay** (decision 5): FeatureTest's through `Scaffold.py`, the demos' eight through their recorded upgrades, World Tree's by its session after the landing; a missed rewrite fails `Scaffold.py --check`, the games suite's upgrade dry run or the provenance audit.
- **A suite's decorated name** (decision 6): a reader that matched rows by the bare declared name of a suite whose entry names a locale must use `"<Name> (<Locale>)"` (`games.py` keys by script and locale; the filter takes either).
