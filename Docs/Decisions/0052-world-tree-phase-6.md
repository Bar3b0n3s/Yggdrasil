**M36 Contact surfaces and characters**

- **W36.1, collider surfaces** (brief 15, brief 16's second part; ~3 sessions).
  - **A `ColliderSurface` component** (version 1), category Physics, appended after `CharacterController` in `PhysicsRegistration.cpp`; requires Transform; script-visible. A component of its own, never fields of the five collider components, which written with their defaults would change the canonical form, and so the state hash, of nearly every 3D scene (FeatureTest's, Rolling Ball's three levels and their three committed replays), and never a physics-material asset (a new `AssetType`, importer and cooked format, and one asset shared by many colliders cannot carry one belt's per-tick velocity). Fields: `Friction` (float, 0.5, ≥ 0, no maximum, as RigidBody's), `Restitution` (float, 0, [0, 1]), `SurfaceVelocity` (vec3, 0, m/s in the entity's own axes, rotation only and scale ignored, so a turned belt carries along its own length; each component within ±`MaxCharacterSpeed`, 500). Both material values apply whenever the component is present (no "inherit" flag); the defaults are RigidBody's, so a component added for its velocity on a body of default material changes nothing else.
  - **Where it applies:** every solid collider component on its own entity (Box, Sphere, Capsule, Mesh and TerrainCollider), whichever body gathers it (a RigidBody's compound, an implicit static body, a TerrainCollider's body); not descendants' colliders, triggers, a character's capsule or 2D colliders. A collider without one keeps its body's values.
  - **The world** (`PhysicsWorld.h`, M11's frozen header, appended): `PhysicsColliderSurface {Collider, Friction, Restitution, SurfaceVelocity (body space)}` and `Status SetColliderSurfaces(BodyHandle, std::span<const PhysicsColliderSurface>)`, which replaces the body's list (unlisted colliders keep the body's values and carry nothing), refuses a non-finite or out-of-range value, an index the shape lacks or a duplicate with `InvalidArgument`, and wakes the bodies inside each changed collider's bounds (`WakeBodiesIn`, `GetSubShapeBounds`), so debris asleep on a stopped belt rides it once it starts. The list lives in `PhysicsBodyRecord`, which the listener already reads. In `OnContactAdded` and `OnContactPersisted` (the CCD pass included), when either body has surfaces, the listener resolves each side's collider (`ResolvePhysicsCollider`) and sets `mCombinedFriction = sqrt(f1 · f2)`, `mCombinedRestitution = max(r1, r2)` and `mRelativeLinearSurfaceVelocity = R2 v2 − R1 v1` (R each body's current rotation, v its surface's body-space velocity), each side's value its surface's or else its body's. A pair where neither body has surfaces is left exactly as Jolt combined it, so every existing contact stays bit-identical. `PhysicsShape.h` and `PhysicsComposition.h` are unchanged, and a surface change never rebuilds a compound.
  - **The scene.** `ColliderSurface`'s signals mark their entity in a dirty set of their own and never set `ComponentsChanged`, so a per-tick write never recomposes the scene. PreStep, after its rebuilds, recomputes the list of each body holding a dirty collider entity (the velocity converted to body space: the owner's inverse world rotation times the entity's world rotation times the local velocity) and sends it; `CreateBody` and `ReplaceShape` send it for every new or rebuilt shape. A write in the fixed step is in force at that tick's PreStep, one in the frame phase at the next tick's (§9.2). The world wakes neighbours only when a value really changed, so the Shuttle Works' per-tick write of an unchanged velocity wakes nothing.
  - **Characters on surfaces.** `CharacterGroundState` gains `GroundBody` (`GetGroundBodyID`) and `GroundCollider` (the collider index, through `ResolveColliderUserData`); `PhysicsCharacterState` gains `GroundCollider` (the collider entity's UUID, null when not grounded or the ground is disabled or pending destruction; another character's entity when it stands on one). The ground collider's surface velocity, in world space, joins the ground's velocity (`GroundVelocity` includes it): its vertical part as every ground's, and its horizontal part carrying a grounded character **whatever `InheritGroundVelocity` says (chosen)**, added to the velocity the script asks for; `InheritGroundVelocity` stays about ground that really moves. A light Dynamic ground still gives none (M34's rule).
  - **Script API** (no namespace, no callback): `CharacterController:GetGroundCollider() -> Entity?` (the collider entity the last update stood on; nil while not grounded), appended after `GetVelocity` in `Bindings/Components.cpp`; `Physics.GetSurface(collider: Entity) -> SurfaceInfo?` with the alias `SurfaceInfo = {Friction: number, Restitution: number, SurfaceVelocity: vector}` (named apart from the component type, which `ScriptApiRegistry` checks against aliases), in `RegisterPhysics`: the values contacts with that collider use (its surface's, the velocity in world space, or else its body's friction and restitution with zero velocity), nil for an entity with no solid collider in a created body (characters included), disabled or pending destruction. Both are read-only, usable in every phase, and read the last update and the current component, as `IsGrounded` does. The fields are read and written through the generic proxy. Brief 15's Footing becomes `Physics.GetSurface(controller:GetGroundCollider())`.
  - **Validation:** `PHYSICS_SURFACE_UNUSED` (Warning, not auto-fixable) for a `ColliderSurface` whose entity holds no solid collider of a creatable 3D body (no collider, triggers only, a character's capsule, 2D colliders only), reported by `project.validate` from the composition through a function of its own beside `ValidateScenePhysics`, its code in an array of its own (W36.1 names the header; the ledger's validation row).
  - **Determinism.** The component's values, a script's per-tick `SurfaceVelocity` writes included, are component data in the canonical serialization and the state hash; the listener's values depend only on the pair's data (`sqrt`, `max` and Jolt's quaternion rotation, no CRT transcendental). No new hash block. No committed hash moves: no existing scene holds the component, contacts without surfaces are untouched, and no committed replay plays a character (FeatureTest's characters are in `CharacterDebris`, `Components`, `Physics` and `Scripting.scene`, which no replay plays; no demo holds one).
- **W36.2, Kinematic bodies that push characters, and the squeeze** (brief 16's third part; ~2 sessions, +1 if the push fails).
  - **The measuring tests come first:** a Kinematic piston at 2 and at 8 m/s into a character, a press brought down onto a grounded character, a character carried into a resting ram. Only what they show needs code.
  - **What is guaranteed** (documented and tested): a Kinematic body moving into a character, or a Dynamic body not lighter than it, pushes the character along the contact normal at the body's velocity while it is within the character's 0.1 m look-ahead at its update (up to 6 m/s at 60 Hz without overlap); a faster body overlaps the character for one tick and pushes it out at the next update; beyond about 0.1 m plus `Radius` a tick it can pass through, an accepted limit (`Docs/Backlog.md` §6 at landing, like M34's for light bodies). A wider look-ahead for Kinematic sweeps (an extra query per character near a moving body) is the fallback, taken only if the test fails at the game's speeds, with a `Perf.py` check.
  - **The squeeze:** after its update, a character is squeezed when a body that pushes it (a Kinematic body, or a Dynamic one not lighter than it, whose contact velocity points into it) could not move it out of the way (the update left it short of that body's push, or still overlapping it, by more than a tolerance, an engine constant W36.2 names with cases each way: a press onto a grounded character and a piston against a wall are squeezes; a character's own `Move` into a wall, sliding into a corner, a steep face and a press's first contact are not). `CharacterController::GetSqueeze()` returns `{IsSqueezed, Body}`, the body the first pushing body by handle (canonical order); `PhysicsCharacterState` gains `IsSqueezed` and `SqueezedBy` (the owner's UUID).
  - **Script API:** `CharacterController:IsSqueezed() -> boolean` and `CharacterController:GetSqueezingBody() -> Entity?`, after `GetGroundCollider`, reading the last update, so a script sees a squeeze in the next fixed update. **No callback and no engine-made escape (chosen):** a query adds no dispatch path, reserved name, gate-3 entry or callback-list conflict with M37's `OnJointBreak`; crushing or shoving what is squeezed is the game's.
  - **Automation:** no new method (§13.5's count unchanged by M36). `physics.bodyInfo`'s `PhysicsBodyInfoResult` (wire format frozen by M11, reviewed as such) gains, after `groundNormal`, `groundCollider` (`EntitySummary`, empty unless a grounded character), `squeezed` (`bool`) and `squeezedBy` (`EntitySummary`), each described, with a Python case in `Tests/Automation/test_physics.py`. `ColliderSurface` is edited through `entity.update`, `edit.batch`, `component.schema` and `prefab.*` like any component.
  - **Determinism:** the ground collider and the squeeze are derived from the character's state each update, as `IsGrounded` is, and not hashed. Surfaces apply in PhysicsPreStep and PhysicsStep and the squeeze in PhysicsPreStep's character update, world phases that M35's world pause holds.
- **Run modes and FeatureTest coverage.** Everything is `RunModes::All` (editor Play and Simulate, Release, Dist). A scaffold `Surfaces.jsonl` makes `Surfaces.scene` and its suite in every mode: one Static `/Level` compound of marble (the body's friction, 0.5) and ice (`ColliderSurface` friction 0.02) with no `PHYSICS_ADJACENT_STATIC_BODIES`, shards struck alike on each and travelling farther on ice; a belt carrying a crate and a character, stopping and reversing; a piston pushing a character; a press squeezing a character; a character carried into a resting ram, stopped and not squeezed. `SurfacesReplay.jsonl` records `Surfaces.replay` (belt, shards and piston, a character moved by input), which the determinism suite verifies in Debug, Release and Dist. Gates: 1 (`ColliderSurface` in a simulated scene, all three fields non-default), 2 (the four new members), 4 (the three fields through the proxy), 5 (`physics.bodyInfo`'s new fields, Python), 6 (`PHYSICS_SURFACE_UNUSED`'s fixture), 7 (every description); 1b, 3, 8 and 9 nothing.
- **The editor:** the generic inspector in the Physics group, with units and ranges from the field metadata; no panel or menu. Parity holds through the component methods and `physics.bodyInfo`.
- **Out** (`Docs/Backlog.md` §2): an angular surface velocity (turntables); physics-material assets; materials per triangle of meshes and height fields (a terrain's splats); combination rules other than the geometric mean and the maximum; surfaces in the 2D world; engine-made sliding for characters (`CharacterVirtual` has no friction; Footing keeps the game's slide); a squeeze callback, a sideways escape and crush damage; characters pushing characters; debug drawing of surface velocities. **Accepted at landing** (§6): a body across an ice–marble seam of coplanar pieces takes the surface of the sub-shape Jolt names its merged manifold after (manifold reduction stays on; turning it off only for bodies with surfaces is the fallback if a test shows it matters); fast Kinematic bodies beyond the look-ahead; no sideways escape from under a flat face.

**M37 Joints**

- **W37.1, joints in the world and the session** (~3–4 sessions). Its first checkpoint settles what a contract would freeze: the four components' fields and `JointMotorMode`, the world's joint API in `PhysicsWorld.h`, the listener's hook in `PhysicsSystem.h`, `physics.jointInfo`'s wire format and the validation code (decision 6).
  - **Four components,** `HingeJoint`, `SliderJoint`, `DistanceJoint` and `FixedJoint` (version 1 each), in a new category **Joints** (`Scene/Registration/JointsRegistration.cpp`, `RegisterJointsComponents` after `RegisterNavigationComponents`). Not RigidBody fields, which would re-hash every scene and prefab holding a RigidBody; one component per type rather than one with a type enum, so each has only the fields it uses (gate 1 asks every field non-default somewhere). Each excludes the other three, so one entity holds at most one joint, and "the joint's entity" names it everywhere. Registry enums: `JointMotorMode` {Off, Velocity, Position} (component) and `JointType` {Hinge, Slider, Distance, Fixed} (`physics.jointInfo`'s result). In code and documents the types are always `HingeJoint` and the others, never a bare `Joint` (a Skeleton joint is `Animator:GetJointTransform`'s).
  - **Which bodies a joint joins:** one pure function, `ComposePhysicsJoints`, in a new `Scene/PhysicsJoints.{h,cpp}`, over `ComposePhysicsBodies`' result and never changing it (M11's frozen `PhysicsComposition.h` stays as it is), shared by the session, the validator and the debug draw. **Its body** is the body of the RigidBody at or above the joint's entity (its own, else its nearest ancestor's, with no CharacterController on the way: §5.3's gathering rule), so a joint sits on the body's entity or on a child, and a body may hold several joints. **`ConnectedBody`** (EntityRef) names the other side by the same rule, or without a RigidBody at or above it the implicit static body that entity owns or belongs to; null joins the body to the world (`Body::sFixedToWorld`). Joints are listed and created in canonical order of their entities, after every body of the same pass.
  - **Fields** (angles in degrees, as `CharacterController.MaxSlopeAngle`; every range enforced on every write path): all four have `ConnectedBody` (null), `Anchor` (vec3 0, m, in the joint entity's space), `CollideConnected` (false), `BreakForce` (0 N, ≥ 0, 0 never breaks) and `Broken` (false; the system sets it when the joint breaks; writing false mends it); all but `DistanceJoint` have `BreakTorque` (0 N m). `HingeJoint` and `SliderJoint`: `Axis` (vec3 (1, 0, 0), normalized, not zero), `UseLimits` (false), `Motor` (`JointMotorMode`, Off), `MotorTargetVelocity` (0, deg/s or m/s), `MotorFrequency` (2 Hz, > 0) and `MotorDamping` (1, ≥ 0), Jolt's position-drive defaults; the hinge `LowerAngle`/`UpperAngle` (−90/90 deg, in [−180, 0] and [0, 180]), `MaxFrictionTorque` (0 N m), `MotorTargetAngle` (0 deg, [−180, 180]) and `MotorMaxTorque` (1000 N m, [0, 1e12]); the slider `LowerLimit`/`UpperLimit` (−1/1 m, ≤ 0 and ≥ 0), `MaxFrictionForce` (0 N), `MotorTargetPosition` (0 m) and `MotorMaxForce` (1000 N, [0, 1e12]); a motor target is clamped to the limits while `UseLimits` holds, as Jolt clamps. `DistanceJoint`: `ConnectedAnchor` (vec3 0, m, in the connected entity's space, world space when `ConnectedBody` is null), `MinDistance`/`MaxDistance` (0/1 m, ≥ 0, Min ≤ Max), `Frequency`/`Damping` (0/0: the limit spring, Hz and ratio, ≥ 0; 0 Hz is rigid), which is the brief's "springiness". The brief's "enabled" is the motor's; a whole joint is switched off as anything is, by its entity's `Active` or by removing the component.
  - **Frames.** On the joint's body the frame is `Anchor` and `Axis` in the joint entity's space (scale baked in as for colliders); for a hinge, slider or fixed joint the frame on the connected body is where that frame lies when the joint is first created (Jolt's world-space convention), so the authored pose is the hinge's angle 0 and the slider's position 0; a distance joint authors both ends and keeps nothing. **Kept frames:** the session keeps each joint's two frames relative to its bodies' origins and creates the Jolt constraint from them in body space whenever a body is created again (a RigidBody change, a re-enabled entity), so a door that has swung keeps its zero and its limits; a change of `ConnectedBody`, `Anchor`, `Axis` or the joint entity's hierarchy forms them again from that moment's poses; `SetShape` moves the kept frames' centre-of-mass offsets and calls Jolt's `NotifyShapeChanged`.
  - **In place.** A change of the motor, a target, a maximum, the drive's spring, `UseLimits`, a limit, friction, the distance spring, `CollideConnected` or a threshold is applied to the live constraint at the next PreStep (or the start flush's synchronization) and wakes its bodies.
  - **Collide connected.** While false, the joint's two bodies never collide: the world counts the joints between each body pair and drops such a pair in its `SimCollideBodyVsBody` hook (`Private/PhysicsEdgeRemoval`), before the narrow phase, so no contact or event is reported between them (the collision groups' filter cannot: it sees only groups).
  - **Breaking.** After each step (PostStep), for each joint in force with a threshold, the force is the length of its linear impulses (point and limit parts) and the torque that of its angular ones (rotation and limit parts, never the motor's) of the last collision step, divided by that step's delta (`FixedDelta / collisionSteps`). A joint over either threshold is removed, its bodies woken, `Broken = true` written into its component (scene data, so hashed) and `OnJointBreak` dispatched. A `Broken` joint is never created; `Broken = false` mends it at the next PreStep at its kept frames.
  - **Safety before Jolt** (§9.1; each Jolt assert content can reach is refused or made safe): a hinge or slider with equal limits and no limit spring is refused (use a `FixedJoint`); hinge limits are clamped to Jolt's [−π, π] after the degree conversion; slider limits keep their signs; axes are normalized and the normal axis built by cross products (no CRT transcendental, `DetMath` only if a rotation is needed); motor settings are valid before `SetMotorState`. A body's joints are destroyed before the body on every one of the session's removal paths (a RigidBody change, a refusal, the disable and destroy flushes, the session's end), each with a regression test under Jolt's asserts in Debug and Release.
  - **Validity:** `PHYSICS_JOINT_INVALID` (Error, not fixable; the joint not created and its bodies simulating unjoined; reported by `project.validate` and at run time as a physics diagnostic, so as a script error) for no RigidBody at or above the joint's entity, a `ConnectedBody` that resolves to no body, both ends the same body, an end under a CharacterController or a 2D entity, a zero `Axis`, `UseLimits` with equal limits, or `MinDistance` above `MaxDistance`; a joint whose body another diagnostic refused gets no second one. Neither end Dynamic is not invalid (Jolt solves a constraint only while one body is Dynamic and awake). Its code sits in an array of its own in `Scene/PhysicsJoints.h` (the ledger's validation row).
  - **Determinism.** Every joint field, `Broken` included, is in the canonical serialization and the hash. The physics block gains a joint part after its bodies and characters, inside `PhysicsSystem::AppendStateHash`: for every joint the session keeps frames for, in canonical order of its entity, the entity's UUID and the bits of its two kept frames; nothing without a joint, so no committed hash moves and `PlaySession::ComputeStateHash` does not change. The world gives every constraint a unique priority from its entity's rank in UUID order, refreshed when the set of joints changes, so the solve order is a function of the state, not of Jolt's add-and-remove history. Breaking reads Jolt's impulses after the step; break events are sorted by joint UUID.
  - **Tests:** each type against an analytic case (a pendulum's period, a motor reaching its target, limits holding, a weld breaking at its threshold and not below); rebuilds keeping the zero; each removal path; one state reached through two histories stepping identically; a chain, a motored hinge, a limited slider and a breaking weld stepped 600 times ending in one state at Jolt thread counts 0, 1 and 8, with a committed constant hash in the Debug and Release unit runs.

- **No component, field, binding, callback or setting** (the owner's answer 3): everything is graph data, node kinds and transpiled Luau, so no scene's hash moves, the script API and `Engine.d.luau` are unchanged, and gates 1 to 4 and 8 gain nothing.
- **W39.1, members, methods and returns** (~4 sessions). Its first checkpoint settles the changed M24 headers (`GraphDocument.h`, `GraphNodeLibrary.h`, `GraphTranspiler.h`, `GraphMethods.h`), reviewed as frozen-interface changes.
  - **Members of any value:** three built-ins in category `Member` (its description widened to "this or another behaviour's members"): `Script.Get` (pure; `Object` Any, `Member` String → `Value` Any; `(<object> :: any)[<member>]`), `Script.Set` (`In`; `Object` Any, `Member` String, `Value` Any → `Then`; `(<object> :: any)[<member>] = <value>`) and `Script.Call` (`In`; `Object` Any, `Method` String, `Arg1` to `Arg4` Any, optional → `Then`, `Result` Any; `o<Id>:<Method>(...)` when `Method` is a literal Luau identifier, else `o<Id>[<method>](o<Id>, ...)`; the first result only, cast `:: any`). `Object` is bound to a local first; trailing unset arguments are left out. A missing member of a table reads nil; indexing nil, a missing member of an engine value, or calling nil or a missing method is Luau's run-time error at the node's line, located through `LineNodes`. A fourth built-in, `Self.Instance` (pure, `Value` Any, text `self`), passes the graph itself or calls its own methods through `Script.Call`.
  - **Graph methods:** the document gains `Methods`, sorted by `Name`, at most 64, each `{Name, Parameters: [{Name, Kind, AssetType}], Result: {Kind, AssetType} | null}`, with `GraphValueKind` gaining `Any` (appended; valid for a variable, a parameter and a result, never a field). At most 4 parameters (matching `Script.Call`'s arguments), named by `IsGraphIdentifier`, unique in the method, never `self`. A method's name is an `IsGraphIdentifier`, not a reserved script field name (`IsReservedScriptFieldName`, as it stands on the merged tree: M37's and M38's callbacks join it), not `RunsWhileWorldPaused`, and unique across fields, variables and methods. Graph-dependent kinds, like `Self.*`: `Method.<Name>` (category Event; outputs `Then` and the parameters typed by kind; several run in id order) and `Return.<Name>` (category Flow; a statement with `In` and no exec output; its `Value` input typed by the result, absent without one).

The new lines are measured by `FindGraphTextLimitIssues`, and W39.1 confirms Luau's strict checker on the fixture texts. A declared method without an event node transpiles to an empty function returning nil.

- **W40.1, the session's music** (~3 sessions).
  - **The owner:** a session-owned player, `Scene/SessionMusic.{h,cpp}`, beside `AudioSystem` (Scene, since it needs `Audio` and the asset manager and must be reachable from Scripting). `PlaySession` owns it from `Activate` to destruction, only in Play mode with an `AudioEngine` (`AudioSystem`'s condition), and never replaces it at `Scene.Load` or `Scene.Reload`.   - **Script API** (all in `RegisterAudio`, no namespace or `RegisterBindings.cpp` line): **`Audio.PlayMusic(clip: AssetRef, options: MusicOptions?) -> ()`**, `MusicOptions = {Volume: number?, FadeSeconds: number?, Loop: boolean?, Intro: AssetRef?}` (an alias, as `DisplaySettingsRequest` is), defaults `Volume` 1 (linear, finite, ≥ 0), `FadeSeconds` 0 (finite, 0 to `MaxMusicFadeSeconds`, 60), `Loop` true; a non-spatial voice in the `Music` group at `AudioSystemMusicPriority`. With another clip, a crossfade: the current voice fades to 0 and is released at the fade's end while the new one fades in. A voice without a fade mixes byte-identically; the stealing rule and priorities are unchanged.

### 6. Process

Phase 5's process, kept as it is (ADR 0042 decision 6, ADR 0051):
- **No contracts.** One builder per milestone works its waves in order; the lead reviews each wave independently, and every confirmed finding is fixed, nits included. - **World Tree's needs.** As ADR 0042 decision 6: the World Tree session reports new gaps as briefs; the lead triages them at the phase's boundaries; after the fork, a brief joins a wave that has not begun on its files or lands straight on main under ADR 0051 when it disturbs no work in progress, and anything else waits for the phase's end. ## Risks

- **M36 and M37 in the same physics functions.** `PhysicsSystem`'s create, rebuild, remove and step paths and `PhysicsWorld.h` change in both. The ledger gives M36 the contact path and the characters and M37 new files and hooks, M36 lands first, and M37 keeps M36's hunks, then runs the physics unit cases and the determinism suite on its merged tree.
- **Jolt's asserts and dangling constraints** (M37). Content can reach Jolt's asserts (equal limits without a spring, out-of-range hinge limits, non-unit axes, invalid motor settings), and a body destroyed under a live constraint leaves raw pointers dangling on any of the session's five removal paths. The world refuses or clamps every value and destroys a body's joints first; each path has a regression test under Jolt's asserts in Debug and Release.
- **Joints across histories** (M37). Without unique priorities the solve order follows Jolt's add-and-remove history; the kept frames are state the scene does not hold, so they are hashed. A test reaches one state through two histories and compares the steps after.
- **Breaking near its threshold** (M37). The force is the last collision step's: below 60 Hz there are several collision steps a tick, so a joint at the edge of its threshold breaks on another tick than a game tuned at another rate (deterministic in every configuration). The documents say the force is per collision step, and FeatureTest's weld sits well away from its resting load. Long chains with large mass ratios may stretch at Jolt's default iterations (a §2 row).
- **Characters on jointed bodies** (M37). A trap door must hold the Warden through M34's character contacts, and a door lighter than him never carries him; FeatureTest's door and the game's need a working mass and motor torque, which the skills state.
- **Seams under manifold reduction** (M36). A body across an ice–marble seam takes one sub-shape's surface; deterministic, accepted and documented, with manifold reduction off for bodies with surfaces as the fallback if a test shows it matters.
- **Per-tick surface writes** (M36). A write that reached `ComponentsChanged` would recompose the scene every tick; a unit case checks that a surface write keeps the body's handle and shape and composes nothing, and waking happens only on a changed value.
- **The push claim and the squeeze** (M36). If the measuring test shows the push failing at the game's speeds, W36.2 grows by a session and a perf check. The squeeze's tolerance and its "pushing contact" test need cases each way (a corner, a steep face, a press's first contact), and a script reads a squeeze one tick after it began.
- **The locale hash departs from the brief's words** (M38). The brief asks for the locale in the state hash; the plan hashes it only once it differs from the start locale and enforces the start locale as a recorded input at `ReplayPlayer::Begin`, so no committed hash moves and a mismatch still names the locale. The World Tree session is told through the product owner.
- **Synchronous `OnLocaleChanged`** (M38). A callback that creates or destroys entities, requests `Scene.Load` or faults inside the dispatch is handled by the snapshot, the started-and-enabled filter, the refusal of a nested change and the caller's deadline, as `NotifyCreated`'s nesting is; a dispatch at teardown is refused.
- **Two format bumps rewrite every replay and graph** (M38, M39). FeatureTest's replays and graphs, the demos' eight replays and Rolling Ball's graph, the test fixtures, and World Tree's own after the landing; a missed rewrite fails `Scaffold.py --check`, the games suite's upgrade dry run or the provenance audit. World Tree must upgrade before it uses an engine with the new formats.
- **The text pipeline** (M38's W38.2). `TextMeasurement`, `TextShaping` and `UiPass` had no owner in phase 5; an existing alignment value must take exactly today's path, which the Ui, UiScripts and text goldens and `MeasureText`'s byte-identity cases guard.
- **Returns in the graph flow model and run-time typing** (M39). ADR 0035 decision 23 kept the limit because several event nodes and `Flow.Delay`'s later flows give a result no single meaning; the defaults give Luau's meaning, refuse `Later`, and are measured by `FindGraphTextLimitIssues`, and the strict checker must accept every path. `Script.*` work on `any`, so a misspelt member or method is found at run time only, located at its node; a method rename does not follow string callers.
- **Chained streams, cursors and faded releases** (M40). A short streamed intro, a self-linked loop, the cursor across the intro's end and the loop's wrap (read from miniaudio internals, as `GetCursor` is), and a release counted on mixed frames each have dedicated `ReadFrames` cases; in Device time a release may come up to one device period early, at a level near 0.
- **Changing M35's landed rule** (M40). `Music` sources and one-shots now play on under the world pause; no FeatureTest suite or replay holds a `Music` voice under it, so no committed result moves, and M35's unit case is amended, not weakened. `Music` one-shots at music priority leave fewer voices for effects to steal.
- **The first hardening since M27** (the owner's answer 5). It covers two phases of code at once, so a finding in phase 5's code (an ASan fault in navigation, a fuzz finding in M28's readers, a soak leak) is fixed on phase 6's last landing branch and lengthens that landing; the ASan unit run is the step nearest its timeout. The gate runs at night with the World Tree session's rendering editor closed.
- **The game's checks the engine meets differently.** "The Warden caught under the hammer ends outside its footprint" (brief 16) cannot come from the engine under a flat face, whose contact normal is vertical: the engine reports a squeeze, and the game's Crush hit shoves the Warden. A game that restores a saved language in its title's `OnStart` overrides `--locale`, so brief 17's Dist check needs a store without another saved choice. Both go to the World Tree session through the product owner.
- **Two sessions in one checkout.** The World Tree session works in `D:\Engine`; the phase works in worktrees and never touches `Projects/WorldTree`, and the bridge stays the World Tree session's.
